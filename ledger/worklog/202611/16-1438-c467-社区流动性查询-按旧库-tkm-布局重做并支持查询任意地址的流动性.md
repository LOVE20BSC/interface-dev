旧库实现（只读参考 `../LOVE20TKM/interface/src/components/Dex/LiquidityQuery.tsx`）的布局与行为（**按此对齐**）：

1. **选择交易对** 卡片：两列 grid —— 左「基础代币」下拉（TKM 是 TUSDT/父代币），右「目标代币」只读显示；下方居中一行「LP 代币地址：」+ 复制按钮 + 加入钱包（TKM 有 AddToMetamask，我们没有就不加）。
2. **交易对统计** 卡片（居中标题「交易对统计」）：loading「加载中...」/ 无池「交易对不存在」/ 有池：
   - LP 总数量、{base} 总数量、{target} 总数量（每行左标签右数值）；
   - 价格行：`1 {target} = X {base}`，旁边 ghost 按钮切换方向为 `1 {base} = X {target}`。
3. **查询地址** 卡片：label「查询地址：」；输入框 placeholder「请输入要查询的地址 (0x...)」+ 提交按钮（未查询时「查询」、查询后「重新查询」、查询中「查询中...」）+ 有结果时的「重置」；未连接钱包时提示「⚠️ 未连接钱包，请手动输入要查询的地址」；地址默认填当前钱包（有连接时）。
4. **查询结果** 卡片：loading「查询中...」/ 无池「未找到流动性池 / {base}-{target} 交易对不存在」/ 有池但该地址无 LP「该地址在此交易对中，没有 LP 代币」/ 有 LP：
   - 「该地址 LP 情况」：LP 代币数量、所占份额；
   - 分割线后「可兑换代币数量：」：{base} 数量、{target} 数量（= 该地址 LP 按储备比例折算）。

我们与旧库的**必要差异**（写进对照表，不要硬搬）：
- 我们只有 WETH 一个基币（无 USDT/父币可选）→ 左侧下拉改为「社区代币」（Launch 目录 + 现有自定义代币地址入口可保留为紧凑次级入口，e2e 的 TestX 空池用例依赖它）；
- 右侧「目标代币」显示 WETH（只读）；
- 合约侧仍是 Uniswap V2 pair（`getReserves`/`totalSupply`/`balanceOf`），无 Zap 相关字段。
