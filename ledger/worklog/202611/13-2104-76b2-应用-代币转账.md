## Background

owner 要求新增「代币转账」应用，功能覆盖旧库同页：`../LOVE20TKM/interface/src/pages/token/transfer.tsx` + `components/Token/Transfer.tsx`（999 行）。旧页能力：代币选择（原生 + 支持代币 + 自定义 ERC20 地址，校验 bytecode、读 symbol/decimals、显示余额）、收款方式「按地址 / 按 NFT 持有人」、金额输入（max、按精度截断、千分位）、资产保护（收款方是合约/已知协议合约时二次确认并显示合约名）、提交状态与余额刷新、失败原因人话化。

本仓现状：只有「身份 NFT 转让」（`features/transfer-identity`，支持 地址/身份 NFT ID/名字 三种收款方式并强制 ID 确认），**没有代币转账页**。可复用：`features/swap-token/ui/token-select.tsx`（展示层与搜索）、`use-swap-catalog.ts`（社区代币目录 = Launch 分页 + 搜索）、`shared/lib/tx-watch.ts`、`shared/ui/sheet.tsx`、`shared/lib/format.ts`。

合约侧：ERC20 `transfer` 与原生币转账都支持，**无合约缺口**。

通用要求（每个页面任务都适用）
1. 面向非加密原生用户：说人话、讲后果、给下一步；界面不出现函数名/ABI/allowance 等术语。错误文案必须可执行，禁止「操作没完成，请稍后重试」这类泛化兜底。
2. 所有中文文案进 `src/shared/config/copy.ts` / `copy-pages.ts`（`src/architecture.test.ts` 强制）；术语以 `GLOSSARY.md` 为准，新词先登记。
3. 复用已有积木：`shared/ui/{button,card,sheet,skeleton,sticky-action,tx-watch-card}`、`shared/lib/format.ts`（金额最多 6 位小数，未知显示 `—`）、`shared/lib/tx-watch.ts`（90 秒有界等待 + 重新查询/重新提交恢复卡）。不要为了复用把某个页面的业务逻辑塞进 shared。
4. 交易流程统一为「填写 → 提交 → 等链上结果 → 回执」；回执必须可关闭且留在原页，关闭后不丢已提交状态。
5. 合约不支持就**停在这一页**：问题写进 `docs/contract-issues/`（编号顺延，当前最大 CI-017），页面用禁用态 + 人话原因；不伪造数据、不绕过合约限制。
6. 结案前门禁全绿：`pnpm typecheck`、`pnpm lint`、`pnpm test`、`VITE_ENV=dev pnpm build`（入口 gzip 警告线 160 kB）、改 ABI/地址簿时 `pnpm abis:check`、`pnpm e2e`（8555 自动化链）。**不要碰 8545 人工链。**
7. 共享文件（`src/domain/apps-catalog.ts`、`src/shared/config/copy-pages.ts`、`src/app/router/app-router.tsx` + `lazy-routes.ts`、`src/pages/apps/apps-page.tsx` 的图标映射、`docs/STATUS.md`）追加本页条目时先重读文件，只 edit 自己需要的行，禁止整文件覆盖——并行任务尤其注意。
8. 中文 commit 消息；结案用 `progress close`，需 owner 明确同意。

8. **接入**：apps-catalog + copy-pages + apps-page 图标 + 路由 + document-title。
9. **单测**：地址/金额校验、资产保护判定（已知合约 / 任意合约 / 普通地址）纯函数；组件测试表单禁用与确认态。
