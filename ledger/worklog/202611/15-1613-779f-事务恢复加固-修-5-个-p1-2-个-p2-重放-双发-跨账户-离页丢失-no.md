## To Do

1. **R1 发送前先落 attempt**：批量转账/流动性/转账在**调用钱包前**保存本次 attempt（request + 操作类型），拿到 hash 后补 hash；成功/失败/取消要清理或替换，确保「重试」永远重发**本次失败的请求**，绝不重发旧请求；首次发送失败也要有可重试状态（不能按钮无响应）。补单测：上一笔成功→下一笔失败→重试发送的是下一笔的参数。
2. **R2 重试必须绑定原哈希与原 nonce**：`resubmit` 记录被替换的 `hash`+`nonce`；读 nonce 期间/之后**复核** `watch` 状态：原交易已 confirmed → 直接走成功态、**不再发送**；仍 pending → 用**原交易的 nonce** 发替换（同 nonce），不是最新 nonce；原交易已 replaced → 按替换处理不再发。补单测 + 模拟「读 nonce 期间原 tx 确认」只发 1 笔。
3. **R3 账户/链归属**：待确认记录与 attempt 必须带 `{chainId, account}`；恢复或签名前校验与当前 wallet/chain 一致，不一致就**清掉记录并给中性提示，绝不代签**。覆盖 batch/liquidity/transfer（swap/mint 若已有记录也核对）。补单测：A 发起→切 B→重进页面不出现可提交的 A 请求。
4. **R4 待确认持久化**：batch 与 liquidity 复用现有 cache 方案（参考 `features/transfer-token/lib/transfer-record.ts`：按 `{chainId, wallet}` 隔离、pending/confirmed 状态），刷新/切页后恢复在途卡片并继续 watch，且**在途期间禁止二次提交**（与 transfer 的 D1 防护一致）。
5. **R5 nonce 策略**：新增/改用 `getTransactionCount(blockTag:'pending')` 给**新操作**分配 nonce（排在钱包已有 pending 之后）；显式固定 nonce 只用于「替换某一笔已知交易」（用它的原 nonce）。全站首笔发送（swap/mint/airdrop/batch/liquidity/transfer）统一；补单测：pending=latest+1 时首笔用 +1。
6. **R6 replaced 判定**：`findReplacementHash` 排除当前被 watch 的 hash；回执读取失败但原 tx 已在链上 → 继续轮询/按 pending 处理，不得判 `replaced`；补单测。
7. **R7 流动性重试加锁 + 钱包等待态**：`submittingRef` 前置加锁、`setMainWalletAction(true)`、`finally` 释放；恢复按钮点击期间禁点。
8. **回归**：现有 633 单测全绿；新增针对 R1–R7 的单测/组件测试；在 8555 上跑全量 e2e 两遍 0 failed/0 did not run（含既有 swap/recovery 用例）；如果 owner review 里的「模拟对照 2 条通过、10 条边界断言失败」有可复用脚本，迁成单测。
9. 文档：`e2e/README.md`/`docs/product/three-line-verification.md` 或交易恢复相关 spec 补「在途/重试/替换」约定；ux-spec 若交互有变化同步。

## Process

### 修复位置与根因（逐条）

1. **P1 重放上一笔（R1）** — 根因：`use-batch-transaction.ts` 旧 `submitInternal` 只在 `writeContractAsync` 返回后才 `lastAttemptRef.current = {hash, kind, request}`，失败路径什么也没留下；而 `resubmit` 用 `pending ?? lastAttemptRef.current`，于是「上一笔成功、下一笔发送失败」时重试重发上一笔的参数，首次失败时 attempt 为 null → 静默死按钮。修法：批量转账/流动性/代币转账三个 hook 都在**调用钱包之前**落 attempt（含 `{chainId, account, kind, request, nonce?}`，批量与流动性同时落盘），拿到 hash 后替换成带 hash 的同一条记录，成功/失败/取消分别清理或替换（`use-batch-transaction.ts:332-334`、`use-liquidity-transaction.ts:331`、`use-transfer-transaction.ts:315`）。
2. **P1 确认期间重试再发一笔（R2）** — 根因：`use-transfer-transaction.ts` 旧 `resubmit` 读 nonce（网络往返）后无条件 `submitInternal(request, nonce)`，期间原 tx 可能已确认，两笔都成交。修法：新增纯决策模块 `src/shared/lib/tx-resubmit.ts`（`decideResubmit`）与链读 `readResubmitSnapshot`（`use-tx-watch.ts:406`，回执/交易/nonce 三读，读失败保留 `undefined`）；`resubmit` 先复核：已成交 → 走成功态不发；仍排队 → **用原 nonce** 替换；nonce 被别人吃掉 → 不再发；读不到 → 中性文案不盲签（transfer `:395`、batch `:401`、liquidity `:405`）。`TxWatch` 新增 `submittedNonce` 暴露观察到的原 nonce。
3. **P1 跨账户重放（R3）** — 根因：`use-liquidity-transaction.ts` 的 pending 不含 chainId/account，A 发起、切到 B 后点重试会用 B 签名而 args 里 `to` 仍是 A。修法：新增 `src/shared/lib/tx-owner.ts`（`isSameTxOwner`，地址大小写不敏感）；pending/attempt 与持久化记录都带 `{chainId, account}`；恢复/签名前校验，不一致就清记录 + `copy.txWatch.ownerChanged` 中性提示（「钱包或网络已经切换，刚才那笔交易没有再提交。请用当前钱包重新发起。」），绝不代签；缓存 scope 仍是 `{chainId, wallet}`，A 的记录在 B 下读不到。
4. **P1 离页/刷新丢失（R4）** — 根因：批量转账/流动性只在组件内存里记 pending，刷新后表单可再次提交。修法：仿 `transfer-record.ts` 新增 `batch-record.ts`（`batchTransferTask`）与 `liquidity-record.ts`（`liquidityTask`，只存「调用形状」地址+函数名+参数，ABI 由函数名在已知 ABIs 里查回，杜绝任意接口被签），scope 用 contract-less `ZERO_ADDRESS`；hydration 恢复在途卡并继续 watch 同一 hash，`pending !== null` 期间 `submit`/`run` 直接 return（与 transfer D1 防护一致）；未拿到 hash 的 attempt 也恢复为可重试态。
5. **P1 nonce 策略（R5）** — 根因：`use-tx-watch.ts` 旧 `useNextNonce` 读 `latest`，swap 首笔经 `pinnedNonce()` 使用它 → `latest=3`、`pending=4` 时新操作仍签 3，撞上钱包排队交易。修法：新增 `usePendingNonce`（`blockTag:'pending'`，`use-tx-watch.ts:361`）；swap 首笔改用它，批量/流动性/转账/铸造/空投铸造/授权 6 处首笔发送统一 pin pending nonce；显式 nonce 只用于「替换已知交易」（用原 nonce，见 R2）；旧 `useNextNonce`（latest）仅保留给 swap/mint/airdrop/approve 的既有「钱包 nonce 陈旧自愈」路径。
6. **P2 replaced 误判自己（R6）** — 根因：`findReplacementHash` 未排除被 watch 的 hash（同 from+nonce 扫到自己也返回），且回执读取失败被当成「没回执」去触发替换扫描，一个滞后/失败的读就把状态判成 `replaced` 并停止轮询。修法：`readReceipt` 改三态（mined / none / failed，`use-tx-watch.ts:93`）；只有**确定无回执**才做替换扫描；扫描用 `excludeHash` 排除当前 hash（`:145-155`）再做一次防御性过滤。
7. **P2 流动性重试无锁无等待态（R7）** — 根因：`resubmit` 未 `setMainWalletAction`、未加 `submittingRef`。修法：前置加锁 + `setMainWalletAction(true)` + `setIsResubmitting(true)`，`finally` 全部释放；`TxWatchCard` 新增 `resubmitDisabled`（`data-testid="tx-watch-resubmit"`），transfer/batch/liquidity 三页在重试期间禁用「重新提交」。
8. **R8 `route-loading` 无 UI 分支** — 根因：`selectSwapScreenState` 返回 `route-loading`，`swap-token-panel` 没有该分支，route=null 时落到最终表单（到账显示 —、`quote.enabled` 因 route 未 ready 永不发请求）→ 30s 死界面。修法：`swap-state.ts` 新增 `ROUTE_LOADING_TIMEOUT_MS = 15_000` 与 `routeLoadingTimedOut` 输入（loading + 超时 → 可重试的 `route-error`）；面板新增显式 `route-loading` 分支（`data-testid="swap-route-loading"`，`aria-busy`）+ 超时降级到专用可重试卡（文案 `copy.swap.states.routeTimeout*`），「重试」会重置计时并 `routeState.retry()`。
9. **R9 e2e 挖矿模式泄漏** — 根因：`swap-slow-wallet`/`transfer-recovery` 临时 `anvil_setIntervalMining 0 + setAutomine false`，`afterAll` 未执行或恢复不完整就会让同链后续 spec 全面超时（两次全量 flake 的高概率根因）；快照/回滚不包含挖矿模式。修法：`e2e/chain.ts` 新增 `SUITE_MINING`/`readMiningMode`/`suspendMining`/`restoreMining`（设置后**回读断言**，不一致抛 `[chain] mining mode not restored …` 并在提示里给 `pnpm e2e:reset-chain`）；`isolateChain()` 在取快照前与回滚后各 `restoreMining()` 一次（覆盖 afterAll 被跳过的情形）；两个 spec 的 `afterAll` 改为 `try/finally` 调 `restoreMining()` 并在 `finally` 里 `readMiningMode()` 断言；`e2e/README.md` 新增「挖矿模式（interval mining）」约定与 Harness guards 条目。
