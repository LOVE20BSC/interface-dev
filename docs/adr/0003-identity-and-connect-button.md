# 0003 身份模型与右上角连接按钮

右上角连接按钮是账户、代币社区、身份三件事的唯一入口。身份是 **(chainId, MemberNFT 合约地址, tokenId)**：MemberNFT 地址**不由用户输入**，而是由环境包里的**种子 core 合约地址**经链上 `MEMBER_NFT_ADDRESS()` getter 解析得到（环境包自带的 MemberNFT 地址只作可选覆盖/钉住）；钱包的候选身份用 `balanceOf` + `tokenOfOwnerByIndex` **链上枚举**。选中结果记在本地；本地缓存一律经统一封装按 `chainId + contractAddress + wallet + businessKey` 命名空间隔离，禁止裸写 `localStorage`。首屏按身份优先渲染：解析当前身份 → 依身份欢迎 → 否则引导“我的 NFT”（枚举列表）→ 再否则引导铸造 MemberNFT。代币社区切换的精确语义、多身份排序等仍是**待定**，本 ADR 只记录已定部分与已知技术边界。

- **Status**: Accepted（含待定项）
- **Date**: 2026-11-11

## Context

所有者给的界面要求：

1. 右上角按钮要能做三件事：连接/断开钱包、切换代币社区、切换身份（MemberNFT）。
2. 环境包只给一个**种子 core 合约地址**；MemberNFT 地址由链上 `MEMBER_NFT_ADDRESS()` 解析（环境包中的 MemberNFT 地址可作可选覆盖/钉住）。用户选择的是具体身份（tokenId），不是合约地址。
3. 所有本地缓存必须按 `chainId + contractAddress + wallet + businessKey` 隔离，通过唯一封装访问。
4. 首屏身份优先：解析当前 MemberNFT → 用身份欢迎 → 没有就从枚举出的身份列表选择 → 还没有就引导去铸造 MemberNFT。

与研究结论直接相关的三条约束：

- **身份可能随时易主**：成员身份 NFT 转移只换控制者，不改身份、历史与既有归属。任何缓存的身份在每次加载时都必须重新按 `ownerOf` 校验，否则用户会对着一个已经不属于自己的身份操作。
- **发现不依赖事件日志**：BSC 公开 RPC 的 `eth_getLogs` 分别限 50 块 / 50 000 块 / 直接拒绝，客户端索引不可行；但 MemberNFT 是 `ERC721Enumerable`，按持有人枚举是直接的 view 调用，无需扫描 `MemberMinted` / `Transfer`，也不需要托管索引器。
- **origin 变更会清空本地存储**：Pages 从项目路径切到自定义域名 = 新 origin，`localStorage` 全空。记住的选中身份会丢，只能重新引导。

## Decision

### 1. 右上角按钮 = 三个面板，一个入口

| 面板 | 能力 | 未连接钱包时 |
| --- | --- | --- |
| 钱包 | 连接、断开、切换当前地址；连接后显示地址缩写与当前链 | 主按钮“连接钱包” |
| 代币社区 | 切换当前代币社区（`tokenAddress`） | 不可用，入口置灰并说明原因 |
| 身份 | 切换当前 MemberNFT（含“不使用身份”），跳转“我的 NFT” | 不可用 |

按钮自身只显示三种状态，不显示四个：**未连接** / **已连接·无身份** / **已连接·身份名**。代币社区是按钮内的一个标签行，不占用主状态位。

**切换代币社区 ≠ 切换网络。** 每个变体只连一条链（ADR-0002），界面不提供网络选择器；链不匹配时走“添加/切换网络”的引导弹层，而不是下拉框。

### 2. 身份 = (chainId, MemberNFT 合约, tokenId)，合约地址由种子 core 合约解析

- **身份列表来自链上枚举，不由用户输入合约地址；环境包只需一个种子 core 合约地址。**
- 身份是 `(chainId, MemberNFT 合约地址, tokenId)` 三元组；`memberId == tokenId`，一个钱包可同时持有多个身份。
- **MemberNFT 地址解析**：每个协议部署只有一个全局 MemberNFT。前端取环境包中的任一 core 合约地址（Launch / Mint / Stake / Submit / Vote），调用其公开 getter `MEMBER_NFT_ADDRESS()` 得到该部署唯一的 MemberNFT；环境包若同时给出 MemberNFT 地址，仅作可选覆盖/钉住（例如离线演示或 core 地址暂缺时）。
- **候选身份枚举**：`n = balanceOf(wallet)`，再对 `i = 0..n-1` 调 `tokenOfOwnerByIndex(wallet, i)` 取全部 tokenId；批量读取走 Multicall3。无需事件扫描、后端或托管索引器，也不需要改合约。
- 选中结果写入本地，键必须包含 `chainId` 与解析出的 MemberNFT 合约地址（否则 dev/test/prod 或两次部署之间会串）；身份的来源不是“用户输入的合约地址”。
- 选中的身份**在每次会话首帧后**都要按 `ownerOf(tokenId) === wallet` 重校验；不匹配即视为失效：清除该条记录、回到“无身份”态、给出中性提示（“这个身份已不属于当前钱包”），不指责用户。
- 身份名是展示用的名字，不是标识；界面任何地方不得用身份名做关联键。
- 身份卡片只展示 `memberName(tokenId)` + `#memberId` + 本地生成的确定性头像；**绝不调用 `tokenURI`**（返回空字符串），也绝不去第三方拉取图片。

### 3. 本地缓存：唯一封装 + 强制命名空间

键格式固定为：

```
love20:v1:<chainId>:<contractAddress>:<wallet>:<businessKey>
```

- `contractAddress` 对“与某个合约无关”的偏好（如界面语言、高级视图开关）用固定占位值，不得留空——留空会让同一业务键在两次部署间互相覆盖。
- `wallet` 统一小写；`businessKey` 由调用方给语义名（`identity`、`onboarding`、`jobs` …），不允许拼地址或 JSON。
- **只有一个封装模块可触达 `localStorage` / `sessionStorage`**。组件、hook、测试里出现裸 `localStorage.` 即违规，用 lint 规则 + CI grep 拦截。
- 封装必须提供：读、写、删、按前缀清空（用于“切换钱包/身份后作废旧数据”）、以及反序列化失败时自我清理（旧版本残留的脏数据不能让首屏崩）。
- 版本号 `v1` 在键里；格式变更时递增，旧键由封装清理，不做迁移。

### 4. 身份优先渲染

| 顺序 | 条件 | 首屏表现 |
| --- | --- | --- |
| 1 | 钱包未连接 | 展示“这是什么、能做什么”，主按钮为连接钱包 |
| 2 | 已连接，有选中身份且 `ownerOf` 校验通过 | “欢迎，<身份名>”，并给出该身份在本轮的可做事项 |
| 3 | 已连接，有选中身份但校验失败 | 清除并落到第 4 步，提示“身份已失效，请重新选择” |
| 4 | 已连接，无选中身份 | 引导“我的 NFT”：枚举到的身份列表（若为空则引导铸造） |
| 5 | 第 4 步枚举结果为空 | 引导铸造 MemberNFT：说明费用、需要一点 BNB 付手续费、铸造后回来选择 |

加载期用骨架屏，**不得**先用 `0` 或空字符串占位（余额/轮次显示成 0 是“我的钱没了”式误读）。

### 5. 待定（明确不在此刻决定）

**已解决：NFT 发现机制。** 每个协议部署只有一个全局 MemberNFT（`ERC721Enumerable`）；环境包给一个种子 core 合约地址，前端读其 `MEMBER_NFT_ADDRESS()` 定位 MemberNFT，再用 `balanceOf(wallet)` + `tokenOfOwnerByIndex(wallet, i)` 枚举该钱包的全部 tokenId。**事件扫描不再必要**：`eth_getLogs` 的 RPC 限制仍然存在，但发现路径完全不依赖日志，也无需托管索引器或合约改动。

| 待定项 | 已知约束 | 为什么现在不决定 |
| --- | --- | --- |
| **代币社区切换的精确语义** | 质押、激励、发射次数都按代币社区隔离；身份是全局主体 | 切社区时是否清空已选身份、是否改变默认落地页、是否影响“我的激励”的统计口径，均未定 |
| 同一钱包持有多个身份时的排序与默认选中 | 合约只提供按持有人枚举，不提供“最近使用”等排序；一个钱包可持有任意多个身份 | 可按最近使用 / tokenId 升序 / 由用户固定，各有代价 |
| 身份被转移后的提示时机与后续动作 | 转移只换控制者 | 是首屏提示、还是写操作前拦截，未定 |
| **代币社区白名单**是否随环境包下发 | 只决定“代币社区”面板列出哪些 `tokenAddress`，与 MemberNFT 合约发现无关（后者已由 `MEMBER_NFT_ADDRESS()` 解决） | 下发等价于官方背书某些社区；不下发则要么只支持单一默认社区，要么要求用户自行提供 `tokenAddress`，首次体验差异大 |

## Consequences

**正面**：首次使用只需一个种子 core 地址即可枚举身份，用户无需寻找或粘贴合约地址；身份与钱包解耦，换钱包不会污染另一钱包的界面；缓存键天然隔离三个环境与两次部署；身份失效可被检出而不是让用户对空身份发交易；按钮只有一个，移动端右上角不会挤成一排图标。

**代价与遗留**：

- **首次铸造仍有门槛**：MemberNFT 地址已由种子 core 合约自动解析，首次使用不再需要寻找/粘贴合约地址；但铸造要求先持有 LOVE20（需先 approve）并支付 BNB 手续费。门槛转移到“获取 LOVE20”，由空投领取/代币兑换引导承接（见 M0 漏斗）。
- **换域名丢记忆**：项目路径 → 自定义域名是新 origin，本地存储清空，用户要重新枚举并选身份。可接受，但发布说明里要写。
- **多标签页不一致**：本地键是共享的，两个标签页可能显示不同身份；本期不做跨标签同步，只在写操作前重校验。
- **隐私**：钱包地址与所选身份落在用户设备上；同一台设备的其他人可见。不做加密（没有可用的密钥材料），但也不写任何链下身份信息。
- 身份校验是**每次加载一次**的读，不是实时订阅：身份在会话中被转移时，界面会在下一次写操作前才纠正。这是无 WSS 可靠通道下的取舍。
