# ADR-0006 · 移除交易重发，卡住态改为纯提示

- 状态：Accepted（owner 2026-11-23）
- 日期：2026-11-24
- 关联：T004；[m0-ux-spec](../product/m0-ux-spec.md) §4.2 / §4.4；[frontend-standards](../engineering/frontend-standards.md) §7.6 / §10.12
- 取代：T002 `adr-0006-draft.md` 中「R2 三模式 / 恢复卡重新提交」的设计前提（该草案未进仓）

## Context

旧实现为「交易卡住/失败」提供两条重发路径：恢复卡上的「重新提交」和签名失败/取消后的「重试」。它们共享 R2 复核、原 nonce 替换、R7 重提锁与 `tx-resubmit.ts`。实际风险：

- 同 nonce 替换没有 gas bump，真实节点会以 `replacement transaction underpriced` 拒绝；e2e 只能靠丢弃交易再重发；
- 8 个 flow × 两套重发语义，测试面大且难穷举；
- 产品上 owner 决定不再支持失败交易重发：失败就是失败，用户重新填表发起。

## Decision

1. **删除所有交易重发**：恢复卡「重新提交」、签名失败/取消后的「重试」、R2 复核（`readResubmitSnapshot` / `decideResubmit` / 原 nonce 替换）、R7 重提锁与 `tx-resubmit.ts`。
2. **卡住态纯提示**：慢/掉队/被替换/nonce 缺口统一显示标题 + 正文「请在钱包或区块浏览器里查看」；无按钮、无链接、无关闭；交易落定后 watcher 自动更新为回执/失败。
3. **只保留有 hash 的在途记录**：stake/liquidity/batch 从「发送前落盘 hash=null」改为「拿到 hash 后落盘」；刷新只恢复有 hash 的在途任务；无 hash 不产生任务、不恢复、不显示「上次操作没提交」。旧记录直接丢弃，不写兼容/双读/迁移。
4. **保留**：同一时刻一笔写操作、新操作 `pending` nonce、账户归属校验、回执关闭释放守卫、approve 阶梯、读失败重试（余额/资格/读模型）。
5. **文案 A（owner Q1124-1）**：标题「这笔交易还没有确认」；正文「请在钱包或区块浏览器里查看。确认或失败后，这里会自动更新。」。

## Consequences

- 正面：删除约 2.5k 行重发/复核/测试代码；grep `resubmit|重新提交` 归零；卡住态没有可误点的动作；不再有同 nonce 替换失败与 R2 分支矩阵。
- 代价：交易卡住后用户只能去钱包/区块浏览器处理，产品不再提供站内解；刷新发生在钱包等待中时看不到任务（无 hash 不落盘）；e2e 的 ghost-hash 用例只验证提示，不验证落定。
- 迁移：T003 的 R2 单测删除/改写，4 条 e2e 改为纯提示；不做旧缓存兼容。

## Rejected alternatives

- **保留「重新提交」并补 gas bump**：仍要维护 R2 复核与 8 个 flow 的分支；owner 已决定不重发。
- **自动重发/后台重试**：用户不可见地签第二笔，风险更高；拒绝。
- **保留失败请求的「上次操作没提交」纯展示**：只为重试服务；owner 选择「不记住失败请求」。若未来要恢复纯展示，可单独加，不影响本 ADR。
- **卡住卡保留「重新查询」或浏览器链接按钮**：owner 明确纯提示无按钮；链接也不放。
