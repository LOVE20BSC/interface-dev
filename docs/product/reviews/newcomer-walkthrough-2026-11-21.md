## 0. 为什么用「注入桩」而不是钱包弹窗

ego-browser 自带一个 MetaMask 兼容钱包（`window.ethereum` 具备 `_metamask` / `_rpcEngine`，支持 `wallet_requestPermissions`），本可以用它走真实授权/签名。但 **ego-browser 技能契约明确：钱包权限弹窗属于浏览器所有，agent 不能点击**（原文 “Permission prompts… require the user to handle them”，只能用 `handOff()` 交给人类）。

owner 2026-11-21 选择「继续用注入桩全自动跑」，因此本次走查把内置钱包的 `request` 路由到 anvil RPC（`eth_sendTransaction` 真发交易，账户是 anvil 未锁账户），**页面逻辑、读链、写链、回执都是真的**，只有「钱包确认弹窗」这一步被绕过。真实钱包的差异见 §4「真机待确认」。

## 2. 发现的问题（按严重度）

### P0-1（迁移中间态）`/submit` 整页「暂时读不到」
- 现象：`/submit` 渲染标题与资格卡（阈值正常），但表单区显示「推举新提案 … 暂时读不到」，`gov-submit-title` 输入框不存在。
- 根因：core 正在把 `ProposalBody.targetData/targetMode` 改成 `creationData`，`MAX_TARGET_DATA_COUNT/BYTES` → `MAX_CREATION_DATA_BYTES`。前端 ABI 已于 13:14 重新生成，但本地链（8545/8555）仍是旧字节码：新 ABI 里的 `MAX_CREATION_DATA_BYTES` 在旧链上不存在 → `useSubmitContext` 的常量多读失败 → `limits` 为 `undefined` → 表单不渲染。
- 归属：**另一个 agent 正在进行的 core/action 接口迁移**，不是本轮改动；等 core 提交并重新 bootstrap 链后复验。

### P0-2（迁移中间态）`vote()` / `submitNewProposal` 写链不可用
- `Vote.vote` 与 `Submit.submitNewProposal` 的 ABI 签名都随迁移变化，旧链上调用会因 selector 不同而失败。因此「推举 → 投票」这条主链在新链部署前跑不通。

### P0-3（待复验）静态预览里代币余额显示 0
- 同一账户、同一条链：`5190`（dev server）显示 `100,000,000 TestLOVE20`，`5192`（我做的静态预览构建）显示 `0` 并判「余额不足」。
- 链上真值 `1e26`，页面内直接 `eth_call balanceOf` 也返回 `1e26`。
- 初步判断：静态预览构建于迁移进行中（14:38），可能吃到中间态代码/被并行构建覆盖的 `dist`；**需要在迁移完成后用干净构建复验**。若复现，则是「未知余额被渲染成 0」的硬规则 4 违规，必须修。

### P1（真 UX 缺陷，与本轮迁移无关）铸造身份页提前显示「已授权」
- 现象：名字为空（价格尚未计算）时，页面已经显示「已授权 第一次只是允许合约扣走最多这么多的 TestLOVE20」。
- 根因：`mint-identity-panel.tsx` 里 `needsApproval = cost !== undefined && effectiveAllowance !== undefined && effectiveAllowance < cost`——**价格未知时 `needsApproval` 恒为 false**，按钮/说明落到「已授权」分支。
- 影响：新账户第一次进页面会被误导为「已经授权过」（实际 allowance = 0）。输入合法名字、价格算出后才会变回「授权 TestLOVE20」。
- 建议：`cost === undefined` 时授权行不给结论（隐藏或写「输入名字后显示授权状态」），不要复用「已授权」文案。

### P2（迁移中间态）首页空投提醒已铸造仍显示「可铸造 100,000,000」
- 空投已成功铸造后，首页提醒仍在。`AirdropDistributor` ABI 在本轮迁移中被改过，claim 状态读失败后回落到快照口径 → 误报。链上余额已是 1 亿。

### P2（桩环境）刷新页面后需要重新点「连接钱包」
- 全页刷新后应用停留在未连接态，需要再点一次。真实钱包 + wagmi 自动重连下大概率不存在，**列真机待确认**，不作为缺陷。

## 3. 走查结论

1. **新人前三步（连接 → 空投铸造 → 进铸造身份页）顺畅**，页面文案、空态、回执都合格，没有出现「未知渲染成 0」「技术词进漏斗」这类问题。
2. **卡点全在「core 接口迁移」这条线上**：推举、投票两页的读写都依赖新 ABI，本地链还是旧字节码；这是并行迁移的中间态，不是产品缺陷。
3. 真正需要改的产品缺陷只有一个：**铸造身份页的「已授权」提前出现**（P1），修法明确、成本极低。
4. 走查还顺带证明：ego-browser 的钱包弹窗无法由 agent 操作，**真机验收需要人点确认**；自动化回归继续用仓库既有的 `installWallet` 桩即可。
