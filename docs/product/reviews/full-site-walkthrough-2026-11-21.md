### P1

#### P1-1 提案页资格说明里的百分比丢了 `%`，把 0.5% 读成「0.5 倍」

- **现象**（`/submit`，#6 无治理权、以及 #0 解锁后门槛变化时都可复现）：
  > 推举需要本轮治理权不低于 **44.7213**（社区总治理权的 **0.5**），你现在是 0。
  > 本轮推举门槛：44.7213 治理权
- **期望**：`（社区总治理权的 0.5%）`。链上 `SUBMIT_MIN_RATIO = 5e15`（= 0.5%），`44.7213 = 8944.2719 × 0.5%`；括号里若写「0.5」读起来是「总治理权的 0.5 倍（=50%）」，与真实门槛差 100 倍。
- **证据**：页面文本（testid `gov-submit-eligibility-reason`）；链 `cast call Submit 0xA51c1f… "SUBMIT_MIN_RATIO()(uint256)" → 5000000000000000`；代码 `src/shared/config/copy-pages.ts:1893-1894` 的模板 `（社区总治理权的 ${ratio}）` 直接吃了 `submitRatioPercent()` 的返回值，而 `src/features/governance-submit/lib/submit-form.ts:102-105` 的 `submitRatioPercent` 用 `formatPercent()` 返回**不带百分号的数字**（`formatPercent` 约定由调用方补 `%`，如 `formatSharePercent` 的调用点都手写了 `%`）。调用点 `src/features/governance-submit/ui/submit-panel.tsx:311-316`。
- **归因**：真缺陷（数值/文案，显示层缺单位）。
- **建议修法**：`submitRatioPercent` 返回时补 `%`（或用 `formatSharePercent` 同款约定），并在 `src/shared/config/copy-pages.ts:1894` 加单测断言 `（社区总治理权的 0.5%）`。

#### P1-2 铸造回执点「设为当前身份 NFT」后，页头药丸的身份名变成「—」且不恢复

- **现象**：#6 首次铸造身份 NFT #7 成功 → 收据出现「设为当前身份 NFT」→ 点击后按钮正确变为禁用的「已设为当前身份 NFT」，但页头药丸第二行 3 秒后仍是 `—`（`0x976E…0aa9 | —`）；点「好的」进 `/my-nft` 名称正常显示 `Testnewbie6`；**整页刷新（重新连接）后才显示 `Testnewbie6`**。
- **期望**：本地选择是纯本地动作，应立刻在页头显示 `Testnewbie6`（与 `/my-nft` 行内一致）；至少不能停在「—」。
- **证据**：`{ text: '0x976E…0aa9 | —' }`（`page.evaluate` 取所有 button innerText，3s 后仍为 `—`）；同一时刻 `/my-nft` 文本 `NFT #7  Testnewbie6  当前`；刷新后 `0x976E…0aa9 | Testnewbie6`。截图 `shots/desktop-dark-mint-receipt-set-identity.png`。
- **归因**：真缺陷（状态刷新）。
- **建议修法**：`src/entities/member-identity/model/use-member-identity.ts:130-140` 里 `selected` 在枚举列表里找不到 tokenId 时回落成 `{ tokenId, name: null }`，而回执的 `onSetIdentity` 走 `select()` 只写 cache + notify，**没有触发 `useMemberIdentities` 重新枚举**。修法二选一：①`select()` 后 `refetch()` 身份枚举；②对 `selected.tokenId` 单读 `memberName()`，读到后回填（`name` 不再是 null，橙心读模型也更稳）。

#### P2-3 投票页在「没有治理权」时显示错误口吻的「合计超过还能投的 0 票。」

- **现象**：`/vote`，钱包无质押（#6）：额度卡已给出正确门槛文案（「治理权来自流动性质押。先质押流动性，下一轮就能投票。」+ 去质押流动性），但提交按钮下方又常驻一行：

  这与「超额投票」的错误提示同款，但用户什么都没输入，且页面还没有可投提案。
- **期望**：无额度时用中性原因（如「本轮没有可投的票」）或直接不渲染；这句 `amountTooMany` 只应在「用户输入值 > 剩余额度」时出现。

- **归因**：真缺陷（文案/状态）。
- **建议**：`remaining === 0n` 时换专用 copy（`copy.gov.vote.noPower`），或把该行移到 `localError` 体系里由「输入超额」触发。

- **建议**：在 `amount > remaining` 时把 `amountTooMany(remaining)` 渲染到 `gov-vote-local-error`（不必等提交）。

#### P2-7 兑换/流动性页在空态就断言「这一笔不需要代币授权」

- **现象**：`/liquidity`（添加）与 `/stake/liquidity` 的授权阶段，在**未输入任何数量**时显示禁用的「这一笔不需要代币授权」并附「这次要用的额度已经够，不需要再授权。」；但 #0 当时对 router/hub 的 allowance 都是 **0**（`allowance-router = 0`）。一旦输入金额，文案会正确变成「授权 TestLOVE20」。
- **期望**：空态不应下「不需要授权」的确定结论（会让人以为此页永远不需要授权）；用「填入数量后显示授权步骤」或骨架/中性占位。
- **证据**：testid `liquidity-add-approve` / `gov-liquidity-approve-token` 文本；`cast call TOKEN "allowance(#0, router)" → 0`。
- **归因**：文案/状态（误导）。
- **建议**：`amount === 0` 时该按钮区留空或显示「输入数量后确认授权步骤」。

#### P2-8 规范与实现的轻微漂移：钱包弹层缺「合约地址」入口、社区菜单缺「复制本页链接」

- **现象**：mUX §1.6 第 7 项要求钱包弹层有「合约地址 → 弹层（链 ID、各合约地址、浏览器链接）」；§1.5 第 8 项要求社区菜单有「复制本页链接」。实机弹层顺序为：地址行 → 网络行 → 身份行 → 两种余额 → 断开连接 → 保存说明，**没有合约地址入口**；社区菜单为：搜索框 → 最近访问 → 父币 → 子币 → 「切换社区不会切换网络。」，**没有复制本页链接**。
- **期望**：要么补回实现，要么回写规范（owner 2026-11-19 有一批弹层改动，可能是规范漏更）。
- **证据**：`shots/desktop-dark-wallet-menu.png`、`shots/desktop-dark-community-menu.png`；代码 `src/widgets/connect-pill/wallet-menu-content.tsx` 中无合约地址行、`community-menu-content.tsx` 只注释了「最近访问 / 父币 / 子币」。
- **归因**：迁移残留（文档 vs 实现）。
- **建议**：请 owner/lead 拍板：若是有意删除，更新 mUX §1.5/§1.6；否则补回（合约地址弹层 `/about` 已有可复用数据）。

#### P2-9 移动端错网络时没有任何社区名（chip 不存在）

- **现象**：390×844、钱包连在 chainId 1：页头只剩「网络不对，点此切换」按钮，页面其余位置无 `TestLOVE20`（移动端首页的 wordmark 按规范在已连接后隐藏，chip 又是唯一社区名位置，但错网络态 chip 不渲染）。
- **期望**：§1.4 说「未连接 = 单按钮；已连接含错网络 = chip + 地址区」；§1.3 又说「连上后社区名由 chip 承担」。实现是「错网络 = 单按钮」，两者冲突，结果是移动端错网络时**社区归属丢失**。

- **归因**：真缺陷/规范冲突（待 owner 拍板）。
- **建议**：错网络态保留 chip（只把地址区替换成「切换网络」按钮），或恢复移动端左侧 wordmark。

#### P2-10 交易 pending 文案「约 90 秒后仍未确认，可以重新提交一笔。」在提交后 2.5 秒就出现
