## §0 设计原则

1. **新手视角（Lite 默认）**：界面不出现 gas、approve、allowance、nonce、revert、滑点、区块、合约等词；「高级视图」默认折叠，只放地址、哈希、轮次与浏览器链接（B-3；M0 的实现是 `/about` 的「合约地址」页（钱包弹层不再放合约地址入口），不做全局开关；各业务页不再重复技术详情折叠）。所有中文过 `GLOSSARY.md` 六条纪律。
2. **身份优先**：首屏先回答「我是谁」，再回答「我能做什么」。未连接也要能读懂这是什么；已连接先解析身份，身份决定文案、CTA 与语气（ADR-0003 §4）。
3. **一页一任务**：每页只有一个主 CTA；次要入口最多两个，且不与主 CTA 同色同权。一个页面不承载两条完整流水线。
4. **结论先于细节（渐进披露）**：先给「能不能做 / 要花多少 / 还差什么」，明细收进折叠区。默认一屏回答完，不要求用户先读规则。
5. **不把合约函数映射成界面**：按用户任务组织（拿到身份 / 空投铸造 / 买到币），一个任务可调多个方法；合约有而用户不需要的能力（融合、默认身份、限额）不出现。反过来，一个方法可拆成多个界面状态（claim 前的资格判定）。
6. **不显示未知值为 0**：加载用骨架，未知用「—」，失败说「读不到」。余额、价格、倒计时、可铸造金额绝不先渲染 `0`（ADR-0003；B-1）。
7. **不制造死路**：每个任务页的空 / 错 / 无资格状态必须有且仅有一个「下一步」按钮，外加一个返回入口；导航页（首页）由常驻入口承担下一步，不另造「无需操作」静默态；不存在只有一句话的页面（B-11）。
8. **估算必须标注**：由报价、池子、区块时间推出来的数字写「预计 / 约」并给出会变的原因；链上精确值（余额、已铸造金额）不标。估算值在提交前重读一次链上。

## §1 应用外壳

### 1.1 布局、断点与安全区

- 断点 `md = 768px`（与 ADR-0001 一致）。`<md` 底部标签栏；`≥md` 左侧可折叠侧栏，**不转换**底部栏（TKM 的做法）。
- 内容区 `max-w-[32rem]` 居中、左右 16px 内边距；桌面侧栏占宽（展开 232px / 图标轨 64px），内容区不因侧栏而拉伸成宽表。
- `viewport-fit=cover`；`--nav-h: calc(64px + env(safe-area-inset-bottom))`；页面容器 `padding-bottom: calc(var(--nav-h) + 8px)`，`md:pb-8`；头部 `padding-top: max(8px, env(safe-area-inset-top))`。
- 头部高 56px，`sticky top-0` + 背景模糊 + 1px 下边框；滚动时内容不穿过头部。
- 底部栏 `fixed bottom-0`，`min-height` 含安全区，`z-40`；弹层 `z-50`，弹层底部同样加安全区内边距。

### 1.3 页面头部规则

| 页面类型 | 左 | 中 | 右 |
|---|---|---|---|
| 一级（首页） | 移动端（<md）：**未连接时**社区 `symbol()`（无社区/未知回退「LOVE20协议」）；已连接（含错网络）隐藏。桌面（≥md）：「首页」文字标签（社区名在左侧栏顶部） | — | 完整药丸（chip + 地址/身份）；已连接时它是移动端页头唯一的社区名位置 |
| 二级（我的 NFT / 铸造身份 NFT / 空投铸造 / 兑换代币 / 应用） | 返回按钮 44×44 | 标题，单行 `truncate`，最长 8 字 | 药丸：chip 始终展示社区名（`max-w-[96px]` 截断，不再收成首字符圆徽），右触发区保留 |
| 占位页 | 返回按钮 44×44 | 标签名（行动；`/group` 旧深链为「链群」） | 药丸：chip 始终展示社区名（`max-w-[96px]` 截断，不再收成首字符圆徽），右触发区保留 |
| 收据态（页面内状态） | 「关闭」→ 首页 | 结果标题（铸造成功 / 兑换完成 / 已铸造） | 紧凑药丸（仅右触发区） |

- **移动端首页：未连接保留左侧标识，连上后由右上角 chip 承担（2026-11-11 owner 决定）**：未连接时右上角只有「连接钱包」，左侧社区标识是移动端唯一社区名；连上后（含错网络）左侧标识隐藏，社区名由右上角药丸的 chip 承载。桌面端仍由左侧栏顶部字标承载，二级页与占位页由标题承载。左侧标识是文字标签，不是第二个首页链接；不新增第二处社区名或第二个连接入口。
- 返回：有历史 → `back`；无历史（直接打开深链）→ 回首页。始终有返回，深链不产生无出口页面。
- 页内标题只描述页面，不重复社区名；社区名在 chip 里。避免「铸造身份 NFT · FOO」这种双标题。「铸造身份 NFT」正好 8 个字符（4 个汉字 + 空格 + 3 个拉丁字母），390 px 页头实测不截断（**2026-11-19 chip 不再收圆徽，标题先让位，实测待补**）。
- **社区名 = `symbol()`；`name()` 只用于技术详情/调试信息，不进主界面。** 只要界面出现「当前社区的名字」——桌面侧栏品牌行、右上角社区 chip、含社区名的页面标题、任何元信息行——一律渲染链上 `symbol()`（如 `TestLOVE20`）。没有选中/未知社区时，这些位置回退到协议标签「LOVE20协议」——它命名的是协议，不是一个代币社区；LOVE20 社区被选中时，社区名就是它自己的 `symbol()`「LOVE20」。页内标题原则上仍不重复社区名（见上一条）；若某个页内标题确实带上社区，用 `symbol()`。`name()` 是形如 `<子币 symbol>@<父币 symbol>` 的复合技术标识（如 `TestLOVE20@TestWETH`），不是显示名，不得用作社区名。
- **冷启动字标不闪协议名（QA 2026-11-14 G8）**：URL 没有 `?symbol=` 的首屏，左侧字标（移动端页头标识、桌面侧栏品牌行）在 `symbol()` 读回前**不渲染**，等链上社区名到手才出现——不先渲染「LOVE20协议」再换成社区名。协议标签仍只是「未知/未解析到社区」的稳定兜底：未知 symbol 等已定论的状态照旧回退「LOVE20协议」，产品语义不变。浏览器标签页标题不受此规则影响。
- **浏览器标签页标题**：有当前社区时 `<页面> · <社区 symbol>`；没有选中/未知社区时只写「LOVE20协议」。社区名同样取 `symbol()`，不用 `name()`。
- 药丸在手机与桌面位置相同（右上角），不做第二处连接入口；移动端社区名只由未连接时的左侧标识或连上后的药丸 chip 承载。

### 1.4 右上角连接药丸

一个容器、三种状态、两个触发区（照 TKM，但不放主题与锚定；主题是独立页面，见 §3.9）：

| 状态 | 外观与文案 |
|---|---|
| 未连接 | 单个按钮「连接钱包」，点击直接 `eth_requestAccounts`；进行中「连接中…」；点击后若 3 秒内仍无注入钱包 → 打开 §4.6 兜底抽屉（不显示死按钮「检测钱包中…」） |
| 链不对 | **社区名（静态展示，不可点、无菜单）** `│` 红色描边按钮「网络不对，点此切换」→「切换中…」；`wallet_switchEthereumChain`，4902 时 `wallet_addEthereumChain`（参数来自环境包），成功自动重连。保留社区名是 owner 2026-11-21 走查后定的：错网络时用户仍要知道自己在哪个社区（移动端 chip 是唯一社区名位置）；此状态钱包不可用，社区菜单也没有可信的链上数据，所以 chip 只作上下文、不响应点击 |
| 已连接 | `[SYMBOL ▾] │ [0x1234…abcd / 身份 NFT 名 ⌄]`；两区各自可点，互不触发 |

- 左触发区（chip）：`max-w-[96px]` `truncate`，`font-mono text-[13px]`；**任何视口、任何页面都展示社区名 chip**——不再在 <480px 或二级页收成 28px 首字符圆徽（owner 2026-11-19：只要有空间就展示社区名；页头放不下时由标题先截断）；chip 可点（**错网络态除外**：该状态只展示社区名、不可点，见上表）。chip 文案一律为当前社区 `symbol()`（§2.1），不是 `name()`；没有选中/解析到社区时，chip 文案回退到协议标签「LOVE20协议」（§1.3）。
- 右触发区：上行地址（mono 13，缩写 4+4），下行身份 NFT 名或「未选择身份 NFT」（11px 灰）；有进行中交易时右上角 6px 琥珀点（§4.2）。药丸本身是「打开菜单」的按钮，**不内嵌第二个复制按钮**（按钮不能嵌套）；钱包地址的点击复制在钱包弹层第一行（§1.6），点药丸即到。
- 弹层形态：`<md` 为底部抽屉（抓手 + 安全区 + 最大高 70dvh，可滚动）；`≥md` 为锚定弹层（代币 240px，钱包 288px，右对齐）。同一时刻只开一个。
- **关闭后焦点回到触发区（QA 2026-11-14 D-1）**：两个弹层无论用 Esc、右上角 ✕、点遮罩还是选中结果关闭，焦点都回到打开它的那个药丸触发区（WAI-ARIA dialog 惯例），不落到 `body`；键盘/读屏用户下一次 Tab 从触发点继续，而不是从页面顶部重新开始。实现：`MenuLayer` 在 Radix `onCloseAutoFocus` 里 `preventDefault()` 并手动 focus anchor。
- 未连接时整个药丸就是一个「连接钱包」按钮：不渲染两个触发区，也不做灰掉的假入口。

## §2 代币社区上下文

### 2.1 唯一事实源

- `?symbol=` 是当前社区的唯一事实源。**不持久化「当前代币」**（与 TKM 的 `localStorage._currentToken` 相反）；刷新、分享、返回都只认 URL。
- `?from` / `?to` 是兑换页自己的兑换对参数（§3.5），与 `?symbol=` 并行：切换社区不改写 from/to，切换 from/to 也不改写 `?symbol=`。
- 缺省或空：读环境包 `firstTokenAddress` 的 `symbol()` 后 `history.replaceState` 补上 `?symbol=`，不新增历史记录。
- 写入 URL 的 symbol 永远来自链上 `symbol()`（如 dev 链的 `TestLOVE20`），不接受用户手输；用户手改 URL 走 §2.5。
- **社区名 = `symbol()`；`name()` 只用于技术详情/调试信息，不进主界面。** 桌面侧栏品牌行、右上角 chip、含社区名的页面标题与元信息行都渲染 `symbol()`（如 `TestLOVE20`），不渲染 `name()`；没有选中/解析到社区时回退到协议标签「LOVE20协议」——它命名协议，不是代币社区。LOVE20 社区被选中时，社区名就是它自己的 `symbol()`「LOVE20」；其他社区则用各自的 `symbol()`。`name()` 是 `<子币 symbol>@<父币 symbol>` 的复合技术标识（如 `TestLOVE20@TestWETH`），不是显示名。
- 解析：`Launch.tokenAddressBySymbol(symbol)`；返回 `0x0` 即不存在。解析成功后保留其余 query（如 `?tx=`）。

### 2.2 切换判定表

| 场景 | 行为 |
|---|---|
| 首页 / 我的 NFT / 铸造身份 NFT / 空投铸造 / 兑换代币 / 应用 / 治理 / 我的（含质押资产） | 原地 `replace` 当前路径 + 新 `?symbol=`，保留其他 query，不整页刷新；整页内容走软过渡（§4.8，180/200 ms）|
| 占位页（行动；`/group` 旧深链） | 同上；URL 保持可分享，页面内容不变 |
| 未知路由 | `replace` 首页 + 新 symbol |
| 目标是当前社区 | 关闭弹层，不发任何请求 |
| 有 pending 交易 | 允许切换；任务继续，头部下方「进行中的操作」条保留，可回到原页看收据 |
| 页面正处于报价 / 输入 | 中止在途请求；兑换页保留 `from`/`to` 与输入金额（`?symbol=` 与兑换方向相互独立），报价按新区块/倒计时重取；其他页清空金额输入并回骨架（不同币价格不可复用） |
| 正处于收据态 | 允许切换；先提示「上一笔交易已经上链，收据仍可在『进行中的操作』里查看」 |

### 2.3 最近访问

- 键：`love20:v1:<chainId>:<launchAddress>:<wallet>:recentCommunities`（统一缓存封装，组件内禁止裸用 `localStorage`）。
- 值：`[{ symbol, address, at }]`；**上限 4**、按 `address` 去重、最新在前、排除当前项；解析成功后写入，切换时 merge 并置顶。
- 脏数据 / 反序列化失败 → 清空该键自身，不阻塞首屏。未连接时不读写（与 ADR-0003「未连接时代币面板不可用」一致）。
- **symbol 搜索直接切换**（§1.5）：命中的社区走同一个 `switchSymbol` → `?symbol=` replace + 写入最近访问，不新增持久化键、不新增第二套「当前社区」。

### 2.4 切换后重取 / 不重取

| 立即重取（query key 含 `tokenAddress`） | 不重取 |
|---|---|
| `symbol()` / `decimals()`（`name()` 仅在技术详情/调试需要时读取，不参与显示）、`parentToken()`、`childTokens()` 总数、`factory.getPair()` 与 `getReserves()`、报价、当前币余额 | 钱包与链、身份 NFT 列表与当前身份 NFT、LOVE20 余额、MemberNFT 铸造报价（按首币计价，与社区无关）、空投资格（空投代币固定为首币） |

### 2.5 错误页

- **symbol 不存在**：标题「没有找到这个代币社区」+ 原样展示 `?symbol=FOO`（mono）+ 「链接里的代币符号可能拼错了，或者这个代币还没发射。」主 CTA「回到首币社区」（replace 首币）；次入口：最近访问（最多 4 条，直接切换）；底部文字链「复制当前链接」。
- **链上读取失败**（不是找不到）：标题「暂时读不到链上数据」+ 「网络可能不稳，你的资产没有变化。」+ 主 CTA「重试」+ 次「回首页」；保留上次成功的数据并标注「上次更新于 X 分钟前」，不把旧数据当新数据。
- Launch 地址缺失属于构建期错误，不出现在界面。

## §3 八个页面

> 通用：未连接时页面不跳转，页内给「连接钱包」；链不对由外壳拦截（§1.4）：页头药丸是唯一的切换控件，三个任务页的页内卡只保留一句说明 + 「回首页」，不再放第二个切换按钮（§0.7：回首页仍是出口，不构成死路）。所有金额读取中一律骨架，不渲染 `0`。收据见 §4.3。**下文「LOVE20」指首币，界面一律渲染链上 `symbol()`（dev 链为 `TestLOVE20`）。** 同理，下文出现的「BNB」是 BSC 生产部署的原生币示例，界面一律渲染环境包 `nativeCurrency.symbol`（本地 anvil 为 `ETH`，BSC 为 `BNB`），不写死字符串。

页面清单：§3.1 首页 · §3.2 我的 NFT · §3.3 铸造身份 NFT · §3.4 空投铸造 · §3.5 兑换代币 · §3.6 应用 · §3.7 我的 · §3.8 关于 · §3.9 主题。

### 3.1 首页

**用户一句话目标**：打开就看到问候和「有没有需要我处理的事」；没有就保持干净。
**定位（2026-11-11 / 2026-11-12 owner 决定）**：首页是**问候 + 提醒流**，不是导航页。导航入口在「应用」目录（§3.6）；余额在「我的」（§3.7）、账户信息（钱包地址 / 网络）在右上角钱包弹层（§1.6），身份 NFT 的完整信息在「我的 NFT」（§3.2），首页只保留一句问候。没有重要信息或事项需要提醒时，首页就是一句问候，没有任何填充句，也没有页脚。
**进入条件与前置**：可未连接浏览；`?symbol=` 缺省补首币；身份取自本地选择并已按 `ownerOf` 校验。空投资格来自快照懒加载 chunk（见下），**不进入首屏包，也不阻塞问候与无身份提醒**。

**区块顺序（自上而下，每一块都条件渲染）**
1. **未连接 → 连接入口** — 说明「一个钱包可以拥有多个身份 NFT，身份 NFT 才是参与凭证。」+「连接钱包」（与右上角药丸是同一个连接动作与状态，不新增第二套连接入口）。
2. **问候（常驻，页面 `h1`）** — **居中**单行（`text-center` + `truncate`，owner 2026-11-19 由左对齐改居中；仍只占一行、仍截断）、**不是链接**。连接且有当前身份 NFT → 「你好，{memberName}」；连接但无身份 NFT、持有但未选择、读取中 → 「你好」；未连接 → 「你好」。问候不显示余额、不显示 `#memberId`；余额详情在「我的」（§3.7），身份 NFT 详情在「我的 NFT」（§3.2）。
3. **提醒卡（按固定顺序，仅适用时出现）**
   - **无身份 NFT**：「你还没有身份 NFT」+「铸造身份 NFT」→ `/mint`。
   - **持有身份 NFT 但未选择**：「你还没有选择身份 NFT」+「选择身份 NFT」→ `/my-nft`（保留当前 `?symbol=`）。与「无身份 NFT」互斥，固定在它之后、空投卡之前。
   - **身份读取中**：在提醒卡位置渲染紧凑骨架（短句「读取身份 NFT 中…」+ 两行骨架），不显示长文案，也不显示会失败的 CTA；避免首页从「只有问候」闪成提醒卡。
   - **身份读取失败**：「身份 NFT 暂时读不到」+ 一行原因「网络可能不稳，你的身份 NFT 没有变化。」+「重试」；「重试」调用身份读取模型的 `refetch`，真的重新读取。RPC / 本地链不可达时也落到这里，**页面不得静默只剩问候**。
   - **环境未部署身份 NFT 合约**：「这个环境还没有部署身份 NFT 合约」+「这里暂时不能铸造身份 NFT。」；不给「铸造身份 NFT」等会失败的 CTA，也不给「重试」（重试不能部署合约）。同一句在 `/my-nft` 复用。
   - **有空投资格且未铸造**：「你有空投资格，可铸造 {X} {symbol}」+「空投铸造」→ `/airdrop`（保留当前 `?symbol=`）。`X` 来自 `claimableAmount`；金额或首币 symbol/decimals 读不到时**省略金额分句**（只写「你有空投资格」），绝不把「—」写进句子里。
   - **有未确认交易**：「1 笔交易还没确认」+「查看」。**M0 未实现**：今天三个写流程各自持久化自己的记录（`mintTask` / `airdropClaim` / `swapReceipt`），没有统一的 pending-tx 读取模型；在出现单一持久化 pending 辅助函数前，这张卡不渲染，也不伪造数量（见 `home-page.tsx` 的 TODO）。
4. **没有适用项** — 只有问候。**不写**「现在没有需要你处理的事。」或任何等价占位句；没有提醒卡，也没有实心按钮。
5. **没有页脚**（owner 2026-11-12）— 首页不再渲染「开源文档」链接，也不再有「技术详情」折叠。开源文档、版本号、链 ID / RPC 与全部合约地址都在 `/about`（§3.8）；首页不再重复这套样板。

**已移除（2026-11-11 / 2026-11-12）**：三个常驻入口行（我的 NFT / 空投铸造 / 兑换代币，已在 `/apps`）；首页细行与其上的余额（问候取代；余额去 §3.7）；独立的身份卡；旧的「现在没有需要你处理的事。」空态句；页脚「开源文档」链接与「技术详情」折叠（2026-11-12，改由 `/about` 承担）。首页不再按 LOVE20 余额不足追加提醒，也不出现「无需操作」静默态之外的额外说明。

**快照加载与提醒卡显隐**
- 当前网络内置的空投快照 JSON 是**首屏渲染之后才 `import()` 的懒加载 chunk**；本地 root 与链上一致时不请求远端，本地缺失、损坏或 root 不一致时回退链上 HTTP(S) URI。问候与无身份提醒先可用，快照数据就绪后空投提醒卡原地出现；**不预留占位、不显示骨架、不阻塞问候**。
- 快照未就绪 → 不显示空投提醒卡；钱包不满足资格 → 不显示卡，也不写「无资格」。
- 本地失效且远端回退仍失败 → 不显示空投提醒卡；首页保持干净（不额外造一行错误文案）。

**实心按钮**：一屏最多一个实心按钮。只有第一张出现的提醒卡提供它：无身份卡与「未选择身份 NFT」卡互斥、都在空投卡之前，所以有任一张时它用实心、空投卡用描边；只有空投卡时它是实心。未连接时实心按钮是「连接钱包」。问候永远不是实心按钮。

**状态与错误**

| 身份状态 | 首页表现（问候 `h1` 常驻） |
| --- | --- |
| `disconnected` | 连接入口卡 +「你好」；没有身份提醒卡 |
| `loading`（已连接） | 「读取身份 NFT 中…」+ 紧凑骨架卡；无 CTA |
| `error`（已连接） | 「身份 NFT 暂时读不到」+ 一行原因 +「重试」（`refetch`）；RPC 不可达也走这里 |
| `unconfigured`（已连接） | 「这个环境还没有部署身份 NFT 合约」+「这里暂时不能铸造身份 NFT。」；无 CTA |
| `empty` | 「你还没有身份 NFT」+「铸造身份 NFT」→ `/mint` |
| `needs-selection` | 「你还没有选择身份 NFT」+「选择身份 NFT」→ `/my-nft` |
| `ready` | 「你好，{memberName}」；没有身份提醒卡 |

- **问候只在 `ready`（`ownerOf` 已校验）时点出身份名称**：其余状态（含本地缓存了 tokenId 但正在读取、读取失败、未部署、无身份、未选择、未连接）一律「你好」——缓存的选择不是事实，与 §1.4 药丸/钱包弹层的规则一致，避免首页点名而药丸显示「—」。
- **「首页在任何身份读取状态下都不允许只显示问候语」**：`loading` / `error` / `unconfigured` 都必须给出骨架、原因或环境说明；只有 `ready` 且没有提醒事项时，首页才允许只保留问候。
- 任何未知值用「—」；身份读取错误在首页就地说明并重试，其他页面的重试入口仍留在「我的」与各任务页。

**验收**
- 未连接打开：左侧社区标识可见；看到问候 `h1`「你好」与「连接钱包」；不再有 `/me` 细行。
- 连接后有身份 NFT、无事可做：左上标识消失；`h1` 显示「你好，{memberName}」；首页不显示余额；页面只有问候，实心按钮 = 0，没有页脚，也没有「现在没有需要你处理的事。」。
- 连接后无身份 NFT：`h1` 为「你好」；出现「你还没有身份 NFT」+「铸造身份 NFT」，点击进入 `/mint`。
- 连接后身份读取中：`h1` 为「你好」；提醒卡位置出现骨架卡「读取身份 NFT 中…」，页面不是裸问候。
- 连接后 RPC / 本地链不可达：`h1` 为「你好」；出现「身份 NFT 暂时读不到」+ 一行原因 +「重试」；点「重试」会重新读取，恢复后出现正常提醒卡。
- 连接后环境未部署身份 NFT 合约：出现「这个环境还没有部署身份 NFT 合约」+「这里暂时不能铸造身份 NFT。」；不出现「铸造身份 NFT」或「重试」。
- 连接后持有身份 NFT 但未选择：`h1` 为「你好」；出现「你还没有选择身份 NFT」+「选择身份 NFT」，点击进入 `/my-nft` 并保留 `?symbol=`；此时不出现无身份卡。
- 有资格：出现「你有空投资格，可铸造 {X} {symbol}」+「空投铸造」，点击进入 `/airdrop` 并保留 `?symbol=`；金额未知时句子里没有「—」。
- 无资格：空投提醒卡不出现，首页只剩问候。
- 身份 NFT 被转走后刷新：中性提示语义由「我的」承担；首页问候回落到「你好」，并出现无身份提醒，不出现指向旧身份的操作。
- 快照 chunk 晚于首屏：问候先可用，提醒卡在数据就绪后出现，不遮挡、不阻塞问候。
- 任一屏最多一个实心按钮；390px 下问候居中、保持单行并被截断，不换行。

### 3.2 我的 NFT

**用户一句话目标**：看清我有几个身份、现在用哪个，并立即换一个。
**进入条件与前置**：需连接（页内连接）；从「应用」目录或钱包弹层身份行进入。身份 NFT 列表 = `balanceOf(wallet)` + `tokenOfOwnerByIndex(wallet, i)`（Multicall3 批量）+ `memberName(tokenId)`。

**布局（参照参考实现的同页，只取结构）**
- `<md`：**卡片行**，一个身份 NFT 一张卡，卡内依次是 `NFT #memberId`、`memberName`、当前身份 NFT pill 与操作。
- `≥md`：**表格**，列为 NFT 编号 / 名称 / 操作。
- 两种形态共用同一排序：**当前身份 NFT 第一，其余按 `memberId` 升序**；当前行整行着色（accent tint）并带「当前」pill。
- 持有数量始终显示真实值，**不因 N ≤ 3 隐藏**；写操作进行中**不禁用整张表**（见状态）。

**区块顺序**
1. **摘要条** — 只写「持有 {N} 个身份 NFT」，不重复当前身份 NFT 名字；空态不渲染摘要条（空态卡已给结论）。数据：`balanceOf`。
2. **说明段（两行内）** — 「每个身份 NFT 都是一个独立的身份，可以在多个社区使用。换钱包不会改身份 NFT，只有转让才换控制者。」
3. **身份 NFT 列表** — 卡片行（<md）/ 表格（≥md）；字段只有 `NFT #memberId`、`memberName`、当前 pill、操作。`tokenURI` 返回空字符串，**不渲染图片、不请求任何图片源**。
4. **行内操作** —
   - 「使用此身份 NFT」：**纯本地选择**，写入本地当前身份 NFT 并立即更新页面，**不发起链上交易、不签名、不等待**；成功后该行置顶并着色。点击期间该行按钮变「切换中…」+ `aria-busy`；被点的卡片**从当前位置平滑移动到列表最顶部**（FLIP，300 ms，`cubic-bezier(0.22, 1, 0.36, 1)`，§4.8.1；`prefers-reduced-motion: reduce` 时直接落位、不播放）。当前行只保留「当前」pill + 行底色 + 一个禁用的行内按钮（不再写一遍「当前身份 NFT」文字）。
   - 「转让」：打开转让抽屉（收款人三选一：**按地址 / 按身份 NFT ID / 按身份 NFT 名字**，输入框左侧的小下拉与代币转账页是同一个共享控件 `shared/ui/identity-input-mode`，校验同源 `shared/lib/identity-input`，两页文案/键盘/错误一致），警告「转让会改变这个身份 NFT 的控制者。身份 NFT 的历史与质押绑定在身份 NFT 上，会随身份 NFT 一起转到对方钱包，之后由对方控制。」（owner 2026-11-14：不再写「不可撤销」这类冗余提示；owner 2026-11-16 纠正方向：不是「留在原钱包」）确认后 `safeTransferFrom(你, 对方, memberId)`；成功的收据写「已转让给 0x…」；若转的是当前身份 NFT，同时清除本地选择——还有其他身份就回到「未选择身份 NFT」，没有则回落到无身份形态。
     - **智能资产保护（owner 2026-11-16，同日收口）**：抽屉内收款人下方是共享开关「智能资产保护」（与 `/transfer`、`/batch-transfer` 同一个偏好，默认开启）；开启时收款人是地址簿已知合约 → 显示「智能资产保护已拦截：这是「{合约名}」合约地址」+「转进合约的资产很可能取不回来。要强制转账，请先关闭「智能资产保护」。」，「确认转让」禁用；关闭开关只跳过「是不是地址簿已知合约」这一项检测——拦截块消失、不再点名合约，同一地址按任意合约规则只出现「这个地址是一个合约」警告，转让恢复可用（按地址/ID/名字的校验与名字确认一条不少）。任意有 bytecode 但不是地址簿条目的收款方只出现「这个地址是一个合约」警告，开关开启/关闭都不阻断。
     - **按地址**：校验 `0x` + 40 位、非零、非自己。
     - **按身份 NFT ID**：`#id` → `ownerOf(id)`；不存在 / 属于自己 / 读取失败各有明确文案与重试；解析出的 owner 地址可点击复制（§4.7）。
     - **按身份 NFT 名字**（owner 2026-11-12，防名称混淆）：用合约 O(1) 的 `memberId(name)` 直接解析（合约内部自行做 `normalizeName` 规范化，输入原样传入）；返回 0 或调用 revert 即「这个身份 NFT 不存在」。名称→id 结果在本会话内缓存（缓存键按规范化名，大小写不同不重复查），不轮询；持有人始终重新读 `ownerOf`，并读一次 `memberName(id)` 在确认区展示链上规范名。**解析成功后必须二次确认**：显示「名称「{name}」→ 身份 NFT #{id}」「收款人 {短地址}」与「名称相近或看起来相同的身份 NFT 可能存在，名称不是唯一依据」；用户勾选「我确认 #{id} 就是正确的身份 NFT」之前，「转让」保持禁用。找不到 / 属于自己 / 解析失败（可重试）均是具体文案，不用泛化错误。
5. **底部** — 「铸造新身份 NFT」（描边按钮）。不再有「回首页」文字链（owner 2026-11-14；回首页交给底部标签栏与页头返回），也不再有不折叠的高级区：MemberNFT 合约地址在 `/about`（§3.8）。
6. **铸造回执返回（owner 2026-11-16）** — 从 `/mint` 铸造回执点「好的」进入本页时，列表上方一行「已铸造 #{id} {name}，已经出现在下面的列表里。」，对应行整行成功色 tint +「刚铸造」pill；进入时重新读一次 `balanceOf` / 枚举（不吃 15 秒读缓存），离开本页后返回条与高亮消失。

**状态**：未连接「连接钱包后查看你的身份 NFT。」+ 说明「没有身份 NFT 也能先看看这里能做什么。」+ 连接按钮 · 加载（3 行骨架 + 摘要骨架）· 空「你还没有身份 NFT。」+ 说明「铸造需要一个名字和少量 LOVE20。」+ 主 CTA「铸造身份 NFT」· 错误「身份 NFT 列表暂时读不到。」+「重试」· 未部署「这个环境还没有部署身份 NFT 合约」+「这里暂时不能铸造身份 NFT。」（无 CTA；与首页同一句）· 身份失效（行内标「已失效」并不可选，同时清除本地选择）· 智能资产保护开关开启且命中已知合约（拦截）/ 关闭（不再检测已知合约，命中合约地址只剩通用警告）· 转让中（**仅该行**显示「转让中…」；其余行的「使用此身份 NFT」照常可用，其余行的「转让」按 §4.2 的单一写操作约束禁用并注明原因，**整表不禁用**）。「使用此身份 NFT」仍是本地选择：忙碌态（「切换中…」+ `aria-busy`）持续到卡片移动结束且 `ownerOf()` 确认新身份，没有链上等待态，也不再有整页淡出淡入（§4.8.1）。
**主 CTA 与次要入口**：有身份时无主 CTA（列表即内容），唯一实心按钮是空态的「铸造身份 NFT」；每行操作为文字/描边按钮。「转让」为危险色并二次确认。
**死路处理**：空态给「铸造身份 NFT」；错误态给「重试」；失效行给「重新选择」。任何一行都不允许只有名字没有操作。
**加载骨架**：摘要条灰块 + 3 行等高行（名称 60% 宽、`#id` 30%、右侧按钮方块）。
**验收**
- 窄屏（<md）为卡片行，宽屏（≥md）为 NFT 编号 / 名称 / 操作 三列表格。
- 持有 2 个身份 NFT：2 行，当前项置顶、整行着色并带「当前」pill；当前行没有「使用此身份 NFT」按钮，只留禁用按钮。
- 空钱包：只有空态卡（「你还没有身份 NFT。」+ 说明 +「铸造身份 NFT」），上方没有「持有 0 个身份 NFT」摘要条。
- 持有 ≤3 个身份 NFT 时数量仍显示真实值，不隐藏。
- 转让抽屉可按名字解析：输入已存在的名字后看到「名称「…」→ 身份 NFT #id」与收款人短地址，未勾选确认前「转让」禁用，勾选后启用；输入不存在的名字显示「没有找到这个名称对应的身份 NFT。」。
- 点「使用此身份 NFT」后无需签名立即生效，置顶与着色移动到该行；回首页看到新名字。点击瞬间按钮变「切换中…」（`aria-busy`），被点的卡片**从原来的 y 位置平滑移动到列表首位**（起点 = 点击前的位置、终点 = 首项位置，中间有若干过渡帧，300 ms），另一张卡同步下移；页面**不再整页淡出淡入**（`<main data-transition>` 始终保持 `idle`），没有整页白屏或突然跳变；`prefers-reduced-motion: reduce` 下直接落位、无动画。
- 从铸造回执点「好的」进入本页：看到「已铸造 #{id} {name}，已经出现在下面的列表里。」+ 该行「刚铸造」pill 与成功色 tint，且该身份**没有被自动选中**（选择仍是本地动作）。
- 不点铸造回执的「好的」时停留在 `/mint`；刷新 `/mint` 不会重复弹回收据（一次性页面状态）。
- 无身份：看到「铸造身份 NFT」并能进入铸造页。
- 转让确认后：该行消失；若转的是当前身份 NFT，本地选择被清除——还有其他身份时回到「未选择身份 NFT」，没有时回落到无身份形态；转的不是当前身份 NFT 则当前身份 NFT 不变；警告写明只换控制者、历史与质押绑定在身份 NFT 上并随身份 NFT 一起转到对方钱包。
- 转让进行中：整张表不被禁用，只有相关行的写操作受限；其他行仍可「使用此身份 NFT」。
- 刷新后当前身份 NFT 仍是上次所选（`ownerOf` 校验通过）。

### 3.3 铸造身份 NFT

**用户一句话目标**：用一个名字铸出身份 NFT，事前知道要花多少、还差什么、下一步去哪。
**进入条件与前置**：需连接 + 链正确；还没有身份 NFT 的用户是主客群。价格按 LOVE20 计价，与当前社区无关。

**区块顺序**

### 3.4 空投铸造

**用户一句话目标**：三十秒内知道自己有没有、能铸造多少、现在能不能铸造，并一次完成。
**进入条件与前置**：需连接；S6 已铸造态的金额必须能在**任意设备**上显示（不得依赖本机缓存，见 [CI-014](../contract-issues/014-airdrop-claimed-amount-not-readable.md)）；资格来自 Merkle 快照（share + proof），快照来源按代币分两条路径（见下），文档按需懒加载、**不进首屏包**。空投代币固定为首币 LOVE20，**与当前社区无关**，切换社区不改变本页内容。页头标题只写「空投铸造」，**不设副标题或解释句**；状态卡**不设「本次空投：{symbol}」元信息行**（owner 2026-11-17 删除；空投代币改由 S5 第 1 行整句点名），资格与份额来源收进「规则」折叠（默认展开，见下）。界面任何位置都不写「领取」；合约动作 `claim` 只保留在代码、合约与术语表里。

**数据源与快照（2026-11-12 起）**
- 合约是 `AirdropDistributor`（地址簿 `airdropDistributor`，`/about` 标签「空投分发器」）。`claim(tokenAddress, share, proof)` 只付给 `msg.sender`，**没有 account 参数**；账户永远是当前连接的钱包。
- 报价与状态：`claimableAmount(token, account, share, proof)`、`isClaimed(token, account)`、`claimedAmount(token, account)`（一次 `eth_call`，不再扫事件）。每 token 的根、轮次、份额与池额全部来自**一次** `airdropInfo(token)`：`merkleRoot`、`claimableFromRound`、`snapshotUri`、`totalClaimedShare`、`totalRemainingShare`、`totalClaimedAmount`、`remainingAmount`；`TOTAL_SHARE()` 仍是链上常量。
- 快照来源：**创世代币**优先懒加载构建内置的 `src/config/network/<network>/airdrop.json`，文件 root 与链上 `airdropInfo(genesisToken).merkleRoot` 一致即使用，不请求远端。本地缺失、损坏或 root 不一致时，回退链上 HTTP(S) URI；远端也须比较 root。新部署在构造期写入本网络 Pages URI，此后不可修改；旧部署可能仍为空 URI，本地匹配时照常可用（[CI-017](../contract-issues/017-genesis-snapshot-uri-locked.md)）。两种来源均不可用时按 S2「空投资格暂时读不到」+「重试」处理，不显示数字。
- **后续 Launch 的代币**：沿用同一套加载器，通过链上 `airdropInfo(token).snapshotUri` 获取 JSON（仅接受 HTTP(S)），同样比较文件 root 与链上值。前端不重建整棵树；当前钱包的 share/proof 由链上 `claimableAmount` 校验，失败态可重试。完整快照的证明与份额总和在生成、同步和发布阶段预检。
- **轮次门槛**：`Phase.currentPhase() < airdropInfo(token).claimableFromRound` 时 `claim` 会回滚 `ClaimRoundNotReached`。此时页面显示独立门槛态（见 S5-G），不显示金额、不出现任何铸造 CTA。等待时间只用「剩余区块 × 观测秒/块」估算成「约 X 分钟」（`observations(0,2,true)`，不足两条时退回 `TARGET_SECONDS / currentPhaseBlocks`），**不得显示绝对时间戳**。

**区块顺序**
1. **状态卡** — 七态之一（见下）或轮次门槛态；卡内没有元信息行，直接进入该态自己的内容（owner 2026-11-17 删除「本次空投：{symbol}」，空投单位只在 S5 第 1 行出现）。S5 可铸造态的卡是**两行**：第 1 行整句「我的份额 {percent}，预计可铸造空投 {symbol}：」（`data-testid="airdrop-share-percent"`，`text-sm` 弱化），第 2 行只放数量（`data-testid="airdrop-expected-amount"`，强调级 `text-2xl`，**不再重复 symbol**；可访问名是完整句「预计可铸造空投 {amount} {symbol}」）。改版前的「预计可得」标签、单位与金额说明小字「按铸造时的池子余额与剩余份额计算，别人铸造后金额会变。」均已删除（owner 2026-11-17）。数据：`claimableAmount(LOVE20, wallet, share, proof)`、`airdropInfo(LOVE20).remainingAmount`、`airdropInfo(LOVE20).claimableFromRound`。
2. **主按钮区** — 仅「可铸造」态出现「立即铸造」（owner 2026-11-17 由「空投铸造」改名）；轮次门槛态没有任何铸造 CTA。

### 3.5 兑换代币

**用户一句话目标**：把任意一种代币换成另一种，事前知道会走哪条路径、能拿到多少、最少拿到多少。
**进入条件与前置**：需连接；**任意代币 ↔ 任意代币**，包括链原生币、包装原生币与任意已发现的社区代币，不再限定原生币买入。代币集合只来自链上与环境包：社区代币用 `Launch.tokens(offset, limit, reverse)` 分页发现，用 `Launch.parentToken(token)` / `Launch.childTokens(parent, offset, 20, reverse)` 还原父子树，用 `Launch.tokenAddressBySymbol(symbol)` 做符号精确查找；除环境包提供的原生币与包装原生币两个条目外，**不维护任何硬编码代币清单**。`?from=<symbol>&to=<symbol>` 决定兑换对并写入 URL，可深链分享；`?symbol=` 仍是当前社区上下文，与 from/to 相互独立。缺省时 `from` 取环境包原生币、`to` 取当前社区代币（`?symbol=` 解析结果，解析不到回退首币），解析完成后把这两个缺省值 `replace` 进 URL。原生币用环境包配置的符号寻址（本地 anvil 为 `ETH`，BSC 为 `BNB`），不写死「BNB」。from/to 任一未知、相同或解析不到 → 中性错误态（见下），不崩溃、不白屏。

**区块顺序**
1. **兑换卡（顶部，两行）** —
   - 「从」：金额输入 + 代币选择器（显示 `symbol()`）+ 当前代币余额 + 「全部」快捷键；输入原生币时「全部」按「余额 − 预留网络手续费」计算并标注「约」。
   - 中间 ⇅ 方向按钮：交换 from/to 并重报价；原生币与包装原生币互逆时仍用同一按钮。
   - 「到」：只读金额（标签「预计可得」）+ 代币选择器（只显示 `symbol()`）+ **到账代币余额**（owner 2026-11-14：「到」这个代币也应该显示余额）。余额行与「从」侧同一规则、同一个 `swapBalanceLine`：`余额 {symbol} {amount}`，小数位按数量级自适应（截断不四舍五入，规则见前端规范 §4.5.1）、精度标签 18 位不写、非 18 位（含 0/6/8/24…）在余额下方单独一行写「精度 {n} 位」、未知写「—」、0 正常写 `0`；读取中显示骨架，读取失败写「读不到余额」。
   两个选择器打开同一个「选择代币」抽屉：分组「原生币 / 包装原生币 / 社区代币」；社区代币按 `Launch.tokens` 分页（每页 20，「加载更多」），顶部搜索框用 `Launch.tokenAddressBySymbol` 精确匹配 symbol。选中即用 `replace` 写回 `?from`/`?to`，保留 `?symbol=` 与其他 query，不新增历史记录。
   **两个选择器互斥（owner 2026-11-14）**：选择器不提供另一侧当前已选的代币 —— 列表里没有、搜索也查不到，列表顶部写一行「另一侧已选 {symbol}，这里不能再选；想换过来请用中间的交换方向。」。若程序化路径（深链重写、恢复动作）仍选到重复代币，按「交换方向」处理：`?from`/`?to` 直接互换并 `replace` 写回。因此正常选择路径永远不会进入「这个兑换对不可用」态；只有深链本身写了相同 symbol 时才保留中性错误态。
2. **信息块（全页唯一）** — 主信息三行：
   - 「1 {FROM} ≈ {rate} {TO}」；
   - 「路径 {A} → {B} → {C}」（低权重、单行，最多 3 跳；即使只有 1 跳也显示，例如 `TestWETH → TestLOVE20`）；
   - 「最少到账 {minOut} {TO}」+「最多可接受的价格变化 [0.1% / 0.5% / 1.0% / 自定义]」（默认 0.5%）。
   以上为主信息；手续费率能读到才写「手续费率 {fee}%」，读不到只写「以链上费率为准」；价格影响 >1% 才显示「价格影响 约 {x}%」，读不到就不显示该行。任何情况下都不猜数字。
   报价状态：只显示剩余 `{n}s` 倒计时（同一行不再写「更新于 {n} 秒前」）；随新区块或 30 秒定时重报价。倒计时归零且新报价未返回时，标「报价已过期」并禁用主按钮，直到新报价返回。
3. **动作组（信息块下方，按钮并排）** — 「授权」与「兑换」是同一组动作，紧邻成一组（owner 2026-11-16：「授权和兑换按钮应放到一起，价格卡片应放到两个按钮上面」）：
   - ERC20 输入（需要授权）：`授权 {symbol}`（§4.1 全局文案，次要样式）在左、`兑换`（主样式）在右，同一行并排；390 px 移动端也放得下（两枚按钮等分整行、单行文案、不换行）。默认使用长期授权开启时按钮写 `长期授权 {symbol}`、授权额 `maxUint256`，提示改成「这次会授权长期额度（几乎无限）…」。授权确认后授权按钮原地变只读的 `已授权`、`兑换` 解锁；已是长期授权则显示禁用的 `已长期授权`（无需操作）。
   - 原生币输入 / 包装解包（不需要授权）：按钮组里只有「兑换」，占满整行。
   - 两个按钮都在内容流里，不再有吸底按钮栏，也不再有编号式「1 授权 / 2 兑换」；授权说明（`note`）与「授权额度不够这次使用」提示放在按钮组下方一行，不把按钮挤开。
4. **主按钮** — 一个主操作位「兑换」，就是动作组里的主样式按钮；需要授权时禁用（先点同组的 `授权 {symbol}`），授权确认后解锁。明细见「执行阶梯」。
5. **收据 / 错误卡** — 成功后整页替换为收据（§4.3）：实际到账金额从回执中交易对的 `Swap` 事件解析（按方向取 `amount0In/amount1In/amount0Out/amount1Out`），ERC20 输入另核对 `Transfer`，**不用报价当结果**；原生币 ↔ 包装原生币的收据取 `WETH9` 的 `Deposit`/`Withdrawal` 金额。失败卡保留 from/to 与金额，给「重新报价并重试」，说明「没有成交，只消耗了网络手续费」。不再有高级折叠：交易对与 Router 地址在 `/about`（§3.8）；滑点容忍度参数与路径 / 最少到账仍留在上方信息块。

**路径解析**
- 交易对图是一棵以包装原生币为根的父子树：每个社区代币只与自己的父币有 Uniswap V2 交易对（`Launch` 建币时 `createPair(token, parent)`）。在 `factory.getPair(a, b)` 能确认的交易对图上找**最短路径**（通常就是 A 上溯到最近公共祖先再下行到 B）；相邻两枚代币必须 `factory.getPair(a, b) != 0x0` 且 `getReserves()` 两边储备都非零。原生币在路由里以包装原生币参与（`Router.WETH()`），界面显示仍写原生币符号。
- 最多 **3 跳**。例：`WBNB → 父币 → 子币`；本地为 `TestWETH → TestLOVE20`。无路径、超过 3 跳、或路径上任一交易对储备为零 → 该方向不可兑换，说明卡在哪一跳，给「换个代币」与「回首页」。
- 原生币 ↔ 包装原生币是 **1:1 包装/解包**，不经过交易对、无手续费与价格影响（`WETH9.deposit` / `withdraw`）；界面汇率行只写「1 X = 1 Y（包装/解包，不经过交易对）」，「无手续费」只由手续费行承担。界面仍用「兑换」按钮与同一套收据。

**报价与保护**
- 报价只调 `Router.getAmountsOut(amountIn, path)`，不在前端复刻 AMM 公式；提交前再读一次，用最新报价重算 `amountOutMin = quote × (1 − 容忍度)`（向下取整）。
- 「最多可接受的价格变化」默认 0.5%，可见档位 0.1% / 0.5% / 1.0% / 自定义；改变档位立即重算「最少到账」。自定义值限制在 0.01%–50%（超出给行内错误），不把「授权缓冲」当滑点。
- 价格影响用 `getReserves` 隐含的边际价与 `getAmountsOut` 成交均价之差估算；> 1% 时显示「价格影响 约 {x}%」，> 10% 时追加红色提示「这笔兑换会明显改变池子价格，继续前请确认。」与「继续」二次确认（提示里不再重复百分比）。≤1% 不显示这一行。
- **手续费率不写死**：从 `Stake` 合约读两个 1e18 定点参数 `SWAP_FEE_FOR_LP_RATIO` / `SWAP_FEE_FOR_PROTOCOL_RATIO`，费率 = 两者之和（合约构造时保证 `lp > proto`、`lp + proto < 1e18`）；能读到才显示「手续费率 {fee}%（已含在报价里）」，百分比 2 位小数、向下截断（本地 `3e15 + 0` → `0.30%`）。读不到（地址簿没有 Stake、getter 失败、参数违反合约不变量）不显示百分比，只写「以链上费率为准」。本地 anvil 为 0.30%、BSC PancakeSwap 为 0.25%，这两个数字只作为部署事实，不作为常量进入报价或计算；台账里「1e18 − lp − proto」是净比例（0.997），不是费率，见 `docs/product/three-line/swap-fee.md` §0.1。
- 报价随新区块或 30 秒定时刷新；信息块只显示倒计时（不再显示「更新于」）。倒计时归零即把报价标为「报价已过期」并禁用主按钮；新报价返回后恢复。失败可见重试，不静默用旧报价提交。

**执行阶梯**

| 输入 / 输出 | 授权 | 调用 |
|---|---|---|
| ERC20 → 任意 | 是：授权额 = 本次输入金额，精确到 wei，不加缓冲、不授权无限额 | `swapExactTokensForTokens`（ERC20 输出）或 `swapExactTokensForETH`（原生币输出） |
| 原生币 → ERC20 | 否：单按钮「兑换」 | `swapExactETHForTokens` |
| 原生币 ↔ 包装原生币 | 否 | `WETH9.deposit` / `withdraw`，1:1 |

- ERC20 输入且 allowance 不足：两段式「授权 → 兑换」两个按钮并排（授权在左、兑换在右）→ 授权确认后停在本页，授权按钮原地变只读「已授权」，兑换按钮解锁；授权额精确等于 `amountIn`，不改写成报价或加缓冲。
- 授权与兑换的按钮文案走 §4.2 三态：`授权中…` → `确认中…` → 成功/失败；兑换同。原生币输入没有授权阶段。

**状态**
- 未连接：「连接钱包后兑换。」+「连接钱包」。
- 未配置（test/prod 空地址簿）：「这个环境还没有配置兑换。」+「回首页」；不发起任何链上请求，不崩溃。
- 加载：余额、路径与报价显示骨架，不渲染 `0`。
- 空输入：主按钮禁用，无报错。
- 报价中：主按钮禁用 + 金额骨架。
- 可兑换。
- 余额不足：「{FROM} 不够，还差约 {x}」；原生币输入同时提示需预留网络手续费。
- 池子为空（见下）。
- 无路径 / 超过 3 跳：「这个方向没有可用的兑换路径。」+「换个代币」+「回首页」。
- from/to 未知或相同：「这个兑换对不可用。」+「链接里的代币符号可能不存在，或者这个代币还没发射。」+「选择代币」+「回首页」。
- 报价失败：「价格暂时读不到。」+「重试」。
- 价格影响 > 10%：红色提示 + 需二次确认。
- 授权中 / 确认中 / 上链中 / 成功（收据）/ 失败（错误卡）。

**池子为空（本协议的真实默认态）**
发射代币时只 `createPair` 建池，不注入流动性，所以新社区大概率无储备。文案：标题「这个兑换对还没有可兑换的流动性。」+ 说明「发射代币时只创建了交易对，没有注入资金，所以现在换不了。」+ 主「换个代币」（打开代币抽屉）+ 次「回首页」+ 高级「查看交易对地址」。**不承诺通知，不出现「稍后重试」这种无信息的按钮。**

**主 CTA 与次要入口**
- 一个主操作位：「兑换」；需要授权时先完成同一按钮组里的 `授权 {symbol}`（默认使用长期授权开启时是 `长期授权 {symbol}`，§4.1），再点「兑换」。页面底部不再有「回首页」文字链；回首页交给底部标签栏与页头返回。
- 页面只有两个代币选择器、两个金额、一个动作组（授权 + 兑换并排，或单个兑换）、一个信息块；**不做订单簿、限价单、K 线或图表**。

**死路处理**：空池、无路径、from/to 无效、余额不足、报价失败、报价过期都有明确下一步；失败重试必须重新报价并刷新 `amountOutMin`；不出现只有一句话的终局。
**加载骨架**：输入框可先输入；选择器显示骨架；信息块 3 行灰条 + 按钮灰块；余额与报价就绪后原地替换，不整页 spinner。
**验收**
- 用户可以从任意已发现代币换到任意另一种（含原生币、包装原生币与社区代币），反向同样可用。
- 深链 `?from=ETH&to=TestLOVE20` 能直接打开并报价；`?symbol=` 切换社区不改变 from/to，也不清空金额。
- from/to 写错或指向不存在的 symbol 时，看到中性错误与「选择代币」，页面不白屏、不崩溃。
- 用户能看到路径（如 `TestWETH → TestLOVE20`）与「最少到账」，默认「最多可接受的价格变化」为 0.5%，改成 1.0% 后「最少到账」立刻变化。
- 报价倒计时归零后出现过期标记，主按钮禁用，直到新报价返回。
- ERC20 输入需要授权时：价格/信息卡片在按钮组上方，`授权 {symbol}`（次要样式）与「兑换」（主样式）并排成同一组、390 px 移动端同排不换行，兑换按钮禁用；授权额等于本次输入金额；**开关「默认使用长期授权」打开后，按钮文案变成 `长期授权 {symbol}`，点击写入的链上 allowance = `maxUint256`（不是本次金额）**；原生币输入不出现授权步骤，按钮组里只有占满整行的「兑换」。已长期授权时按钮显示 `已长期授权` 且无需操作，兑换可直接进行。
- 池子为空时看到专门说明与「换个代币」「回首页」两条出路。
- 成功后显示的实际到账来自回执中交易对的 `Swap` 事件（原生币 ↔ 包装原生币取 `WETH9` 的 `Deposit`/`Withdrawal`），不是用报价当结果。

### 3.10 代币转账

**用户一句话目标**：把一种代币转给一个地址（或一个身份 NFT 的持有人），事前看清余额、金额与收款方，事后拿到可核对的回执。
**进入条件与前置**：从「应用」目录「代币」分类的「代币转账」行进入（`/transfer?symbol=`），也支持直接深链；目录条目 `requires: null`——普通转账只需要钱包，不依赖任何协议合约，所以任何地址簿状态下都可用。**必须连接钱包**；未连接显示「连接钱包后转账。」+ 连接按钮，网络不对显示一句「切换到这个应用使用的网络后再转账。」+ 回首页。页面标题「代币转账」。

**代币集合（只来自链上与环境包，不维护硬编码清单）**
- **原生币**（环境包符号，本地 `ETH`）；
- **社区代币**：与兑换页同一个 `Launch.tokens` 分页（每页 20 + 「加载更多」）与 `Launch.tokenAddressBySymbol` 精确查找；
- **包装原生币**：地址簿 `weth` 的 `symbol()/decimals()`；
- **LP 代币**：地址簿 `pair` 的 `symbol()/decimals()`（本地 `UNI-V2`）；
- **自定义 ERC20**：在代币抽屉底部输入 `0x` + 40 位地址 → 「添加代币」→ 先校验 bytecode，再读 `symbol()/decimals()`；合约不存在 / 读不到 → 人话错误（「这个地址上没有合约，不能作为代币。」/「读不到这个代币的名称或精度，暂时不能转账。」）且不产生代币条目。
选择器分组固定为 原生币 → 社区代币 → 包装原生币 → 流动性凭证 → 自定义代币；搜索按 `symbol()` 子串过滤 + 精确 symbol 查询。**精度只在 `decimals ≠ 18` 时显示**（「精度 {n} 位」）；没有社区代币时该分组显示「还没有发现社区代币。」，页面降级为原生币 + 自定义 ERC20，不白屏。

**区块顺序（一张卡片，owner 2026-11-14：先收款方，再代币数量）**
1. **收款方行** — 输入框左侧一个小下拉切换三种模式：「按地址」/「按身份 NFT ID」/「按身份 NFT 名字」。模式**显式决定**输入含义，不从文本猜。这个下拉+输入框是与「转让身份 NFT」抽屉**同一个共享控件**（`shared/ui/identity-input-mode` + `shared/lib/identity-input`）：两页的标签、占位符、键盘类型、按模式校验与错误文案完全一致，切模式会清空上一模式的解析结果与确认勾选。**按身份 NFT ID 与按名字的输入各存一份**：切到名字模式不会把 ID 模式下输入的 `#2` 当成名字去查（D6，2026-11-14），切回来也不丢已经输入的另一份文本；地址模式的输入同样独立保留。
   - 按地址：`0x` + 40 位、校验非零、非自己；错误文案分别是「收款地址格式不对，需要 0x 开头的 40 位地址。」/「收款地址不能是零地址。」/「不能转给自己。」。
   - 按身份 NFT ID：只收纯数字编号（可带 `#`，如 `#12`）；名字文本直接给人话错误「请输入身份 NFT 编号，例如 #12。」，不发起解析；解析复用「转让身份 NFT」的 `ownerOf(id)`。
   - 按身份 NFT 名字：一律走合约 `memberId(name)`，**纯数字名字不会被当成 ID**（防止有人注册了 `123456` 的名字而 ID 不是 `123456`）；解析后再读 `memberName(id)` 展示链上规范名。
   - 两种身份模式解析成功后显示「身份 NFT #{id} {name}」+「收款人 0x…」（收款地址可点击复制，§4.7），并且必须勾选「我确认 #{id} 及上面的收款地址都正确」才能提交（名称可能混淆，ID + 地址是唯一依据）；该确认块与转让抽屉共用同一个展示组件。**ID 模式下 `memberName` 还没返回时，确认块不出现**（行内显示「正在读取身份名字…」），既不能勾选也不能提交——慢 RPC 下不允许在看不到规范名时确认（D7，2026-11-14）。
2. **金额行 + 余额小字（owner 2026-11-16 布局）** — 金额输入独占一行（大字号，`inputMode=decimal`），**右侧是当前代币下拉**（显示 symbol，胶囊按钮），点开是代币选择器（含自定义 ERC20）；**余额移到金额下方**，写成一行小号 muted 文字「余额 {金额} {symbol}」（例「余额 10,000 ETH」），不再占卡片第一行的醒目位；精度只在 ≠18 时跟在这行后面写「精度 {n} 位」。下方右侧是「全部」；原生币「全部」= 余额 − 预留网络手续费（`0.001`，写「约」），**可花余额为 0 时「全部」禁用**（不产生注定非法的 `0`，D5，2026-11-14）；超过余额时行内写「{symbol} 不够，还差 {x}」并禁用主按钮；`0` 写「金额必须大于 0。」、负数/非数字写「请输入有效的金额。」；小数位超过精度时**按精度向下截断**并提示「已按精度截断到 {n} 位小数。」（不四舍五入）。**余额读不到时主按钮禁用**，按钮下方写「余额暂时读不到，稍后重试。」并提供「重新读取余额」（D3，2026-11-14）——余额未知不能假装可以提交。
3. **智能资产保护开关 + 收款方保护（owner 2026-11-16，同日收口）** — 收款方块内先出现共享开关「智能资产保护」（`shared/ui/asset-protection-switch`，默认**开启**、持久化、与转让抽屉/批量转账共用同一偏好，滑块与流动性智能模式统一为 18px 行程、左右各留 2px）。**开启**时收款方是地址簿已知合约（router / stake / vote / submit / mint / launch / groupChat / lpExecutor / airdropDistributor / pair / weth / multicall3 / memberNFT 等）→ **拦截**：显示「智能资产保护已拦截：这是「{合约名}」合约地址」+「转进合约的资产很可能取不回来。要强制转账，请先关闭「智能资产保护」。」，主按钮禁用，页内不出现勾选（唯一出口是关闭开关）。**关闭**只跳过「收款方是不是地址簿已知合约」这一项检测：不拦截、不要求勾选、不再出现「这是「{合约名}」合约地址」，同一地址按任意合约规则只提示「这个地址是一个合约」（有 bytecode 时；bytecode 还没读到时先不提示）。合约名用 `/about` 同一套标签，一个合约不出现两个叫法。收款方是**任意有 bytecode 但不是地址簿条目**的地址时，无论开关开启或关闭都只显示「这个地址是一个合约」+「转进合约的资产可能取不回来，请确认你清楚它的用途。」（警告不阻断，用户可能确实要转）。**关闭只影响已知合约检测**：地址格式/零地址/自己/金额/余额等基础校验、身份 NFT 确认门禁一条都不少。
4. **主操作位** — 唯一实心按钮「确认转账」（钱包确认时「转账中…」），有界等待走 §4.2 的 `tx-watch` 纯提示（90 秒上限，无操作按钮）。**在途交易持久化（D1，2026-11-14）**：钱包返回哈希的瞬间就把 `{hash, token, amount, recipient, confirmed:false}` 落盘；刷新后首帧恢复 pending 卡片并继续 watch 同一个哈希，**同一笔在途/已成交时主按钮禁用**（下方「这笔转账还在确认中，确认后可以再转下一笔。」），不允许再发一笔。卡住提示出现后主按钮同样禁用并写「上面这笔还没有结果，请稍后在钱包或区块浏览器里查看。」；交易落定后自动更新，不提供重发。
5. **回执** — 成功后整页替换为回执（移动端底部 sheet、桌面端页面内卡片）：`已转出 {金额} {symbol}`、收款人（按身份 NFT 时附「身份 NFT #{id} {name}」；收款地址用**短格式**展示，完整地址在 `title` / `aria-label` 里，点击复制完整地址，§4.7）、交易哈希（复制 + 浏览器链接，哈希不套用地址短格式）。**只有一个按钮「好的」**（§4.3，owner 2026-11-16）；点击后关闭回执、留在原页并收成成功条「转账完成 / 已转出 {金额} {symbol}」，同时刷新余额。回执数字来自这笔交易实际携带的 wei 金额，不是估算。**成功条带交易哈希**（等宽显示、可复制、有浏览器链接时给「在区块浏览器里查看」）。**刷新后恢复成功条**（金额 + 哈希），但**回执 sheet 不重复弹出**——回执是一次性页面状态，与铸造/兑换同口径（D4，2026-11-14）。

**执行阶梯**：ERC20 直接调用 `transfer(to, amount)`，**没有授权阶段，界面不出现「授权」**；原生币是普通转账。同一时刻只允许一笔写操作在途。

**状态** — 未连接 / 网络不对 / 加载（余额骨架，选择器与输入框可先操作）/ 可提交 / 余额不足 / 金额非法 / 收款地址非法或零地址或自己 / 身份 NFT 编号非法（ID 模式输入名字）、读取中、不存在、属于自己、读取失败（可重试）/ 智能资产保护开启且命中已知合约（拦截）/ 开关关闭（不再检测已知合约，命中合约地址只给通用警告）/ 任意合约警告 / 钱包确认中 / 上链确认中 / 卡住提示（慢、丢失、被替换、nonce 缺口；纯提示无按钮）/ 成功回执 / 发送失败（人话结论 + 下一步）。错误文案不出现 gas、allowance、nonce、revert、selector 或原始 hex。

**主 CTA 与次要入口**：唯一主操作位「确认转账」；页面底部不再有「回首页」文字链（交给底部标签栏与页头返回）。不做订单簿、地址簿管理、批量转账或定时转账（批量转账是独立页面）。

- 布局：卡片第一块是收款方，第二块是金额行；金额输入右侧是当前代币下拉（同一行、输入框右边），余额在金额下方、小号 muted「余额 {金额} {symbol}」；18 位精度不写精度。
- 原生币转账 0.1 ETH：余额行「余额 10,000 ETH」→ 回执「已转出 0.1 ETH」。
- ERC20 非整数转账 1.5 TestLOVE20：余额行「余额 99,799,100 TestLOVE20」→ 回执关闭后余额 99,799,098.5。

### 3.11 代币授权

**用户一句话目标**：看清这个代币被哪些合约允许扣款、各自能扣多少，并随时把不用的授权撤掉。
**进入条件与前置**：从「应用」目录「代币」分类的「代币授权」行进入（`/approvals?symbol=`），也支持直接深链；目录条目 `requires: null`——ERC20 `allowance`/`approve` 对任何代币都可用，spender 行由本环境地址簿决定，所以任何地址簿状态下都可用。**必须连接钱包**；未连接显示「连接钱包后查看授权。」+ 连接按钮，网络不对显示「切换到这个应用使用的网络后再查看授权。」+ 回首页。页面标题「代币授权」。

**代币集合**：与代币转账同一套（社区代币分页 + 精确搜索 / 包装原生币 / LP 代币 / 自定义 ERC20），但**不含原生币**（原生币没有授权概念）。**默认代币在社区代币目录首次加载结束之后才决定**：取第一个社区代币；目录已 settled 但为空或读取失败时才回退到包装原生币 → LP（否则首次进入/刷新会先落到余额 0 的包装原生币并一直停在那里）。自定义 ERC20 校验 bytecode 并读 `symbol()/decimals()`；**代币按地址去重**：添加的地址若已在社区/包装原生币/LP 里，直接选中那个内置项，选择器不再出现第二个同名项，并在添加框下写「{symbol} 已经在「{分组}」里，不用重复添加。」。选中后显示 `{symbol} 余额 {格式化金额}`；精度只在 `decimals ≠ 18` 时在余额行右侧写「精度 {decimals} 位」，18 位不写。

**区块顺序**（owner 2026-11-14 整改：除了页首的代币上下文行，下面四块严格按 ①→④ 排列）
0. **代币行（页面上下文）** — 代币选择器 + 余额 + 精度。不选代币就看不了额度，所以它永远在四块之上。
1. **默认使用长期授权** — 页内第一块：一个开关（checkbox）。勾选后**本页把「长期授权」按钮画成更醒目的描边主样式，并且其它页面（兑换 / 铸造 / 流动性 / 批量转账）的授权步骤改为写 `maxUint256`、按钮文案变成 `长期授权 {symbol}`**（不再是行内徽标、也不出现「推荐」二字）；布尔值持久化在 `love20:tokenApprovalUseUnlimitedByDefault`（`1`/`0`，沿用旧库语义），只记在这台设备上，不随钱包/社区变化，开关改动后其它页面下次打开即生效。
2. **授权说明** — 一段说明段落 + 三条人话要点：授权是什么、额度可随时撤销、长期授权几乎无限只给信任的合约开；界面不出现 allowance / approve / 函数名。
3. **自定义地址** — 输入 `0x` + 40 位 spender：非法地址即时写「这是一个无效的地址，需要 0x 开头的 40 位地址。」、零地址写「授权地址不能是零地址。」、自己钱包写「这是你自己的钱包地址，授权给自己没有意义。」；合法地址立即查额度，无额度写「这个地址没有授权额度。」，有额度显示金额与「撤销」「长期授权」；已是长期授权时授权按钮转只读的「已长期授权」（禁用，与 §4.1 全局文案一致）。地址本身点击即复制（§4.7 共享地址组件）。
4. **常用合约列表** — spender 固定取地址簿：兑换路由（`router`）/ 质押（`stake`）/ 投票（`vote`）/ 提交行动（`submit`）/ 铸造（`mint`）/ 发射（`launch`）/ 一键加池（`hub`）/ 扩展 LP（`lpExecutor`）/ 批量转账（`batchTransfer`）/ 链群聊天（`groupChat`）；**列表全部展开、不折叠**：每行 = 中文名 + 一句话用途 + 当前额度 + 缩略合约地址（完整地址在 `title`，点击即复制并给「已复制」反馈；统一走 §4.7 共享地址组件，不保留页面内自造的复制实现）+ 「撤销」「长期授权」。额度三态固定：`未授权` / `长期授权`（`≥ 2^255`，按钮写入 `maxUint256`）/ `具体额度`（`{formatTokenAmount} {symbol}`，小数位按数量级自适应（§4.5.1）、只截断不四舍五入；**极小非零额度按有效位显示**（1 wei 就是 `0.000000000000000001 {symbol}`，不再写 `< 0.000001`），绝不显示成 0）。极长额度（如 `2^255 − 1`）在行内单行截断显示（省略号），完整文本放在 `title`，不许撑破一行。「撤销」写入 `0`；已长期授权的行授权按钮保持禁用但文案改成「已长期授权」（owner 2026-11-14：禁用的「长期授权」会被读成"还没完成"）。

**执行阶梯**：每行只有两种写值——长期授权 = `approve(spender, maxUint256)`、撤销 = `approve(spender, 0)`；点击后先出现确认 sheet（写明当前额度 → 确认后额度、这个地址、后果与「确认长期授权」/「确认撤销」/「取消」），确认后走 `tx-watch` 90 秒有界等待（卡住时纯提示，无操作按钮）。成功后列表原地刷新，页面顶部出现可关闭的成功条「已撤销「{合约名}」的授权。」/「已把「{合约名}」设为长期授权，可随时撤销。」；关闭后留在 `/approvals`，列表仍是链上真值。同一时刻只允许一笔写操作在途。

**状态** — 未连接 / 网络不对 / 代币目录读取中（「正在读取代币列表…」，不落「还没有可以查看的代币」）/ **网络读不到**（「暂时读不到网络数据」+ 正文「…这不是没有代币，请检查网络后重新读取。」+「重新读取」，余额行「余额暂时读不到」；网络恢复后点「重新读取」直接自愈，不需要刷新页面；**不得**把网络故障写成「还没有可以查看的代币」或「先在代币选择里添加一个 ERC20 代币地址」）/ 额度读取中（行内「读取授权额度中…」）/ 读取失败（「授权额度暂时读不到」+「重新读取」）/ 未授权 / 长期授权 / 具体额度 / 自定义地址校验失败 / 钱包确认中 / 上链确认中 / 卡住提示（纯提示无按钮） / 成功条 / **发送失败（错误在确认弹层内可见**：失败结论 +「这次没有产生交易。请重新填写后再发起。」；弹层不收起、按钮恢复可点、额度不变，关闭弹层后页面底部错误条仍在）。错误文案不出现 allowance、approve、gas、nonce、revert、selector 或原始 hex。

**主 CTA 与次要入口**：这是列表管理页，没有底部主 CTA；唯一实心按钮是确认 sheet 里的「确认长期授权」，撤销用红描边「确认撤销」；次入口只有「回首页」。

**验收**
- `/apps` 的「代币」分类出现「代币授权」行；点进去是 `/approvals?symbol=`，返回后 `?symbol=` 仍在；地址簿为空时该行仍然可点（`requires: null`）。
- 首次进入/刷新 `/approvals` 不手动选代币，默认选中社区代币 TestLOVE20（不是余额 0 的包装原生币）。
- 钱包里取消签名：确认弹层内立刻出现「你在钱包里点了取消，这次授权没有改动。」，弹层不消失、按钮可重试；关闭弹层后页面底部错误条仍在。
- RPC 不可用：页面写「暂时读不到网络数据」+「重新读取」，不出现「还没有可以查看的代币」；网络恢复后点「重新读取」直接恢复，不用刷新页面。

### 3.12 批量转账

**用户一句话目标**：把一种资产一次转给多个收款方，事前逐行核对地址与金额，并清楚「一笔失败整批不到账」。
**进入条件与前置**：从「应用」目录「代币」分类的「批量转账」行进入（`/batch-transfer?symbol=`），也支持直接深链；目录条目 `requires: batchTransfer`——本构建地址簿没有批量转账合约时该行禁用并写原因（「这个环境还没有部署批量转账合约。」），页面本身同态（不显示假表单）。**必须连接钱包**；未连接「连接钱包后批量转账。」+ 连接按钮，网络不对「网络不对。」+「切换到这个应用使用的网络后再批量转账。」+ 回首页。**首屏即判网络**（owner 2026-11-14 QA D11）：已注入钱包但链不对时，不必先「连接钱包」，页面与头部（「网络不对，点此切换」）首屏就落网络不对态。页面标题「批量转账」。

**区块顺序**（owner 2026-11-14 09:30 整理，参考旧库 `batch-transfer.tsx`：资产/币种 → 收款清单 → 逐行错误就地 → 合计与余额对比 → 主按钮 → 预余额核对 → 高级选项折叠）
1. **资产行** — 原生币 / 代币 二选一（原生币默认）；代币模式出现代币选择器（与代币转账同一套社区代币分页 + 搜索 / 包装原生币 / LP），余额 `{symbol} 余额 {格式化金额}` + 「精度 {decimals} 位」（仅 `decimals ≠ 18` 时显示，18 位不写），桌面/移动同一行内排布，不再单独占一块。金额规则与 §4/全局一致：极小非零金额按有效位显示（如 `0.0000001`、1 wei → `0.000000000000000001`），绝不显示成 0；`< 最小可见单位` 只在显式压位数时兜底（D3）；代币模式还没解析出代币时余额行写「代币余额暂时读不到，换个代币或重试读取。」，**不回落**成「ETH 余额 —」（D9）。余额读不到属于可恢复态：旁边给「重新读取」。
2. **收款方文本域** — 每行「地址 金额」，用空白或逗号分隔，支持直接粘贴多行；占位符示范两行。逐行错误在文本域下方按行号就地列出：`第 N 行：缺少金额。` / `第 N 行：地址格式不对，需要 0x 开头的 40 位地址。` / `第 N 行：金额格式不对。` / `第 N 行：金额必须大于 0。` / `第 N 行：收款地址不能是零地址。` / `第 N 行：不能转给自己。` / `第 N 行：不能转给批量转账合约本身。`。**重复地址不再合并**：后出现的行写 `第 N 行：与第 M 行重复，这一行先不计入，请删掉其中一行。`，该行不进入收款方列表、不计入合计，主按钮禁用，由用户删行后恢复；小数按 decimals 向下截断并写「金额已按精度截断到 {decimals} 位小数。」。
3. **合计与余额对比** — `{N} 行，{M} 个收款方` + `合计 {formatTokenAmount} {symbol}`（极小非零金额按有效位显示、不写 0；`< 最小可见单位` 只在显式压位数时兜底，D3）+ 固定一行「整批一起执行：有一笔失败，全部都不会到账。」；合计超过可花余额时写 `{symbol} 不够，还差 {短差}`（原生币另写「需要预留一点 {symbol} 支付网络手续费。」），主按钮禁用。**发送方余额读不到且合计 > 0 时**写「余额暂时读不到，还不能判断够不够转，请先重试读取。」+「重新读取」，**主按钮禁用**（D8：不把「读不到」当成「够转」）。
4. **智能资产保护 + 合约收款方提示（owner 2026-11-16，同日合并）** — 收款清算区里带一个共享开关「智能资产保护」（与 `/transfer`、转让抽屉同一个偏好，默认**开启**）。**开启**时若有收款方命中地址簿已知合约 → **只渲染一个合并块**（`batch-transfer-known-contract`，`role=alert`）：标题点明行数「有 {N} 行是协议合约」/「有 {N} 行是协议合约、{M} 行是其它合约地址，智能资产保护已拦截」，块内按行号逐行列出——已知合约行写「第 {N} 行：这是「{合约名}」合约地址」，同一批里其它有 bytecode 的合约行写「第 {N} 行：这是一个合约地址」，块尾只写一条禁用原因「转进合约的资产很可能取不回来。要强制转账，请先关闭「智能资产保护」。」，主按钮禁用。此时**不再另起**「有收款方是合约地址」通用警告块（两块合并成一块）。**关闭**只跳过已知合约检测：合并块完全不出现（不点名、不拦截），有 bytecode 的收款方（含原本的已知合约）统一落到通用警告「有收款方是合约地址」+ 说明，主按钮恢复可提交；逐行的地址/金额/重复/余额校验一条不少。位置在主按钮之前，因为它影响「要不要提交」的判断。
5. **授权行（仅代币）** — 三态且互斥：读到了才写 `已允许批量转账合约使用 {当前额度} / 本次需要 {合计} {symbol}`；额度不足时主按钮是第一阶段「授权 {symbol}」，并写「这笔批量转账需要先授权一次，授权确认后再提交批量转账。」；额度足够时写「额度已足够，不需要再次授权。」，主按钮直接是「批量转账」。**额度读不到**时只写单一句「额度暂时读不到，无法判断是否需要授权，请重试读取。」+「重新读取」并禁用主按钮，**不得**同屏出现「额度已足够」（D2），也不得把额度写 0。
6. **主按钮** — 在流内的唯一主操作位（不吸底，§4）；错误卡与等待卡紧跟其后，同一屏内可看到。
7. **预余额核对表（主按钮之后，条件出现）** — 逐行 = 收款方（缩写 + 合约徽标）+ 金额 + 当前余额；当前余额来自批量转账合约的 `nativeBalances(address[])` / `erc20Balances(token, address[])`，一次读取整批；读不到显示「—」（不当 0），表下写「收款方余额暂时读不到，提交后仍会逐行核对到账差额。」（D6）；行金额同样遵守极小非零金额的有效位规则（不写 0）。**标题行右侧常驻一个「刷新」按钮**（owner 2026-11-17）：随时重读整批余额，刷新期间**保留屏幕上已有的数字**（不闪回「—」、不整表骨架），按钮显示读取中并 `aria-busy`、禁止连点；`busy`（交易进行中 / 回执核对中）时按钮禁用。**刷新后的读数就是提交时写进回执的「到账前」基线**：因此刷新进行中**禁止提交**（主按钮禁用，避免用旧基线对比）；读失败态的恢复入口就是这个常驻刷新按钮——表下只留说明文字，**不再并列第二个「重新读取」按钮**（D6）。
8. **高级选项（默认折叠）** — 「每行执行预算」默认 30000（原生）/ 60000（代币），范围 21000–1000000/收款方，且 `行数 × 预算 ≤ 30000000`；越界写「每行执行预算至少 21,000。」/「每行执行预算最多 1,000,000。」/「这批交易的计算上限超过一个区块的容量，请减少收款方或调低每行执行预算。」并禁用主按钮。
9. **回执（交易已上链，只有一个「好的」按钮，§4.3）** — 整页/抽屉回执：`合计转出 {formatTokenAmount} {symbol}`（极小非零按有效位显示、不写 0）+ `{N} 个收款方` + 逐行「收款方 / 金额 / 到账前 → 到账后 / 差额」；差额只允许四种形态：`+X`（与应到账额逐 wei 相等；非零差额按有效位显示（1 wei 也写 `+0.000000000000000001`），不写 `+0`）、`未变化`、`{X}（异常）` 高亮、读不到 `—`。**结论按核对结果三态**（D1）：全部逐行核对通过才写「整批一起执行：上表每一行都已到账。」；有 N 行余额读取失败（提交前或到账后）写「到账核对不完整：有 N 行余额读取失败，未能核对，请到区块浏览器确认交易结果。」并把图标换成警告色；核对到但差额不符写「到账核对发现异常：有 N 行的差额与应到账额对不上，请到区块浏览器确认。」。代币模式下链上仍有残留授权（先按合计授权、再改小清单提交）时追加「还留着 {X} {symbol} 的授权，可到「代币授权」页撤销。」（D7）。关闭回执留在原页，上方出现成功条「已转出 {合计} {symbol}」。
10. **失败** — 发送前先在链上预演整批：预演失败不发交易、不扣手续费，错误卡按行定位：`第 N 行收款方拒收了这笔转账（对方可能是不接收 {symbol} 的合约）。整批没有转出，你的资产没有变化。` 或 `第 N 行的执行预算不够，这一批没有转出。可以在高级选项里调高每行执行预算。`；余额/额度竞态写「{symbol} 不够，整批没有转出。」/「批量转账额度还不够 {symbol}，请先完成授权再提交。」；交易上链但回滚写「交易上链了，但没有成功。整批没有到账，你的资产没有变化。」。钱包拒绝写「你在钱包里点了取消，这一批没有转出。」。任何错误都保留输入，可直接改行重试。

**状态**：未配置 / 未连接 / 网络不对（已注入钱包在其它链时首屏即此态，D11）/ 余额与额度读取中（骨架，不渲染 0）/ 余额或额度读不到（单一「读不到」结论 + 「重新读取」，余额未知时禁止提交，D6/D8）/ 空输入（「还没有可用的收款方。按上面的格式每行填一个。」）/ 逐行错误（含千分位金额按数值解析、精度截断为 0 的专用文案，D4/D5）/ 重复地址提示（阻塞提交，删行后解除）/ 超余额 / 预算越界 / 需授权 / 授权确认中 / 授权已足够 / 批量确认中 / 回执（核对完整 / 不完整 / 异常三态）/ 错误卡（卡住时纯提示，无操作按钮）。**整批原子是硬约束**：页面任何位置都不出现「部分成功」「分批到账」「失败的几行稍后补发」。

**主 CTA 与次要入口**：整页一个主操作位——代币模式额度不足时是全局文案 `授权 {symbol}`（默认使用长期授权开启时是 `长期授权 {symbol}`，授权额 `maxUint256`），额度足够或原生币模式是「批量转账」/「确认批量转账」；额度已是长期授权时额度行写「已长期授权…不需要再次授权」。页面底部不再有「回首页」文字链。回执只有「好的」一个按钮（§4.3）。

### 3.13 流动性池

**用户一句话目标**：把两种代币放进池子赚手续费，或者输入要拿回的流动性凭证数量把对应的两种代币撤出来；输入之后只看「预计获得多少流动性凭证 / 预计收到约多少」，过程量要展开才看。

- 版面：摘要卡（`N 轮可铸造` + 批量「铸造这 N 轮」）→ 轮次表（轮次 / 投票激励 / 加速激励 / 状态）→ 底部三态（加载更多 / 读取中 / 已经到底）。
- 行状态：可铸 → 「铸造」按钮；已铸 → 「已铸造」；该轮没投票 → 「没有投票」（不可铸）。批量只收**已扫描到且确认可铸**的轮次（合约按传入数组逐轮处理，任何一轮失败整笔回滚）。
- 为什么不做「一次铸完」：`(token, 轮次, 身份)` 三维键没有反向索引（[CI-001](../contract-issues/001-no-member-round-index.md)），前端只能按轮扫描；页面不承诺未扫描到的轮次。
- 铸给谁：固定铸到当前钱包（合约要求 `msg.sender` 持有该身份 NFT），界面不出现「收款人 / 受益人」。

**`/gov/proposal-rewards` 提案激励**（core `Mint` 的提案侧）：
- 数据：`Mint.proposalReward(轮次)`（本轮池子）、`Vote.totalVoteAmount(轮次)`、`Mint.PROPOSAL_REWARD_MIN_VOTE_RATIO`（门槛比例）→ `门槛 = ceil(总票数 × 比例)`；逐提案 `Mint.proposalRewardSettlement`（金额 + 状态 0 未结算 / 1 已铸造 / 2 已销毁）与 `Vote.voteAmountByProposalId`。
- 版面：轮次选择（上一轮 / 下一轮，默认最近一个已结束轮次）→ 汇总卡（提案激励池 / 本轮总票数 / 本轮门槛）→ 提案表（提案、票数 / 门槛、激励金额、状态）+ 每行说明。
- **只读 + 一个销毁动作**：票数过门槛的提案，激励**只能由提案目标合约铸造**（合约 `onlyProposalTarget`），本页只写「已过门槛，由提案目标合约铸造」、不给按钮；票数没到门槛的，任何人都能销毁（`burnProposalReward`），页面给「销毁这部分」+ 一句不可撤销说明；票数为 0 的提案调用是空操作，所以不给按钮。
- 本轮没人投票时池子为 0，显示「这一轮没有预留提案激励（本轮没有人投票）」。

**本轮明确不做**（如实记录，避免被当成已实现）：回调提案的推举与投票（行动域）、验证页、行动/链群页、提案正文的链上富文本、提案目标的白名单校验（合约只要求非零地址；回调模式才要求是合约）。

**证据**：三线校验 [three-line/gov-core.md](three-line/gov-core.md)；前端线 `e2e/gov-core-numbers.spec.ts`；合约线 `scripts/verify/gov-core-contract.mjs`；截图 `gov-core-*`（390×844 / 1280×800 × 浅色/深色）。

## §4 横切交互规范

### 4.1 授权 → 执行：按钮阶梯
- 只在需要时出现第一阶段：`allowance(wallet, memberNFT) ≥ 本次应付` 时直接显示单按钮「铸造」，回访用户永远只看到一次确认。兑换页同理：`allowance(wallet, router) ≥ amountIn` 时直接显示「兑换」。
- 铸造的授权额 = 本次报价 × 1.01（按需 + 1% 缓冲）；**兑换的授权额 = 本次输入金额，精确到 wei，不加缓冲**（§3.5）；流动性加池/撤出、批量转账同理按各自需要的精确额。文案必须写「只是允许合约最多扣这么多，不会立刻扣钱」。
- **默认使用长期授权（owner 2026-11-16）**：`/approvals` 的开关是设备级偏好（`love20:tokenApprovalUseUnlimitedByDefault`，`1` 开 / `0` 关）。**开启后，所有页面的授权步骤一律改写成 `approve(spender, maxUint256)`**（兑换 / 铸造 / 加池 / 撤出 / 批量转账），按钮文案变成 `长期授权 {symbol}`，按钮下方提示改成「这次会授权长期额度（几乎无限）…」；关闭时回到上面的精确额与 `授权 {symbol}`。偏好只记在这台设备上，开关改动后其它页面下次打开（或同标签页已挂载时立即）生效；金额决策只有一个纯函数 `shared/lib/approve-amount.ts#decideApproveAmount(useUnlimited, exact)`。
- **授权文案全局统一（owner 2026-11-14）**：任何页面给某个代币授权的按钮都写 `授权 {symbol}`（`copy-pages.ts` 的 `copy.approve`），只有代币不同；偏好开启时改写 `长期授权 {symbol}`；进行中 `授权中…` → `确认中…`。不再出现「1. 授权」「1 授权」「1 允许使用 {symbol}」等变体。
- **授权按钮永远在流内、永远显示、且与主按钮成一组**（owner 2026-11-14；布局 2026-11-16）：兑换页的 `授权 {symbol}` 与 `兑换` **并排成同一组按钮，放在价格/信息卡下方**（owner：「授权和兑换按钮应放到一起，价格卡片应放到两个按钮上面」）；铸造 / 流动性 / 批量转账同理，先决条件按钮在前、主按钮在后，同一组紧邻。移动端不再有 fixed 吸底按钮栏（`StickyAction` 已删除，改为流内的 `ActionStack`），`--sticky-action-height` 一并删除。
- **已长期授权时按钮仍显示**：授权额度 ≥ 2^255 时按钮就地显示 `已长期授权`（禁用、无需操作）；额度已够但不是长期授权时显示 `已授权`。额度读不到时显示 `读取授权额度中…`。
- 阶段 1 成功后**不跳转、不刷新、不弹 toast**：授权按钮原地变 `已授权`，主按钮解锁。
- **禁止**把授权缓冲写成「滑点」：参考实现的「滑点：0.1%」实为授权缓冲，不是价格滑点，属于错误标签。
- 用户拒签，或授权后价格上行使额度不够 → 按钮回到可点，文案「授权不够这次使用，需要再授权一次」，不跳页、不清空输入。

### 4.2 交易 pending 语法
- 三态，措辞固定：**等待你在钱包确认** → **已提交，等待上链** → **已上链 / 没有成功**。不把三者合并成一个「加载中」；授权阶段同样走这三态，按钮写「授权中…」。
- 任务对象 `{ id, kind, tokenAddress, memberId?, amount?, hash?, state, startedAt }` 存本地；**只有拿到 hash 后才写记录**；刷新时只恢复有 hash 的在途任务。没有 hash 就不产生任务、不落盘、不恢复；失败/取消后用户重新填表发起。
- 展示位置：按钮内文案 + 头部下方 36px 任务条；也**不做全屏 LoadingOverlay**，不锁页面（参考实现的全屏遮罩是漏斗漏点）。
- pending 中允许切页、切社区；任务条常驻，点击回到发起页。同一时刻只允许一个写操作在途，其余**写操作**按钮禁用并注明「有一个操作正在进行」；纯本地选择（如「使用此身份 NFT」）不受影响。
- 先落本地收据、再刷新数据，避免「数据已变但用户没看到收据」。
- **新操作用 `pending` nonce（owner 2026-11-16，R5）**：每笔写操作（**含刷新后的第一笔**）在提交前用页面正在监听的那条链读一次 **`pending`** nonce 并作为显式 nonce 提交——排在钱包已有排队交易**之后**，不会复用一笔仍在途的 nonce（`latest=3`、钱包里已有 nonce 3 在排队时，新操作签 4）。读取失败则把 nonce 交还钱包。**不再替换已知交易**；显式 nonce 只用于新操作。nonce 缺口判定同样读 **`pending`** 计数（排队在同钱包另一笔交易之后的交易不算缺口），同一缺口持续 10 秒才出纯提示，避免一次滞后的链读把页面冻在提示上。
- **在途与账户归属约定（owner 2026-11-24）** —— 所有写操作共用同一套语义：
  - **不保留失败请求**：调用钱包后失败/取消即结束；不落请求、不提供「重试」。发送前不落 attempt；只有拿到 hash 后才写本地在途记录（stake/liquidity/batch 由发送前落盘改为 hash 后落盘）。
  - **账户归属**：在途记录带 `{chainId, account}`；恢复/继续 watch 前与当前钱包/网络比对，不一致就**清记录 + 中性提示**「钱包或网络已经切换，刚才那笔交易没有再提交。请用当前钱包重新发起。」，绝不代签。
  - **离页/刷新**：批量转账与流动性复用代币转账的缓存方案（`{chainId, wallet}` 作用域、在途/已成交状态）；刷新后只恢复有 hash 的在途卡并继续 watch 原哈希，在途期间禁止二次提交。
- **卡住态是纯提示卡（owner 2026-11-24，Q1123-4）**：慢/掉队/被替换/nonce 缺口统一显示标题 + 正文「请在钱包或区块浏览器里查看」；不提供站内重发、手动刷新、关闭等按钮；交易落定后由 watcher 自动更新为回执/失败。
- **失败/取消不再有重试（owner 2026-11-23，Q1123-3）**：签名失败或用户取消后，页面只显示失败结果；用户重新填表发起新操作。
- **回执关闭必须释放全部发送守卫（owner 2026-11-14）**：点「好的」后除收起成功条外，还要清掉 hook 里的 receipt / pending / 授权态与有 hash 的本地在途记录，否则下一次点「兑换」会被「有一笔回执还在」的守卫静默吞掉。

### 4.3 成功收据（取代 toast + 2 秒跳走）
- 收据是**页面内状态**：不自动跳转、不 2 秒消失。标题 + 你得到什么 + 哈希。
- 必备字段：结果（铸造成功 / 兑换完成 / 已铸造）· **你得到什么**（`#memberId` + 链上 `memberName` / 实际到账数量 / 已铸造金额）· 实际支付（若有）· 交易哈希（复制 + 浏览器链接）。
- **回执只有一个按钮「好的」（owner 2026-11-16）**：点击后关闭回执。除铸造外留在当前页，页面顶部收成成功条（成功条是纯信息，不再带第二个按钮）。回执里不再出现「回首页」「再兑换一次」「再转一笔」「去我的 NFT」等第二个按钮；导航交给页头返回与底部标签栏。**铸造回执例外（owner 2026-11-16）**：点「好的」后自动进入 `/my-nft`，新身份在列表里高亮（§3.2）；不点按钮则留在 `/mint`。跳转与其余整页变化一样走软过渡（§4.8）。
- **治理域回执走自下而上面板（owner 2026-11-19）**：治理域五个页面（`/gov`、`/stake/liquidity`、`/stake/staketoken`、`/stake/unstake`、`/stake/liquid` 共用同一个 `GovTxFeedback`）的回执不再在页面顶部内联一张卡，改成成功后从底部弹出 `Sheet`（`<md` 底部 sheet / `≥md` 居中弹层，同一个 `Sheet` 实现）承载同一份内容（标题 + 你得到什么 + 哈希 + 唯一按钮「好的」）；关闭（「好的」/ 关闭按钮 / Esc / 点遮罩）即清回执，页面留在原页、表单可再次提交。面板式回执同样遵守本节其余条款：不自动跳转、不自动消失、一次性状态、数字取自本笔交易事件。
- **所有关闭类按钮统一「好的」（owner 2026-11-16）**：回执唯一按钮、授权成功条关闭、钱包缺失兜底抽屉关闭、RPC 拦截提示关闭都用「好的」，四处不再出现旧文案；语义不同的按钮保持原名（确认弹层的「取消」、钱包/网络错误弹层的「关闭」、banner 的「刷新页面」）。
- **离开页面再回来不重复显示（owner 2026-11-14）**：回执是**一次性页面状态**。已确认的交易不再写回本地记录（swap / mint / airdrop 在拿到回执时清除记录），再次进入页面只显示表单或 S6「已铸造」链上状态，不会从本地记录恢复成弹层。未确认的 pending 仍按 §4.2 恢复。
- 所有数字来自本笔交易回执：`MemberMinted.cost/name/memberId`、ERC20 `Transfer`、`AirdropClaimed.amount`；**不用前端估算值**。

### 4.4 错误文案映射（消费 `registry/errors.json`）
- 原则：**写结果与下一步，不写机制**。不出现 gas、allowance、nonce、revert、selector、`0x…` 堆栈、HTTP 状态码。
- 三层：`selector → 英文错误名（errors.json）→ 中文结论 + 下一步`；未收录的 selector 落到「交易被合约拒绝」+ 哈希 + 「重试」。

| 情形 | 文案（结论 + 下一步） |
|---|---|
| 用户取消（4001） | 「你在钱包里点了取消，没有扣款。」/ 重新填写后再发起 |
| 网络手续费不足 | 「BNB 不够付手续费。请先转一点 BNB 进来。」/ 复制地址 |
| 代币余额不足 | 「LOVE20 不够，还差 {x}。」/ 空投铸造、兑换 |
| 授权不足 | 「授权额度不够这次使用。」/ 再授权一次 |
| `NameAlreadyExists` | 「这个名字已经被用了。」/ 换一个名字 |
| `NameTooLong` / `NameInvalidCharacters` | 「名字太长 / 含有不可用的字符。」/ 修改名字 |
| 流动性不足 / 价格变动保护 | 「价格变化太大，这笔交易没有成交。」/ 重新报价 |
| 超时 / RPC 失败 | 「网络没有及时响应，交易状态未知。」/ 查看哈希；不自动重发 |

### 4.5 估算类信息标注
- 三档标记：**预计**（空投可铸造金额、铸造价格、兑换报价与最少到账）、**约**（手续费预留、价格影响、任何倒计时）、**精确**（余额、已铸造金额、已上链数量）。
- 每个预计值必须带半句「为什么会变」：空投「别人铸造后金额会变」；铸造「价格随已铸造数量变化」；兑换「价格随池子变化」。
- 基于 Phase 的倒计时只能用「区块差 × 观测出块时间」估算，写「约 X 分钟」，并说明阶段长度会被协议调整（`Phase` 以区块计量，不是时间戳）。M0 页面不显示轮次倒计时；此规则适用于后续页面。
- 提交前重读一次链上；报价超过 30 秒视为过期，需重新报价。

### 4.6 移动端钱包兜底阶梯
- 顺序：① 用系统浏览器打开（Universal Link / `window.open`）② 扫码（二维码内容 = **当前页面 URL**，不是 WalletConnect URI；M0 只有注入钱包）③ 复制链接 ④ 说明「在钱包 App 内置浏览器里粘贴此链接」。
- 触发：应用内浏览器 UA 命中 → **连接之前**显示顶部横幅；没有 `window.ethereum` → 连接按钮直接打开兜底抽屉，不转圈、不报错。
- 抽屉文案：「这个浏览器里没有钱包。用下面任意一种方式打开，就能连接。」+ 三个按钮 + 一行「已经装了钱包？在钱包 App 的浏览器里粘贴这个链接。」
- 抽屉底部按钮：「复制本页链接」+「好的」（关闭，owner 2026-11-16 与回执/成功条/RPC 提示统一）。
- 桌面放大二维码，移动优先 Universal Link 与复制；二维码本地生成，不调用第三方服务。没有兜底就不放「连接钱包」按钮——任何「点了没反应」都是漏斗漏点。

### 4.7 全局地址复制（owner 2026-11-14 09:30）

「所有出现的合约地址、钱包地址，都应该支持点击复制」：实现上只有**一个**共享组件 `src/shared/ui/copyable-address.tsx`（`CopyableAddress`），页面与弹层不得再各自实现复制按钮/复制状态。

- **形态（owner 2026-11-19 统一）**：地址文本本身是一个按钮；**所有合约地址与钱包地址一律用中间省略的短格式** `0x1234…abcd`（正文默认 4+4，列表行 6+4），空间够也不再用换行铺满 40 字符的长格式。完整地址始终在 `title` 与 `aria-label`（`复制地址：{中文名}`）里；组件仍保留「完整形态」能力，但产品界面不再使用。**交易哈希不套用本条**：`tx-watch` 卡继续用短哈希，回执里的哈希继续是「完整哈希 + 独立复制按钮」。
- **行为**：点击后用 `copyText()`（`navigator.clipboard`，失败回退隐藏 textarea + `execCommand`）复制**完整地址**；成功在地址右侧原地写「已复制」2 秒，失败写「复制失败，请手动选中地址」——不存在点了没反应的地址。
- **可访问性**：`aria-label` 为「复制地址：{中文名}」，复制成功后变「地址已复制：{中文名}」；反馈区 `aria-live="polite"`。地址按钮不做成实心主按钮（不参与 §4.1 的主操作位）。
- **覆盖范围**：关于页每个合约地址、代币授权（自定义 spender + 常用合约列表每行）、代币转账解析出的身份收款人、转让抽屉解析出的收款人、转账回执的收款人、钱包弹层的钱包地址、批量转账预检与回执的每行地址、身份列表「已转让给」里的地址（「我的」页的账户区已随 2026-11-19 改版移除，地址复制入口只剩钱包弹层这一处）。社区菜单与连接药丸不直接展示可复制地址（药丸的地址复制在钱包弹层，§1.4/§1.6）。
- **一致性**：同一地址在任何页面复制出的字符串都是**完整地址**；页面之间只有缩写位数差异，不存在两套「已复制」文案，也不存在第二种长格式展示。

### 4.8 整页变化的软过渡（owner 2026-11-16；2026-11-17 缩减覆盖）

owner 原话：「设置使用此身份 NFT 的时候，有一个过渡动画，要不然感觉很突兀，突然刷新了下，还要仔细看下才注意到发生了什么；类似的交互也都改下」。

2026-11-17（owner）：「使用此身份 NFT」不再走整页淡出淡入 —— 改成被点的卡片移动到列表最顶部（§4.8.1）。软过渡只保留给其余整页变化。

- **覆盖**：① 社区切换（社区菜单 / 最近访问 / symbol 搜索命中的同一条 `switchSymbol`）；② 主题切换；③ 铸造回执「好的」→ `/my-nft`。普通路由跳转不复用（保持轻量，不上全局 Router 动画）。「使用此身份 NFT」自 2026-11-17 起改由 §4.8.1 的卡片移动承担，**不再**触发整页淡出淡入。
- **唯一实现**：`src/shared/model/soft-transition.tsx`（`SoftTransitionProvider` + `useSoftTransition()`）与 `src/index.css` 的 `.l20-page-transition`；`<main data-transition="idle|leaving|entering">`。`run(change)` 的顺序是 **180 ms 淡出（leaving）→ 内容不可见时应用变化 → 200 ms 淡入（entering）→ idle**。纯 CSS `@keyframes`，不引入动画库。
- **交互细节**：淡出期间 `<main>` 为 `pointer-events: none`，连点不会排队第二次整页变化；变化完成后的置顶/「当前」pill 行为与之前一致。
- **可访问性**：`prefers-reduced-motion: reduce` 时 JS 直接应用变化（跳过 180/200 ms 延迟）且 CSS 关闭 `l20-page-leave` / `l20-page-enter` 动画——减动效用户看到的是瞬时切换，但不会看到半透明中间态。
- **测试**：`src/shared/model/soft-transition.test.tsx` 覆盖阶段顺序、连点忽略、减动效、无 Provider 时立即执行；e2e 在社区切换 / 主题切换 / 铸造回跳中断言 `main[data-transition]` 与「切换中…」并截对应过渡态。选择身份的断言见 §4.8.1。

### 4.8.1 卡片移动到顶部（owner 2026-11-17）

owner 原话：「点击使用此身份NFT的时候，改为卡片从当前位置移动到最顶部，这样会更加明显、清晰。」列表本来就按「当前身份置顶、其余 memberId 升序」排序（`src/domain/identity-order.ts`），所以这次交互要让人**看得见这张卡被搬到了首位**，而不是两帧之间悄悄换位置。

- **实现**：FLIP（First–Last–Invert–Play）+ Web Animations API，`src/shared/lib/flip.ts`：点击时量各卡片 `getBoundingClientRect()`（First）→ `identity.select()` 提交重排 → `useLayoutEffect`（首帧绘制前）量 Last 并 `element.animate([{ transform: translateY(delta) }, { transform: 'none' }])`。**不引入动画库**，动画 `fill: 'none'`，结束后浏览器自动丢弃效果，元素不留内联 transform。位移 < 2 px 的卡片跳过；两套断点 DOM 中未布局（0×0）的那套跳过，移动端与桌面永不混测。
- **参数**：300 ms、`cubic-bezier(0.22, 1, 0.36, 1)`（快起软落）；被点卡片临时抬高（`z-index`）以免越过其它卡时钻到下面，并叠一次 brand 系高亮淡出（卡片用 `boxShadow` 光晕、表格行用 `--color-brand-soft` 底色脉冲，颜色全走主题 token，深浅色一致）。
- **忙碌态与读取**：被点的行按钮显示「切换中…」+ `aria-busy` + disabled（优先于「当前身份 NFT」，防连点；可访问名在忙完后恢复为「当前身份 NFT」）。忙碌态持续到「移动动画结束 **且** `ownerOf()` 确认新身份」；确认期间列表继续用缓存枚举渲染（顺序已按新选中身份排好），不闪骨架屏。焦点不丢（同一 DOM 节点复用）。
- **桌面退化**：`≥md` 的表格行不做 transform（Chromium 支持、Safari/Firefox 历史上不可靠），退化为「即时置顶 + 620 ms 底色脉冲」，表格布局不动、可用性不变。
- **可访问性**：`prefers-reduced-motion: reduce` 时**不量不播**直接落位，也不闪高亮。
- **测试**：`src/shared/lib/flip.test.ts` 覆盖位移/时长/缓动/清理/减动效/无 `animate` 环境/高亮关键帧；e2e `home-my-nft.spec.ts` 断言被点 `li` 收到一次 move 动画（`translateY(+Δ) → 0`，300 ms，同一条缓动）、逐帧采样该卡 `top` 从旧位置单调移动到首项位置（首末间隔 ≥100 ms，排除瞬移）、结束时它是第一项，且 `<main data-transition>` 全程 `idle`（用 `expectNoPageFade()` 证明已不再走整页淡出）；桌面断言行上只有强调动画、没有任何 transform 动画。


### 4.9 轮次与阶段的展示格式（owner 2026-11-17）

**时钟只有一个**：全局按「阶段」（`Phase`）一格一格前进，一个阶段是若干区块、长度会被协议按出块速度调整。**轮次是一条流水线**：把相邻若干阶段串成「投票 →(加入)→(验证)→ 铸币」的完整业务周期。第 X 轮的各个环节落在阶段 X、X+1、X+2、X+3（环节数量按轮次类型不同）。

- **轮次只有四种类型**：治理轮 / LP 行动轮 / 链群行动轮 / 链群服务轮。**不引入「层」这个说法**，也不用「治理层 / 行动层」当集合名词。
- **任何轮次数字都必须带类型前缀**，写成三段式：`{类型} · 第 N 轮 · {环节}`，例：`链群行动 · 第 3 轮 · 验证阶段`。禁止裸写「第 3 轮」（同一时刻四类轮次在跑不同轮号，裸数字无意义）。
- **环节名固定四个**：投票阶段 / 加入阶段 / 验证阶段 / 铸币阶段；某类轮次没有的环节不出现（LP 行动无验证阶段、治理轮只有投票与铸币）。
- **阶段数字只在高级视图出现**；主界面用业务环节名 + 「约 X 分钟」，不展示阶段号，也不展示绝对时间（沿用 §4.7 的倒计时口径）。
- 用户可见处写「阶段」，不写「时间片」（旧译，仅在解释协议结构时用）。

## §6 M0 验收脚本大纲

**前置**：`vite preview --base=/<repo>/` 跑构建产物（不是 dev server）；Playwright + 注入型测试钱包（EIP-1193 stub + 本地私钥签名）；链 = 本地 anvil 31337，`make bootstrap` 起链并 seed：首币池注入 **200,000 LOVE20 + 100 WETH**（`SEED_LIQUIDITY_TOKEN_AMOUNT=2e23`、`SEED_LIQUIDITY_PARENT_TOKEN_AMOUNT=1e20`，见 ADR-0004）；dev 的地址与 ABI 只读 `anvil/export/deployments/anvil31337_dev.json` 与 `anvil/export/abis/*.json`（前端消费副本 `src/config/network/anvil31337_dev/network.json`）。fixture 的 anvil 0–9 号账户都在快照内（0–4 已铸造，5–9 有份额未铸造），所以主流程必须用**不在快照内**的新私钥（先从一个 anvil 账户转一点原生币（anvil：ETH）作 gas）。GitHub owner 与仓库名已定（`LOVE20BSC/interface-dev` / `interface-test` / `interface`，见 ADR-0002 §4），环境变体由 CI 按仓库名关键字选择（含 `dev` → dev，否则含 `test` → test，否则 prod；`vars.VITE_ENV` 可覆盖），发布命令为 `pnpm release-to <target>`（ADR-0002 §4）；**只有里程碑最终排期〔待定〕**。`--base` 由 CI 变量注入，脚本不得硬编码。

1. **打开 `/` → 未连接 → 连接**：未连接态 = 左侧社区标识 + 问候「你好」+「连接钱包」；底部 5 tab 可见；治理/行动占位页显示「即将上线」、一句说明与「回首页」，无空白、无半成品表单。点「连接钱包」→ 左侧标识隐藏、药丸变为两区，URL 补上 `?symbol=<首币>`。
2. **无身份 NFT → 铸造身份 NFT**：首页问候为「你好」，提醒流显示「你还没有身份 NFT」+「铸造身份 NFT」。点「铸造身份 NFT」→ `/mint`。「我的」页不再有身份 NFT 卡片（2026-11-14 移除，§3.7），不重复这个入口。
3. **进入铸造页（从我的 NFT 空态的「铸造身份 NFT」）** → 名称可输入；费用卡出现「预计 {cost} LOVE20」，下方「我的 LOVE20：0」被标成不足；余额旁有次级「去兑换代币」文字链；不出现整页 spinner。
4. **输入 7+ 字节且以 `Test` 开头的名字**（如 `Teste2e-member`）→ 检查行「可以用」；再输入一个不以 `Test` 开头的名字 → 规则行「名称必须以 Test 开头」仍在，检查行出现「✗ 还没加 Test 前缀」且不能提交；余额不足 → 资金分支卡出现。
5. **点分支卡「用 BNB 兑换」**（本地 anvil 按环境包渲染为「用 ETH 兑换」）→ 落在兑换页且 URL 同时带 `?symbol=<首币>&from=<原生币>&to=<首币>`（不是当前子币）；在「从」输入 `0.05` 原生币（本地 anvil 为 `ETH`）→ 见「预计可得」、路径行与更小的「最少到账」。
6. **兑换** → 依次见「等待你在钱包确认」→「已提交，等待上链」→「已上链」；收据显示实际到账（回执中交易对的 `Swap` 事件；ERC20 输入另见 `Transfer`）与哈希。
7. **前置注入（环境准备，不是用户路径）**：让测试钱包获得 ≥ 一个铸造价的 LOVE20（约 1000 LOVE20）：把步骤 5 的兑换金额提到约 `0.6` 原生币（anvil：ETH），或给测试钱包空投份额；采用哪种〔待定〕，见阻塞点 1。
8. **回铸造页 → 「1 授权」** → 授权确认后**停在本页**，按钮就地变「铸造」，出现「✓ 已授权」。
9. **「铸造」** → 收据：`#{memberId}` + 链上 `memberName` + 实际支付（`MemberMinted.cost`）+ 哈希；点唯一按钮「好的」→ 落在 `/my-nft`，刚铸造的身份带「刚铸造」高亮与返回条。
10. **我的 NFT** → 摘要「持有 1 个身份 NFT」（一个也显示数量，不隐藏）；`<md` 为卡片行（`NFT #id` + 名字 + 当前徽标），`≥md` 为 NFT 编号 / 名称 / 操作 三列表格；该行「当前」徽标且置顶着色；断开再连，身份仍被选中。
11. **有身份 → 问候 + 我的**：回首页 → `h1` 为「你好，{memberName}」（居中单行），首页不显示余额、没有「切换身份 NFT」；从底栏进入「我的」只有 `钱包余额` / `质押资产` 两个标签：默认 `钱包余额` 显示余额与「兑换」，切到 `质押资产` 才出现质押资产卡；页面上没有「账户」「关于」两个 section，也没有身份 NFT 的名字 / `NFT #{memberId}` /「切换身份 NFT」入口（2026-11-14 / 2026-11-19 两次移除后）。
12. **有资格 → 空投提醒卡出现且可点**：第二账号（anvil #5：fixture 给了 share、尚未铸造，而且没有身份 NFT——顺带验证提醒卡与身份无关）→ 首页先渲染问候与无身份提醒，快照 chunk 就绪后出现空投提醒卡（「你有空投资格，可铸造 {X} {symbol}」+「空投铸造」，不遮挡问候；两张卡同时存在时只有第一张用实心按钮）→ 进入空投铸造页 → S5 可铸造 → 点「立即铸造」→ 收据金额 = 回执 `AirdropClaimed.amount`；刷新后仍为 S6「已铸造」；换设备（清本地）后只显示「已铸造」。
13. **无资格 → 该卡不出现**：换一个不在快照内的新钱包（同样由 anvil 账户转原生币（anvil：ETH）作 gas）→ 首页不出现资格卡，也没有「无资格」字样或「无需操作」；回到刚铸造完份额的 anvil #5 刷新 → 卡片同样消失（`claimableAmount` 已为 0）。
14. **错误腿**：重名 → 「这个名字已经被用了。」；超额兑换 → 「{原生币} 不够…」；拒绝签名 → 「你在钱包里点了取消，没有扣款。」；三条都不出现 gas / allowance / nonce / `0x`。

15. **全局地址复制 / 身份输入三模式 / 社区 symbol 搜索（owner 2026-11-14 09:30）**：关于页任一合约地址、代币授权任一 spender、代币转账解析出的身份收款人、转让抽屉解析出的收款人、转账回执收款人、钱包菜单钱包地址——点击后原地出现「已复制」，剪贴板内容 = 完整地址（§4.7）；`/transfer` 与转让抽屉左下拉都在「按地址 / 按身份 NFT ID / 按身份 NFT 名字」之间切换，ID 模式输入名字给「请输入身份 NFT 编号，例如 #12。」且不发解析，名字模式输入同一字符串解析到对应 id + owner（纯数字名字不当 ID）；社区菜单输入 symbol：精确命中直接切换并关闭菜单，前缀命中列出候选，未知 symbol 给「没有找到这个 symbol 的社区。」且 URL 不变。

**阻塞点（必须显式处理，不得让脚本假装通过）**
- **零资产路径**：dev 参数下 7 字节名字的铸造价约 `1e21`（1000 LOVE20）。本地 bootstrap 已给首币池注入 **200,000 LOVE20 + 100 WETH**（`SEED_LIQUIDITY_TOKEN_AMOUNT=2e23`、`SEED_LIQUIDITY_PARENT_TOKEN_AMOUNT=1e20`，见 ADR-0004），初始价约 `0.0005` WETH/LOVE20；买够一次铸造约需 `0.5` WETH（含 0.3% 手续费，按初始池价估算），所以经济上闭合。但步骤 5 的 `0.05` 原生币（anvil：ETH）只够买约 100 LOVE20，不足一次铸造：要么把该步金额提到约 `0.6` 原生币，要么保留步骤 7 的空投注入。采用哪种〔待定〕。这是步骤 7 存在的原因。
- **dev/test 名称规则**：本地是 dev 变体，铸造名必须以 `Test` 开头（`T` 大小写敏感）；E2E 输入用 `Teste2e-member`，断言链上 `memberName` 与输入逐字相同（`core@72a1604` 后合约不再改写名字）。prod 变体没有该规则。
- 移动端连不上本地 anvil（钱包拒绝 `http:` RPC）；真机验收走测试网或 HTTPS 隧道。
- 铸造价、空投金额、兑换报价都是「预计」→ 脚本断言标签与格式，不断言具体数值；数值断言只用于回执解析结果。
