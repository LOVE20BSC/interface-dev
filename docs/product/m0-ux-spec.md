# M0 交互规格（UX Spec）

> 状态：Draft v2 · 已按 owner 决定更新首页、我的 NFT、铸造身份与铸造空投份额（§3.1–§3.4） · 适用：M0（身份漏斗 + 空投 + 单向兑换） · 读者：UI 工程师、验收
> 证据：`.research/tkm-connect-and-nav.md`、`.research/tkm-funnel-pages.md`、`.research/membernft-identity.md`、`.research/dex-and-anvil.md`、`.research/domain-model.md`、`.research/static-hosting-and-ux.md`、`GLOSSARY.md`、`docs/adr/0001..0003`、`docs/product/m0-scope.md`。
> 边界：本文件只写界面与交互。技术栈、构建、三环境注入见 ADR-0001/0002；**本文件未出现的合约方法一律视为不存在**（例如没有链上「默认身份」、`tokenURI` 不含任何内容、没有事件索引）。


## §0 设计原则

1. **新手视角（Lite 默认）**：界面不出现 gas、approve、allowance、nonce、revert、滑点、区块、合约等词；「高级视图」默认折叠，只放地址、哈希、轮次与浏览器链接（B-3；M0 的实现是各页「高级」折叠 + 钱包弹层的合约地址，不做全局开关）。所有中文过 `GLOSSARY.md` 六条纪律。
2. **身份优先**：首屏先回答「我是谁」，再回答「我能做什么」。未连接也要能读懂这是什么；已连接先解析身份，身份决定文案、CTA 与语气（ADR-0003 §4）。
3. **一页一任务**：每页只有一个主 CTA；次要入口最多两个，且不与主 CTA 同色同权。一个页面不承载两条完整流水线。
4. **结论先于细节（渐进披露）**：先给「能不能做 / 要花多少 / 还差什么」，明细收进折叠区。默认一屏回答完，不要求用户先读规则。
5. **不把合约函数映射成界面**：按用户任务组织（拿到身份 / 铸造空投份额 / 买到币），一个任务可调多个方法；合约有而用户不需要的能力（融合、默认身份、限额）不出现。反过来，一个方法可拆成多个界面状态（claim 前的资格判定）。
6. **不显示未知值为 0**：加载用骨架，未知用「—」，失败说「读不到」。余额、价格、倒计时、可铸造金额绝不先渲染 `0`（ADR-0003；B-1）。
7. **不制造死路**：每个任务页的空 / 错 / 无资格状态必须有且仅有一个「下一步」按钮，外加一个返回入口；导航页（首页）由常驻入口承担下一步，不另造「无需操作」静默态；不存在只有一句话的页面（B-11）。
8. **估算必须标注**：由报价、池子、区块时间推出来的数字写「预计 / 约」并给出会变的原因；链上精确值（余额、已铸造金额）不标。估算值在提交前重读一次链上。

## §1 应用外壳

### 1.1 布局、断点与安全区

- 断点 `md = 768px`（与 ADR-0001 一致）。`<md` 底部标签栏；`≥md` 左侧可折叠侧栏，**不转换**底部栏（TKM 的做法）。
- 内容区 `max-w-[32rem]` 居中、左右 16px 内边距；桌面侧栏占宽（展开 232px / 图标轨 64px），内容区不因侧栏而拉伸成宽表。
- `viewport-fit=cover`；`--nav-h: calc(64px + env(safe-area-inset-bottom))`；页面容器 `padding-bottom: calc(var(--nav-h) + 8px)`，`md:pb-8`；头部 `padding-top: max(8px, env(safe-area-inset-top))`。
- 头部高 56px，`sticky top-0` + 背景模糊 + 1px 下边框；滚动时内容不穿过头部。
- 底部栏 `fixed bottom-0`，`min-height` 含安全区，`z-40`；弹层 `z-50`，弹层底部同样加安全区内边距。

### 1.2 一级导航（5 项，同一份配置）

| # | 标签 | 路由 | 图标（lucide） | M0 状态 |
|---|---|---|---|---|
| 1 | 首页 | `/?symbol=` | `House` | 可用 |
| 2 | 治理 | `/governance?symbol=` | `Vote` | 占位 |
| 3 | 行动 | `/actions?symbol=` | `ListChecks` | 占位 |
| 4 | 链群 | `/groups?symbol=` | `UsersRound` | 占位 |
| 5 | 我的 | `/me?symbol=` | `UserRound` | 占位 |

- 移动端：24px 图标 + 11px 标签，激活态用实心图标 + 强调色；**不做中央凸起**——凸起会把一个不可用功能伪装成主入口（参考实现把「社区行动」凸起，实际是 M2 能力）。
- 桌面侧栏：5 项同序，激活项左侧 3px 指示条；顶部折叠按钮，折叠状态记在 `love20:v1:<chainId>:ui:<wallet>:sidebar`；底部放版本号 + 测试网徽标 + 「合约地址」入口（与钱包弹层同一弹层）。
- **占位页不是空白**：标题 + 「即将上线」徽标 + 一句将提供什么 + 一句为什么现在没有 + 「回首页」。文案：治理「用身份对提案投票，按治理轮结算。M0 只做身份与兑换，这一页还没有内容。」；行动「链群行动、链群服务、LP 行动将在后续版本开放。」；链群「链群是成员身份组成的协作单位，后续版本开放。」；我的「个人中心还在做。现在可以从首页或右上角进入『我的 NFT』。」（「我的」额外给一个「去我的 NFT」文字链）。
- 底部栏不显示徽标计数；经典「红点」留给以后有真实未读时再用。

### 1.3 页面头部规则

| 页面类型 | 左 | 中 | 右 |
|---|---|---|---|
| 一级（首页） | 品牌字标：当前社区 `symbol()`；无社区时「LOVE20」 | — | 完整药丸（chip + 地址/身份） |
| 二级（我的 NFT / 铸造身份 / 铸造空投份额 / 兑换代币） | 返回按钮 44×44 | 标题，单行 `truncate`，最长 8 字 | 药丸：chip 收成 28px 首字符圆徽（<480px），右触发区保留 |
| 占位页 | 品牌字标（同首页规则） | 标签名 | 完整药丸 |
| 收据态（页面内状态） | 「关闭」→ 首页 | 结果标题（铸造成功 / 兑换完成 / 已铸造） | 紧凑药丸（仅右触发区） |

- 返回：有历史 → `back`；无历史（直接打开深链）→ 回首页。始终有返回，深链不产生无出口页面。
- 标题只描述页面，不重复社区名；社区名在 chip 里。避免「铸造身份 · FOO」这种双标题。
- **社区名 = `symbol()`；`name()` 只用于技术详情/调试信息，不进主界面。** 只要界面出现「当前社区的名字」——页头品牌行、右上角社区 chip、含社区名的页面标题、任何元信息行——一律渲染链上 `symbol()`（如 `TestLOVE20`）；未选中或未知社区时品牌回落协议名「LOVE20」。标题原则上仍不重复社区名（见上一条）；若某个标题确实带上社区，用 `symbol()`。`name()` 是形如 `<子币 symbol>@<父币 symbol>` 的复合技术标识（如 `TestLOVE20@TestWETH`），不是显示名，不得用作社区名。
- 药丸在手机与桌面位置相同（右上角），不做第二处连接入口。

### 1.4 右上角连接药丸

一个容器、三种状态、两个触发区（照 TKM，但去掉主题与锚定）：

| 状态 | 外观与文案 |
|---|---|
| 未连接 | 单个按钮「连接钱包」，点击直接 `eth_requestAccounts`；进行中「连接中…」；点击后若 3 秒内仍无注入钱包 → 打开 §4.6 兜底抽屉（不显示死按钮「检测钱包中…」） |
| 链不对 | 红色描边按钮「网络不对，点此切换」→「切换中…」；`wallet_switchEthereumChain`，4902 时 `wallet_addEthereumChain`（参数来自环境包），成功自动重连 |
| 已连接 | `[SYMBOL ▾] │ [0x1234…abcd / 身份名 ⌄]`；两区各自可点，互不触发 |

- 左触发区（chip）：`max-w-[96px]` `truncate`，`font-mono text-[13px]`；二级页且视口 <480px 时收成 28px 首字符圆徽，其余情况显示完整 chip；两种形态都可点。chip 文案一律为当前社区 `symbol()`（§2.1），不是 `name()`。
- 右触发区：上行地址（mono 13，缩写 4+4），下行身份名或「未选择身份」（11px 灰）；有进行中交易时右上角 6px 琥珀点（§4.2）。
- 弹层形态：`<md` 为底部抽屉（抓手 + 安全区 + 最大高 70dvh，可滚动）；`≥md` 为锚定弹层（代币 240px，钱包 288px，右对齐）。同一时刻只开一个。
- 未连接时整个药丸就是一个「连接钱包」按钮：不渲染两个触发区，也不做灰掉的假入口。

### 1.5 左弹层：代币社区（行项完整顺序）

1. 分组标签「最近访问」。
2. 最近行（最多 4）：symbol（mono）+ 当前项「当前」徽标；点行即切换。
3. 空态：「还没有访问过其他社区」。
4. 分隔线。
5. 「父币」+ 右侧父币 symbol；根代币时整行禁用，右侧写「{根父币 symbol}（根）」（本地为 `TestWETH`）并附小字「当前已是根代币」。
6. 「子币」+ 右侧「{N} 个」+ chevron → 子币抽屉：`childTokens(parentTokenAddress, offset, 20, false)` 分页，「加载更多」，空态「这个社区还没有子币」。
7. 分隔线。
8. 「复制本页链接」（分享 / 移动端兜底要用）。

**没有**：锚定（pin）、「其他子币」二级入口、「代币信息」页、地址与复制。层级最多两层（弹层 → 子币抽屉）。

### 1.6 右弹层：钱包与身份（行项完整顺序）

1. 「钱包地址」+「复制」→ 2 秒「已复制」；下方完整地址 `font-mono text-xs break-all`。
2. 分隔线。
3. 身份行（整行可点 → 我的 NFT）：有身份 = 名称 + `#{memberId}` + 右侧「查看」；已连接但未选 = 「还没有选择身份」+「去选择」；钱包无 NFT = 「你还没有身份」+「去铸造」。
4. 「LOVE20」余额（按 `decimals()` 展示 2 位，精确值）+ 「BNB」余额（4 位）+ 小字「BNB 用于支付网络手续费」。
5. 分隔线。
6. 「进行中的操作 {n}」（仅有任务时出现）→ 任务抽屉（§4.2）。
7. 「合约地址」→ 弹层：链 ID、LOVE20、MemberNFT、Airdrop、Router、交易对地址 + 区块浏览器链接 + 逐项复制（信任信号，B-5）。
8. 分隔线。
9. 「断开连接」（危险色）。
10. 页脚小字：「身份保存在这台设备；换浏览器需要重新选择。」

**没有**：主题切换、网络选择器、ENS、头像、切换钱包地址列表（换地址 = 断开再连）。

### 1.7 全局横幅（互斥，最多一条）

| 触发 | 文案 | 动作 |
|---|---|---|
| test/dev 环境 | 「测试网 · 没有真实价值」 | 常驻细条，不可关闭 |
| 应用内浏览器（MicroMessenger / Telegram / Discord / FBAN / Instagram / Twitter） | 「在浏览器中打开才能连接钱包」 | 复制链接 / 尝试 Universal Link（§4.6） |
| 构建版本被证伪（build id 不一致） | 阻断式抽屉「有新版本，请刷新」 | 刷新；**仅在证据成立时出现** |

## §2 代币社区上下文

### 2.1 唯一事实源

- `?symbol=` 是当前社区的唯一事实源。**不持久化「当前代币」**（与 TKM 的 `localStorage._currentToken` 相反）；刷新、分享、返回都只认 URL。
- 缺省或空：读环境包 `firstTokenAddress` 的 `symbol()` 后 `history.replaceState` 补上 `?symbol=`，不新增历史记录。
- 写入 URL 的 symbol 永远来自链上 `symbol()`（含 dev 链的 `Test` 前缀），不接受用户手输；用户手改 URL 走 §2.5。
- **社区名 = `symbol()`；`name()` 只用于技术详情/调试信息，不进主界面。** 页头品牌行、chip、含社区名的页面标题与元信息行都渲染 `symbol()`（如 `TestLOVE20`），不渲染 `name()`；没有选中/解析到社区时品牌回落「LOVE20」。`name()` 是 `<子币 symbol>@<父币 symbol>` 的复合技术标识（如 `TestLOVE20@TestWETH`），不是显示名。
- 解析：`Launch.tokenAddressBySymbol(symbol)`；返回 `0x0` 即不存在。解析成功后保留其余 query（如 `?tx=`）。

### 2.2 切换判定表

| 场景 | 行为 |
|---|---|
| 首页 / 我的 NFT / 铸造身份 / 铸造空投份额 / 兑换代币 | 原地 `replace` 当前路径 + 新 `?symbol=`，保留其他 query，不整页刷新 |
| 占位页（治理 / 行动 / 链群 / 我的） | 同上；URL 保持可分享，页面内容不变 |
| 未知路由 | `replace` 首页 + 新 symbol |
| 目标是当前社区 | 关闭弹层，不发任何请求 |
| 有 pending 交易 | 允许切换；任务继续，头部下方「进行中的操作」条保留，可回到原页看收据 |
| 页面正处于报价 / 输入 | 中止在途请求；金额输入清空；页面回骨架（不同币价格不可复用） |
| 正处于收据态 | 允许切换；先提示「上一笔交易已经上链，收据仍可在『进行中的操作』里查看」 |

### 2.3 最近访问

- 键：`love20:v1:<chainId>:<launchAddress>:<wallet>:recentCommunities`（统一缓存封装，组件内禁止裸用 `localStorage`）。
- 值：`[{ symbol, address, at }]`；**上限 4**、按 `address` 去重、最新在前、排除当前项；解析成功后写入，切换时 merge 并置顶。
- 脏数据 / 反序列化失败 → 清空该键自身，不阻塞首屏。未连接时不读写（与 ADR-0003「未连接时代币面板不可用」一致）。

### 2.4 切换后重取 / 不重取

| 立即重取（query key 含 `tokenAddress`） | 不重取 |
|---|---|
| `symbol()` / `decimals()`（`name()` 仅在技术详情/调试需要时读取，不参与显示）、`parentToken()`、`childTokens()` 总数、`factory.getPair()` 与 `getReserves()`、报价、当前币余额 | 钱包与链、身份列表与当前身份、LOVE20 余额、MemberNFT 铸造报价（按首币计价，与社区无关）、空投资格（空投代币固定为首币） |

### 2.5 错误页

- **symbol 不存在**：标题「没有找到这个代币社区」+ 原样展示 `?symbol=FOO`（mono）+ 「链接里的代币符号可能拼错了，或者这个代币还没发射。」主 CTA「回到首币社区」（replace 首币）；次入口：最近访问（最多 4 条，直接切换）；底部文字链「复制当前链接」。
- **链上读取失败**（不是找不到）：标题「暂时读不到链上数据」+ 「网络可能不稳，你的资产没有变化。」+ 主 CTA「重试」+ 次「回首页」；保留上次成功的数据并标注「上次更新于 X 分钟前」，不把旧数据当新数据。
- Launch 地址缺失属于构建期错误，不出现在界面。

## §3 五个页面

> 通用：未连接时页面不跳转，页内给「连接钱包」；链不对由外壳拦截（§1.4）。所有金额读取中一律骨架，不渲染 `0`。收据见 §4.3。**下文「LOVE20」指首币，界面一律渲染链上 `symbol()`（dev 链为 `TestLOVE20`）。**

### 3.1 首页

**用户一句话目标**：打开就知道「我是谁、现在该做什么」。
**进入条件与前置**：可未连接浏览；`?symbol=` 缺省补首币；身份取自本地选择并已按 `ownerOf` 校验。空投资格来自快照懒加载 chunk（见下），**不进入首屏包，也不阻塞身份区**。

**区块顺序**
1. **身份区（首屏）** — 三态（另单独处理身份失效）：
   - 未连接：身份说明「一个钱包可以拥有多个身份，身份才是参与凭证。」+「连接钱包」（与右上角药丸是同一个连接动作与状态，不新增第二套连接入口）。
   - 已连接、无身份：「你还没有身份」+「去我的 NFT」文字入口。**首页不做铸造判断**：不出现「铸造身份」主 CTA，也不按 LOVE20 余额或空投资格决定去向；铸造由「我的 NFT」空态与 §3.3 承接。
   - 已连接、有身份：「你好，{memberName}」+ `#{memberId}` +「切换身份」文字入口（→ 我的 NFT，页内用「使用此身份」完成本地切换）。
   - 身份失效（`ownerOf` 不符）：清除本地选择，中性提示「这个身份已不属于当前钱包」，回落到无身份形态（仍持有其他身份时状态为「未选择身份」，一个都没有时才是「无身份」），不指责用户。
2. **空投资格卡（条件出现，全页唯一主 CTA）** — **仅当**钱包在快照中有未铸造条目且 `claimableAmount(...) > 0` 时出现。卡内只有标题「你参与了销毁活动，获得空投铸造资格」与主按钮「铸造空投份额」；**没有副标题、没有解释句**（金额在 §3.4 展示）。按钮跳转铸造空投份额页并保留当前 `?symbol=`。
3. **余额一行** — `LOVE20` 余额（精确，2 位），右侧「兑换」文字链；不展示 BNB（在钱包弹层里）。
4. **三个常驻导航入口** — 我的 NFT / 铸造空投份额 / 兑换代币，纯文字行，不与主按钮同色。入口行只是导航，**不代表空投资格**；资格只由第 2 块决定。
5. **页脚** — 开源文档链接「开源文档」→ `https://love20bsc.github.io/docs/`（新标签打开）。其下是默认折叠的「技术详情」，收版本号与 LOVE20 / MemberNFT / Airdrop / Router / 交易对地址 + 区块浏览器链接（与 §1.6 钱包弹层的「合约地址」同源）。合约地址与版本号不再直接铺在页脚；测试网横幅仍按 §1.7 全局渲染。

**快照加载与资格卡显隐**
- 空投快照 JSON 是**首屏渲染之后才 `import()` 的懒加载 chunk**：身份区、余额与入口先可用，快照数据就绪后资格卡原地出现；**不预留占位、不显示骨架、不阻塞或替换身份区**。
- 快照未就绪 → 不显示资格卡；钱包不满足资格 → 不显示资格卡，也不写「无资格」或「无需操作」。
- chunk 读取失败 → 页内一行低权重「空投资格暂时读不到」+「重试」，**不出现资格卡**。

**状态与错误**
- 未连接 · 加载（身份区与余额骨架，最多 1.5s）· 无身份 · 有身份 · 身份失效 · 资格卡出现 · 资格卡不出现 · 错误（身份 / 余额 / 资格）· pending（顶部任务条，不遮页面）。

- 任一屏最多一个实心按钮：未连接时是「连接钱包」；有资格时是「铸造空投份额」；其余情况不出现实心按钮。

**主 CTA 与次要入口**：有资格时唯一主 CTA 是资格卡内的「铸造空投份额」；无资格时没有主 CTA，只有身份区与入口行的文字入口。身份区的「去我的 NFT / 切换身份」与入口行均为文字链，不与主按钮同色同权。
**死路处理**：不设「无需操作」态。首页是导航页而不是任务终局：身份区始终给出下一步（连接 / 去我的 NFT / 切换身份），入口行常驻，因此资格卡缺席不会被读成「漏了什么」；无需额外静默文案。
**加载骨架**：身份区两行短条 + 余额一行灰条 + 入口行灰条；资格卡不占位、不出骨架。
**验收**
- 未连接打开：看到「连接钱包」与身份说明，并能连接。
- 连接后无身份：看到「你还没有身份」与「去我的 NFT」；不出现「铸造身份」主 CTA，也不因 LOVE20 余额或空投状态改判去向。
- 连接后有身份：看到「你好，{memberName}」+ `#id` +「切换身份」，点「切换身份」进入我的 NFT。
- 有资格：资格卡出现，标题与按钮文案逐字正确，且没有副标题 / 解释句；点按钮进入铸造空投份额页。
- 无资格：资格卡不出现，页面其余内容正常，且没有任何「无需操作」文案。
- 资格读取失败：出现「空投资格暂时读不到」+「重试」，不出现资格卡，身份区不受影响。
- 身份被转走后刷新：看到中性提示「这个身份已不属于当前钱包」，回落到无身份形态（仍持有其他身份时是「未选择身份」），不出现任何指向旧身份的操作。
- 快照 chunk 晚于首屏：身份区先可用，卡片在数据就绪后出现，不遮挡、不阻塞身份区。
- 任一屏最多一个实心按钮。

### 3.2 我的 NFT

**用户一句话目标**：看清我有几个身份、现在用哪个，并立即换一个。
**进入条件与前置**：需连接（页内连接）；从首页入口或钱包弹层身份行进入。身份列表 = `balanceOf(wallet)` + `tokenOfOwnerByIndex(wallet, i)`（Multicall3 批量）+ `memberName(tokenId)`。

**布局（参照参考实现的同页，只取结构）**
- `<md`：**卡片行**，一个身份一张卡，卡内依次是 `#memberId`、`memberName`、当前身份 pill 与操作。
- `≥md`：**表格**，列为 编号 / 名称 / 操作。
- 两种形态共用同一排序：**当前身份第一，其余按 `memberId` 升序**；当前行整行着色（accent tint）并带「当前」pill。
- 持有数量始终显示真实值，**不因 N ≤ 3 隐藏**；写操作进行中**不禁用整张表**（见状态）。

**区块顺序**
1. **摘要条** — 「持有 {N} 个身份」+「当前：{name} / 未选择」。数据：`balanceOf`。
2. **说明段（两行内）** — 「一个 NFT 就是一个身份，可以在多个社区使用。换钱包不会改身份，只有转让才换控制者。」
3. **身份列表** — 卡片行（<md）/ 表格（≥md）；字段只有 `#memberId`、`memberName`、当前 pill、操作。`tokenURI` 返回空字符串，**不渲染图片、不请求任何图片源**。
4. **行内操作** —
   - 「使用此身份」：**纯本地选择**，写入本地当前身份并立即更新页面，**不发起链上交易、不签名、不等待**；成功后该行置顶并着色。当前行显示禁用态「当前身份」。
   - 「转让」：打开转让抽屉（收款地址 + 校验：`0x` + 40 位、非零、非自己），警告「转让会改变这个身份的控制者。身份的历史与质押仍留在身份上，随身份一起换控制者、不单独转移；转让不可撤销。」确认后 `safeTransferFrom(你, 对方, memberId)`；成功的收据写「已转让给 0x…」；若转的是当前身份，同时清除本地选择——还有其他身份就回到「未选择身份」，没有则回落到无身份形态。
5. **底部** — 「铸造新身份」（描边按钮）+「回首页」（文字）。
6. **高级折叠** — MemberNFT 合约地址 + 浏览器链接。

**状态**：未连接「连接钱包后查看你的身份。」+ 连接按钮 · 加载（3 行骨架 + 摘要骨架）· 空「你还没有身份。」+ 说明「铸造需要一个名字和少量 LOVE20。」+ 主 CTA「铸造身份」· 错误「身份列表暂时读不到。」+「重试」· 身份失效（行内标「已失效」并不可选，同时清除本地选择）· 转让中（**仅该行**显示「转让中…」；其余行的「使用此身份」照常可用，其余行的「转让」按 §4.2 的单一写操作约束禁用并注明原因，**整表不禁用**）。「使用此身份」是本地选择，没有「切换中」等待态。
**主 CTA 与次要入口**：有身份时无主 CTA（列表即内容），唯一实心按钮是空态的「铸造身份」；每行操作为文字/描边按钮。「转让」为危险色并二次确认。
**死路处理**：空态给「铸造身份」；错误态给「重试」；失效行给「重新选择」。任何一行都不允许只有名字没有操作。
**加载骨架**：摘要条灰块 + 3 行等高行（名称 60% 宽、`#id` 30%、右侧按钮方块）。
**验收**
- 窄屏（<md）为卡片行，宽屏（≥md）为 编号 / 名称 / 操作 三列表格。
- 持有 2 个身份：2 行，当前项置顶、整行着色并带「当前」pill。
- 持有 ≤3 个身份时数量仍显示真实值，不隐藏。
- 点「使用此身份」后无需签名立即生效，置顶与着色移动到该行；回首页看到新名字。
- 无身份：看到「铸造身份」并能进入铸造页。
- 转让确认后：该行消失；若转的是当前身份，本地选择被清除——还有其他身份时回到「未选择身份」，没有时回落到无身份形态；转的不是当前身份则当前身份不变；警告写明只换控制者、历史与质押留在身份上。
- 转让进行中：整张表不被禁用，只有相关行的写操作受限；其他行仍可「使用此身份」。
- 刷新后当前身份仍是上次所选（`ownerOf` 校验通过）。

### 3.3 铸造身份

**用户一句话目标**：用一个名字铸出身份，事前知道要花多少、还差什么、下一步去哪。
**进入条件与前置**：需连接 + 链正确；无身份用户是主客群。价格按 LOVE20 计价，与当前社区无关。

**区块顺序**
1. **名称输入** — 占位「给身份起个名字」；上限字节数由 `MAX_NAME_LENGTH()` 读取（不硬编码；按 UTF-8 字节校验，不用 `maxLength`，否则中文会被截错）；下方实时「{n}/32 字节」+ 一行规则「中文 3 字节、英文与数字 1 字节；名字越短，价格越高」。
2. **检查行** — 「检查中…」/「✓ 可以用」/「✗ 这个名字已经被用了（#{existingId}）」/「✗ 太长了」/「✗ 含有不可用的字符」。数据：`isNameUsed(name)`（防抖 400ms）→ 提交前以 `mint` 的 `eth_call` 模拟为准。
3. **费用卡** — 「铸造价格 **预计** {cost} LOVE20」+「我的 LOVE20：{balance}」+ 余额旁的小文字链「去兑换代币」+ 不足时「还差 {diff}」+ 小字「价格随已铸造数量变化，提交时以链上为准」。`去兑换代币` 是次级文字入口：与余额同一行、不描边、不填充，视觉权重低于铸造主 CTA；跳转 §3.5 兑换代币页并固定首币 `?symbol=<LOVE20>`（与下方资金分支同一落点）。数据：`calculateMintCost(name)`、`LOVE20.balanceOf`。
4. **资金分支卡（仅不足时出现）** — 见下。
5. **按钮区** — 两段式「1 授权」「2 铸造」（§4.1）；下方折叠一行「为什么要两次确认？第一次只是允许合约扣款，不会立刻扣钱；第二次才是铸造。」
6. **收据** — 成功后整页替换为收据（§4.3）：`#{memberId}` + 链上 `memberName`、实际支付（来自 `MemberMinted.cost`）、哈希、下一步。

**资金分支卡（余额不足时的唯一分叉）**

| 条件 | 文案 | 按钮 |
|---|---|---|
| 空投可铸造 | 「你还有空投份额可以铸造，预计 {X} LOVE20，铸造后就够了。」 | 铸造空投份额（主） |
| 空投不可铸造 | 「LOVE20 不够。可以用 BNB 换一些，再回来铸造。」 | 用 BNB 兑换（主） |
| 资格读不到 | 「暂时确认不了你的空投资格。」 | 重试（主）/ 先兑换（次） |

> 分叉落点固定为**首币 LOVE20**：即使当前社区是子币，也跳 `?symbol=<LOVE20>`（兑换页买的是当前社区币，买错币等于没解决）。

**状态**：未连接「连接钱包后铸造身份。」+ 连接按钮 · 名称空（按钮禁用，无报错）· 检查中（按钮禁用）· 不可用（按钮禁用 + 原因）· 余额不足（显示分支卡，主按钮改为分支 CTA）· 待授权「1 授权」· 授权中「授权中…」· 已授权（阶段 1 消失，只留「铸造」）· 待铸造「2 铸造」· 铸造中「铸造中…」· 成功（收据）· 失败（错误卡 + 重试，保留名字）。
**主 CTA 与次要入口**：整页只有一个实心按钮：未授权时是「1 授权」，授权后同位置变「铸造」。次要入口为费用卡内的小文字链「去兑换代币」与页尾「回首页」；两者都不与主按钮同色同权。
**死路处理**：名字不可用 → 保留输入与光标，给「换一个名字」；余额不足 → 分支卡；交易失败 → 保留名字与报价，给「重试」；**任何状态都不把用户弹回首页**。
**加载骨架**：输入框可用（先让用户打字），费用卡 3 行灰条，按钮区一个灰块；余额读完后原地替换，不整页 spinner。
**验收**
- 用户输入已被使用的名字，应在 1 秒内看到「已经被用了」且不能提交。
- 用户余额不足时，应看到「还差多少」和一条明确出路（铸造空投份额或兑换），且该出路指向 LOVE20；有资格时分支按钮为「铸造空投份额」。
- 费用卡余额旁有次级「去兑换代币」文字链，跳转兑换页并固定首币 LOVE20；它不是实心按钮，不与铸造主 CTA 同权。

- 用户铸造成功后，应看到含 `#id`、名字、实际支付与哈希的收据，并能一键去「我的 NFT」。
- 用户刷新页面时若有未完成交易，应看到恢复后的 pending 或收据，而不是空白表单。

### 3.4 铸造空投份额

**用户一句话目标**：三十秒内知道自己有没有、能铸造多少、现在能不能铸造，并一次完成。
**进入条件与前置**：需连接；资格来自部署时固定的 Merkle 快照（share + proof，按需 `import()` 的快照 JSON，**不进首屏包**）。空投代币固定为首币 LOVE20，**与当前社区无关**，切换社区不改变本页内容。页头标题只写「铸造空投份额」，**不设副标题或解释句**；「本次空投：LOVE20」是状态卡首行的一行元信息，快照机制收进「规则」折叠。界面任何位置都不写「领取」；合约动作 `claim` 只保留在代码、合约与术语表里。

**区块顺序**
1. **状态与金额卡** — 七态之一（见下）；首行元信息「本次空投：LOVE20」；金额行「预计可得 {X} LOVE20」+ 小字「按铸造时的池子余额与剩余份额计算，别人铸造后金额会变。」数据：`claimableAmount(LOVE20, wallet, share, proof)`、`balanceOf(airdrop)`。
2. **主按钮区** — 仅「可铸造」态出现「铸造空投份额」。
3. **规则折叠** — 「为什么金额会变」「快照是什么」「空投合约地址」。
4. **收据** — 铸造成功后整页替换（§4.3）。

**状态**：S0 未连接 / S1 加载 / S2 错误 / S3 空（无资格）/ S4 暂不可铸造 / S5 可铸造 / S6 已铸造；pending 走 §4.2（铸造中 → 已上链），成功即 S6 收据（§4.3），失败回到 S5 + 错误卡。

**七态文案（互斥，同屏只显示一条）**

| 状态 | 文案与按钮 |

| S0 未连接 | 「连接钱包后查看你的空投份额。」+「连接钱包」 |

**主 CTA 与次要入口**：整页只有一个实心按钮；S5 是「铸造空投份额」，其他态的主按钮是各自的出路（连接 / 重试 / 兑换）。次入口固定为「回首页」或「复制链接」。

### 3.5 兑换代币

**用户一句话目标**：用 BNB 换到当前社区代币，事前知道会拿到多少、最少拿到多少。
**进入条件与前置**：需连接；**仅原生币 → 当前社区币单向**，不提供反向；原生币输入**不需要授权**，所以本页只有一个确认步骤。路径由 `parentToken()` 逐级上溯到 WETH（最多 3 跳）；池子储备读 `factory.getPair()` + `getReserves()`。
**区块顺序**
1. **方向行** — 「用 BNB 兑换 {SYMBOL}」+ 小字「只支持买入，卖出不在 M0」。
2. **输入** — 金额输入 + 「余额 {b} BNB」+「最多可用 {b-0.002}」（预留手续费，标注约）；数据：`getBalance`。
3. **报价卡** — 「预计可得 {out} {SYMBOL}」「1 BNB ≈ {rate}」「最少到账 {minOut}」「手续费 0.3%（已含在报价里）」「更新于 {n} 秒前」；价格影响 >3% 才加一行「这笔交易会让价格变动约 {x}%」。数据：`router.getAmountsOut(amountIn, path)`。
4. **不可兑换卡** — 池子为空 / 路径超过 3 跳时替换报价卡与按钮。
5. **主按钮** — 「兑换」→「确认中…」→「上链中…」。
6. **失败卡** — 保留金额，给「重新报价并重试」；说明「没有成交，只消耗了网络手续费」。
7. **高级折叠** — 路由（WETH→…→{SYMBOL}）、交易对地址、Router 地址、浏览器链接。

**状态**：未连接（「连接钱包后兑换。」+ 连接按钮）· 加载余额 · 空输入（按钮禁用）· 报价中（按钮禁用 + 数字骨架）· 可兑换 · 价格影响 >10%（红色提示 + 需二次确认）· **池子为空** · 路径不支持 · BNB 不足（「BNB 不够，还差约 {x}」+ 留手续费的说明）· 报价失败（「价格暂时读不到」+ 重试）· 确认中 · 上链中 · 成功（收据）· 失败（失败卡）。

**池子为空（本协议的真实默认态）**：发射只 `createPair` 建池，不注入流动性，所以新社区大概率无储备。文案：「这个社区还没有可兑换的流动性。」+「发射时只创建了交易对，没有注入资金，所以现在用 BNB 买不到 {SYMBOL}。」+ 主「看看其他社区」（打开代币抽屉，含最近访问）+ 次「复制本页链接」+ 高级「查看池子地址」。**不承诺通知，不出现「稍后重试」这种无信息的按钮。**

**主 CTA 与次要入口**：一个实心「兑换」；次入口只有「回首页」。参数（滑点档位）只在高级折叠里，主界面不出现「滑点」二字，只说「最少到账」。
**死路处理**：空池、路径不支持、余额不足、报价失败都有明确下一步；失败重试必须重新报价并刷新 `amountOutMin`。
**加载骨架**：输入框可先输入；报价卡 3 行灰条 + 按钮灰块；余额就绪后原地替换。
**验收**
- 池子为空时，用户应看到专门说明与至少两条出路，而不是一条 toast。
- 用户输入金额后，应同时看到「预计可得」与更小的「最少到账」，并知道数字会变。
- 用户输入接近全部余额时，应看到「最多可用」与手续费预留提示。
- 交易失败后，用户应保留金额、看到原因，并能一键重新报价重试。
- 成功后，用户应看到实际到账（来自回执中的 ERC20 `Transfer`）与交易哈希。

## §4 横切交互规范

### 4.1 授权 → 执行：按钮阶梯
- 只在需要时出现第一阶段：`allowance(wallet, memberNFT) ≥ 本次应付` 时直接显示单按钮「铸造」，回访用户永远只看到一次确认。
- 授权额 = 本次报价 × 1.01（按需 + 1% 缓冲），不授权无限额；文案必须写「只是允许合约最多扣这么多，不会立刻扣钱」。
- 阶段 1 成功后**不跳转、不刷新、不弹 toast**：同一位置的按钮就地变为「铸造」，阶段 1 收成一行「✓ 已授权」。
- 按钮文案固定：`1 授权` → `授权中…`（钱包确认）→ `上链中…` → `已授权`；`2 铸造` 在授权确认前禁用，确认后同位置变 `铸造` → `铸造中…`。
- **禁止**把授权缓冲写成「滑点」：参考实现的「滑点：0.1%」实为授权缓冲，不是价格滑点，属于错误标签。
- 用户拒签，或授权后价格上行使额度不够 → 按钮回到可点，文案「授权不够这次使用，需要再授权一次」，不跳页、不清空输入。

### 4.2 交易 pending 语法
- 三态，措辞固定：**等待你在钱包确认** → **已提交，等待上链** → **已上链 / 没有成功**。不把三者合并成一个「加载中」；授权阶段同样走这三态，按钮写「授权中…」。
- 任务对象 `{ id, kind, tokenAddress, memberId?, amount?, hash?, state, startedAt }` 存本地；有 hash 时刷新用 `getTransactionReceipt` 恢复；无 hash 视为未提交，中性文案「上次的操作没有提交」。
- 展示位置：按钮内文案 + 头部下方 36px 任务条；也**不做全屏 LoadingOverlay**，不锁页面（参考实现的全屏遮罩是漏斗漏点）。
- pending 中允许切页、切社区；任务条常驻，点击回到发起页。同一时刻只允许一个写操作在途，其余**写操作**按钮禁用并注明「有一个操作正在进行」；纯本地选择（如「使用此身份」）不受影响。
- 先落本地收据、再刷新数据，避免「数据已变但用户没看到收据」。

### 4.3 成功收据（取代 toast + 2 秒跳走）
- 收据是**页面内状态**：不自动跳转、不 2 秒消失。标题 + 你得到什么 + 哈希 + 两个下一步。
- 必备字段：结果（铸造成功 / 兑换完成 / 已铸造）· **你得到什么**（`#memberId` + 链上 `memberName` / 实际到账数量 / 已铸造金额）· 实际支付（若有）· 交易哈希（复制 + 浏览器链接，收在高级里）· 下一步（主「回首页」或「去我的 NFT」，次「再去兑换」或「去铸造」）。
- 所有数字来自本笔交易回执：`MemberMinted.cost/name/memberId`、ERC20 `Transfer`、`AirdropClaimed.amount`；**不用前端估算值**。
- 收据可刷新、可后退、不会被切换社区清掉；刷新后从本地任务恢复。

### 4.4 错误文案映射（消费 `registry/errors.json`）
- 原则：**写结果与下一步，不写机制**。不出现 gas、allowance、nonce、revert、selector、`0x…` 堆栈、HTTP 状态码。
- 三层：`selector → 英文错误名（errors.json）→ 中文结论 + 下一步`；未收录的 selector 落到「交易被合约拒绝」+ 哈希 + 「重试」。

| 情形 | 文案（结论 + 下一步） |
|---|---|
| 用户取消（4001） | 「你在钱包里点了取消，没有扣款。」/ 重试 |
| 网络手续费不足 | 「BNB 不够付手续费。请先转一点 BNB 进来。」/ 复制地址 |
| 代币余额不足 | 「LOVE20 不够，还差 {x}。」/ 铸造空投份额、兑换 |
| 授权不足 | 「授权额度不够这次使用。」/ 再授权一次 |
| `NameAlreadyExists` | 「这个名字已经被用了。」/ 换一个名字 |
| `NameTooLong` / `NameInvalidCharacters` | 「名字太长 / 含有不可用的字符。」/ 修改名字 |
| 流动性不足 / 价格变动保护 | 「价格变化太大，这笔交易没有成交。」/ 重新报价 |
| 超时 / RPC 失败 | 「网络没有及时响应，交易状态未知。」/ 查看哈希 + 重试（不重复发送） |

### 4.5 估算类信息标注
- 三档标记：**预计**（空投可铸造金额、铸造价格、兑换报价与最少到账）、**约**（手续费预留、价格影响、任何倒计时）、**精确**（余额、已铸造金额、已上链数量）。
- 每个预计值必须带半句「为什么会变」：空投「别人铸造后金额会变」；铸造「价格随已铸造数量变化」；兑换「价格随池子变化」。
- 基于 Phase 的倒计时只能用「区块差 × 观测出块时间」估算，写「约 X 分钟」，并说明时间片长度会被协议调整（`Phase` 以区块计量，不是时间戳）。M0 页面不显示轮次倒计时；此规则适用于后续页面。
- 提交前重读一次链上；报价超过 30 秒视为过期，需重新报价。

### 4.6 移动端钱包兜底阶梯
- 顺序：① 用系统浏览器打开（Universal Link / `window.open`）② 扫码（二维码内容 = **当前页面 URL**，不是 WalletConnect URI；M0 只有注入钱包）③ 复制链接 ④ 说明「在钱包 App 内置浏览器里粘贴此链接」。
- 触发：应用内浏览器 UA 命中 → **连接之前**显示顶部横幅；没有 `window.ethereum` → 连接按钮直接打开兜底抽屉，不转圈、不报错。
- 抽屉文案：「这个浏览器里没有钱包。用下面任意一种方式打开，就能连接。」+ 三个按钮 + 一行「已经装了钱包？在钱包 App 的浏览器里粘贴这个链接。」
- 桌面放大二维码，移动优先 Universal Link 与复制；二维码本地生成，不调用第三方服务。没有兜底就不放「连接钱包」按钮——任何「点了没反应」都是漏斗漏点。

## §6 M0 验收脚本大纲

**前置**：`vite preview --base=/<repo>/` 跑构建产物（不是 dev server）；Playwright + 注入型测试钱包（EIP-1193 stub + 本地私钥签名）；链 = 本地 anvil 31337，`make bootstrap` 起链并 seed：首币池注入 **200,000 LOVE20 + 100 WETH**（`SEED_LIQUIDITY_TOKEN_AMOUNT=2e23`、`SEED_LIQUIDITY_PARENT_TOKEN_AMOUNT=1e20`，见 ADR-0004）；dev 的地址与 ABI 只读 `anvil/export/deployments/anvil31337_dev.json` 与 `anvil/export/abis/*.json`（前端消费副本 `src/config/deployments/anvil31337_dev.json`）。fixture 的 anvil 0–9 号账户都在快照内（0–4 已铸造，5–9 有份额未铸造），所以主流程必须用**不在快照内**的新私钥（先从一个 anvil 账户转一点 BNB 作 gas）。GitHub owner 与仓库名已定（`LOVE20BSC/interface-dev` / `interface-test` / `interface`，见 ADR-0002 §4），环境变体由 CI 按仓库名关键字选择（含 `dev` → dev，否则含 `test` → test，否则 prod；`vars.VITE_ENV` 可覆盖），发布命令为 `pnpm release-to <target>`（ADR-0002 §4）；**只有里程碑最终排期〔待定〕**。`--base` 由 CI 变量注入，脚本不得硬编码。

1. **打开 `/` → 未连接 → 连接**：未连接态 = 品牌一句话 + 「连接钱包」；底部 5 tab 可见；逐个点占位页，都应看到「即将上线」、一句说明与「回首页」，无空白、无半成品表单。点「连接钱包」→ 药丸变为两区，URL 补上 `?symbol=<首币>`。
2. **无身份 → 去我的 NFT**：首页身份区显示「你还没有身份」+「去我的 NFT」；**不出现「铸造身份」主 CTA、不出现「无需操作」，也不因 LOVE20 余额或空投资格改判去向**。点「去我的 NFT」→ 我的 NFT 空态「你还没有身份。」+「铸造身份」。
3. **进入铸造页（从我的 NFT 空态的「铸造身份」）** → 名称可输入；费用卡出现「预计 {cost} LOVE20」，下方「我的 LOVE20：0」被标成不足；余额旁有次级「去兑换代币」文字链；不出现整页 spinner。
4. **输入 7+ 字节名字**（如 `e2e-member`）→ 检查行「可以用」；余额不足 → 资金分支卡出现。
5. **点分支卡「用 BNB 兑换」** → 落在兑换页且 `symbol=<首币>`（不是当前子币）；输入 `0.05` BNB → 见「预计可得」与更小的「最少到账」。
6. **兑换** → 依次见「等待你在钱包确认」→「已提交，等待上链」→「已上链」；收据显示实际到账（回执 `Transfer`）与哈希。
7. **前置注入（环境准备，不是用户路径）**：让测试钱包获得 ≥ 一个铸造价的 LOVE20（约 1000 LOVE20）：把步骤 5 的兑换金额提到约 `0.6` BNB，或给测试钱包空投份额；采用哪种〔待定〕，见阻塞点 1。
8. **回铸造页 → 「1 授权」** → 授权确认后**停在本页**，按钮就地变「铸造」，出现「✓ 已授权」。
9. **「铸造」** → 收据：`#{memberId}` + 链上 `memberName` + 实际支付（`MemberMinted.cost`）+ 哈希；点「去我的 NFT」。
10. **我的 NFT** → 摘要「持有 1 个身份」（一个也显示数量，不隐藏）；`<md` 为卡片行（`#id` + 名字 + 当前徽标），`≥md` 为 编号 / 名称 / 操作 三列表格；该行「当前」徽标且置顶着色；断开再连，身份仍被选中。
11. **有身份 → 切换身份**：回首页 → 「你好，{memberName}」+ `#{memberId}` +「切换身份」；点「切换身份」→ 我的 NFT；首页任何状态都不出现「无需操作」。
12. **有资格 → 资格卡出现且可点**：第二账号（anvil #5：fixture 给了 share、尚未铸造，而且没有身份——顺带验证资格卡与身份无关）→ 首页先渲染身份区，快照 chunk 就绪后出现资格卡（标题「你参与了销毁活动，获得空投铸造资格」+「铸造空投份额」，无副标题、无金额、不遮挡身份区）→ 进入铸造空投份额页 → S5 可铸造 → 点「铸造空投份额」→ 收据金额 = 回执 `AirdropClaimed.amount`；刷新后仍为 S6「已铸造」；换设备（清本地）后只显示「已铸造」。
13. **无资格 → 该卡不出现**：换一个不在快照内的新钱包（同样由 anvil 账户转 BNB 作 gas）→ 首页不出现资格卡，也没有「无资格」字样或「无需操作」；回到刚铸造完份额的 anvil #5 刷新 → 卡片同样消失（`claimableAmount` 已为 0）。
14. **错误腿**：重名 → 「这个名字已经被用了。」；超额兑换 → 「BNB 不够…」；拒绝签名 → 「你在钱包里点了取消，没有扣款。」；三条都不出现 gas / allowance / nonce / `0x`。

**阻塞点（必须显式处理，不得让脚本假装通过）**
- **零资产路径**：dev 参数下 7 字节名字的铸造价约 `1e21`（1000 LOVE20）。本地 bootstrap 已给首币池注入 **200,000 LOVE20 + 100 WETH**（`SEED_LIQUIDITY_TOKEN_AMOUNT=2e23`、`SEED_LIQUIDITY_PARENT_TOKEN_AMOUNT=1e20`，见 ADR-0004），初始价约 `0.0005` WETH/LOVE20；买够一次铸造约需 `0.5` WETH（含 0.3% 手续费，按初始池价估算），所以经济上闭合。但步骤 5 的 `0.05` BNB 只够买约 100 LOVE20，不足一次铸造：要么把该步金额提到约 `0.6` BNB，要么保留步骤 7 的空投注入。采用哪种〔待定〕。这是步骤 7 存在的原因。
- 首币 symbol 以 `Test` 开头时链上会给名字加 `Test` 前缀 → 收据名字与输入不同；断言按链上 `memberName`，不按输入。
- 移动端连不上本地 anvil（钱包拒绝 `http:` RPC）；真机验收走测试网或 HTTPS 隧道。
- 铸造价、空投金额、兑换报价都是「预计」→ 脚本断言标签与格式，不断言具体数值；数值断言只用于回执解析结果。
