> 证据：`.research/tkm-connect-and-nav.md`、`.research/tkm-funnel-pages.md`、`.research/membernft-identity.md`、`.research/dex-and-anvil.md`、`.research/domain-model.md`、`.research/static-hosting-and-ux.md`、`GLOSSARY.md`、`docs/adr/0001..0003`、`docs/product/m0-scope.md`。
> 边界：本文件只写界面与交互。技术栈、构建、三环境注入见 ADR-0001/0002；**本文件未出现的合约方法一律视为不存在**（例如没有链上「默认身份」、`tokenURI` 不含任何内容、没有事件索引）。


## §0 设计原则

1. **新手视角（Lite 默认）**：界面不出现 gas、approve、allowance、nonce、revert、滑点、区块、合约等词；「高级视图」默认折叠，只放地址、哈希、轮次与浏览器链接（B-3；M0 的实现是 `/about` 的「合约地址」页 + 钱包弹层的合约地址，不做全局开关；各业务页不再重复技术详情折叠）。所有中文过 `GLOSSARY.md` 六条纪律。
2. **身份优先**：首屏先回答「我是谁」，再回答「我能做什么」。未连接也要能读懂这是什么；已连接先解析身份，身份决定文案、CTA 与语气（ADR-0003 §4）。
3. **一页一任务**：每页只有一个主 CTA；次要入口最多两个，且不与主 CTA 同色同权。一个页面不承载两条完整流水线。
4. **结论先于细节（渐进披露）**：先给「能不能做 / 要花多少 / 还差什么」，明细收进折叠区。默认一屏回答完，不要求用户先读规则。
5. **不把合约函数映射成界面**：按用户任务组织（拿到身份 / 空投铸造 / 买到币），一个任务可调多个方法；合约有而用户不需要的能力（融合、默认身份、限额）不出现。反过来，一个方法可拆成多个界面状态（claim 前的资格判定）。
6. **不显示未知值为 0**：加载用骨架，未知用「—」，失败说「读不到」。余额、价格、倒计时、可铸造金额绝不先渲染 `0`（ADR-0003；B-1）。
7. **不制造死路**：每个任务页的空 / 错 / 无资格状态必须有且仅有一个「下一步」按钮，外加一个返回入口；导航页（首页）由常驻入口承担下一步，不另造「无需操作」静默态；不存在只有一句话的页面（B-11）。
8. **估算必须标注**：由报价、池子、区块时间推出来的数字写「预计 / 约」并给出会变的原因；链上精确值（余额、已铸造金额）不标。估算值在提交前重读一次链上。

## §1 应用外壳

### 1.1 布局、断点与安全区

- 断点 `md = 768px`（与 ADR-0001 一致）。`<md` 底部标签栏；`≥md` 左侧可折叠侧栏，**不转换**底部栏（TKM 的做法）。
- 内容区 `max-w-[32rem]` 居中、左右 16px 内边距；桌面侧栏占宽（展开 232px / 图标轨 64px），内容区不因侧栏而拉伸成宽表。
- `viewport-fit=cover`；`--nav-h: calc(64px + env(safe-area-inset-bottom))`；页面容器 `padding-bottom: calc(var(--nav-h) + 8px)`，`md:pb-8`；头部 `padding-top: max(8px, env(safe-area-inset-top))`。
- 头部高 56px，`sticky top-0` + 背景模糊 + 1px 下边框；滚动时内容不穿过头部。
- 底部栏 `fixed bottom-0`，`min-height` 含安全区，`z-40`；弹层 `z-50`，弹层底部同样加安全区内边距。

### 1.2 一级导航（5 项，同一份配置）

| # | 标签 | 路由 | 图标（lucide） | M0 状态 |
|---|---|---|---|---|
| 1 | 首页 | `/?symbol=` | `House` | 可用 |
| 2 | 治理 | `/governance?symbol=` | `Vote` | 占位 |
| 3 | 行动 | `/actions?symbol=` | `ListChecks` | 占位 |
| 4 | 应用 | `/apps?symbol=` | `LayoutGrid` | 可用（功能页目录） |
| 5 | 我的 | `/me?symbol=` | `UserRound` | 可用（余额 + 账户） |

- **「应用」取代「链群」（2026-11-11 owner 决定）**：第 4 项是功能页目录 `/apps?symbol=`（图标 `LayoutGrid`），把创世空投、身份 NFT、代币兑换以及今后独立的功能页集中管理。**未来页面只加一条目录数据，不加导航代码**；功能页多起来后按条目的 `category` 自动分组（≥2 个分类才出现分组标题）。`/group` 路由保留给旧深链（占位页，不 404），但底栏不再出现「链群」。

- 移动端：24px 图标 + 11px 标签，激活态用实心图标 + 强调色；**不做中央凸起**——凸起会把一个不可用功能伪装成主入口（参考实现把「社区行动」凸起，实际是 M2 能力）。
- 桌面侧栏：5 项同序，激活项左侧 3px 指示条；顶部折叠按钮，折叠状态记在 `love20:v1:<chainId>:ui:<wallet>:sidebar`；底部放版本号 + 测试网徽标 + 「合约地址」入口（与钱包弹层同一弹层）。
- **占位页不是空白**：标题 + 「即将上线」徽标 + 一句将提供什么 + 「回首页」。徽标已经说明「现在没有」，正文不重复。文案：治理「用身份 NFT 对提案投票，按治理轮结算。M0 只做身份 NFT 与兑换。」；行动「链群行动、链群服务、LP 行动。」；`/group` 旧深链「链群是身份 NFT 组成的协作单位。」。我的不再是占位页：它承接余额与账户信息（§3.7），底栏与侧栏也不再给它「即将上线」标记。
- 底部栏不显示徽标计数；经典「红点」留给以后有真实未读时再用。

### 1.3 页面头部规则

| 页面类型 | 左 | 中 | 右 |
|---|---|---|---|
| 一级（首页） | 移动端（<md）：**未连接时**社区 `symbol()`（无社区/未知回退「LOVE20协议」）；已连接（含错网络）隐藏。桌面（≥md）：「首页」文字标签（社区名在左侧栏顶部） | — | 完整药丸（chip + 地址/身份）；已连接时它是移动端页头唯一的社区名位置 |
| 二级（我的 NFT / 铸造身份 NFT / 空投铸造 / 兑换代币 / 应用） | 返回按钮 44×44 | 标题，单行 `truncate`，最长 8 字 | 药丸：chip 收成 28px 首字符圆徽（<480px），右触发区保留 |
| 占位页 | 返回按钮 44×44 | 标签名（治理 / 行动；`/group` 旧深链为「链群」） | 药丸：chip 收成 28px 首字符圆徽（<480px），右触发区保留 |
| 收据态（页面内状态） | 「关闭」→ 首页 | 结果标题（铸造成功 / 兑换完成 / 已铸造） | 紧凑药丸（仅右触发区） |

- **移动端首页：未连接保留左侧标识，连上后由右上角 chip 承担（2026-11-11 owner 决定）**：未连接时右上角只有「连接钱包」，左侧社区标识是移动端唯一社区名；连上后（含错网络）左侧标识隐藏，社区名由右上角药丸的 chip 承载。桌面端仍由左侧栏顶部字标承载，二级页与占位页由标题承载。左侧标识是文字标签，不是第二个首页链接；不新增第二处社区名或第二个连接入口。
- 返回：有历史 → `back`；无历史（直接打开深链）→ 回首页。始终有返回，深链不产生无出口页面。
- 页内标题只描述页面，不重复社区名；社区名在 chip 里。避免「铸造身份 NFT · FOO」这种双标题。「铸造身份 NFT」正好 8 个字符（4 个汉字 + 空格 + 3 个拉丁字母），390 px 页头实测不截断。
- **社区名 = `symbol()`；`name()` 只用于技术详情/调试信息，不进主界面。** 只要界面出现「当前社区的名字」——桌面侧栏品牌行、右上角社区 chip、含社区名的页面标题、任何元信息行——一律渲染链上 `symbol()`（如 `TestLOVE20`）。没有选中/未知社区时，这些位置回退到协议标签「LOVE20协议」——它命名的是协议，不是一个代币社区；LOVE20 社区被选中时，社区名就是它自己的 `symbol()`「LOVE20」。页内标题原则上仍不重复社区名（见上一条）；若某个页内标题确实带上社区，用 `symbol()`。`name()` 是形如 `<子币 symbol>@<父币 symbol>` 的复合技术标识（如 `TestLOVE20@TestWETH`），不是显示名，不得用作社区名。
- **冷启动字标不闪协议名（QA 2026-11-14 G8）**：URL 没有 `?symbol=` 的首屏，左侧字标（移动端页头标识、桌面侧栏品牌行）在 `symbol()` 读回前**不渲染**，等链上社区名到手才出现——不先渲染「LOVE20协议」再换成社区名。协议标签仍只是「未知/未解析到社区」的稳定兜底：未知 symbol 等已定论的状态照旧回退「LOVE20协议」，产品语义不变。浏览器标签页标题不受此规则影响。
- **浏览器标签页标题**：有当前社区时 `<页面> · <社区 symbol>`；没有选中/未知社区时只写「LOVE20协议」。社区名同样取 `symbol()`，不用 `name()`。
- 药丸在手机与桌面位置相同（右上角），不做第二处连接入口；移动端社区名只由未连接时的左侧标识或连上后的药丸 chip 承载。

### 1.4 右上角连接药丸

一个容器、三种状态、两个触发区（照 TKM，但不放主题与锚定；主题是独立页面，见 §3.9）：

| 状态 | 外观与文案 |
|---|---|
| 未连接 | 单个按钮「连接钱包」，点击直接 `eth_requestAccounts`；进行中「连接中…」；点击后若 3 秒内仍无注入钱包 → 打开 §4.6 兜底抽屉（不显示死按钮「检测钱包中…」） |
| 链不对 | 红色描边按钮「网络不对，点此切换」→「切换中…」；`wallet_switchEthereumChain`，4902 时 `wallet_addEthereumChain`（参数来自环境包），成功自动重连 |
| 已连接 | `[SYMBOL ▾] │ [0x1234…abcd / 身份 NFT 名 ⌄]`；两区各自可点，互不触发 |

- 左触发区（chip）：`max-w-[96px]` `truncate`，`font-mono text-[13px]`；二级页且视口 <480px 时收成 28px 首字符圆徽，其余情况显示完整 chip；两种形态都可点。chip 文案一律为当前社区 `symbol()`（§2.1），不是 `name()`；没有选中/解析到社区时，chip 文案回退到协议标签「LOVE20协议」（§1.3）。
- 右触发区：上行地址（mono 13，缩写 4+4），下行身份 NFT 名或「未选择身份 NFT」（11px 灰）；有进行中交易时右上角 6px 琥珀点（§4.2）。药丸本身是「打开菜单」的按钮，**不内嵌第二个复制按钮**（按钮不能嵌套）；钱包地址的点击复制在钱包弹层第一行（§1.6），点药丸即到。
- 弹层形态：`<md` 为底部抽屉（抓手 + 安全区 + 最大高 70dvh，可滚动）；`≥md` 为锚定弹层（代币 240px，钱包 288px，右对齐）。同一时刻只开一个。
- **关闭后焦点回到触发区（QA 2026-11-14 D-1）**：两个弹层无论用 Esc、右上角 ✕、点遮罩还是选中结果关闭，焦点都回到打开它的那个药丸触发区（WAI-ARIA dialog 惯例），不落到 `body`；键盘/读屏用户下一次 Tab 从触发点继续，而不是从页面顶部重新开始。实现：`MenuLayer` 在 Radix `onCloseAutoFocus` 里 `preventDefault()` 并手动 focus anchor。
- 未连接时整个药丸就是一个「连接钱包」按钮：不渲染两个触发区，也不做灰掉的假入口。

### 1.5 左弹层：代币社区（行项完整顺序）

**symbol 搜索（owner 2026-11-14）**：弹层顶部一个输入框「输入代币 symbol」。输入后按 `Launch.tokenAddressBySymbol` 做**精确匹配**、按已加载的 `Launch.tokens` 目录做**前缀匹配**，结果行点一下直接切换并关闭弹层（复用兑换页同一个 Launch 目录；当前项带「当前」徽标，精确项标「精确匹配」）；回车取第一条。查找中 / 没有找到 / 列表读取失败各有明确一行，不出现空白框。输入为空时下面仍是「最近访问」，清空即恢复；「最近访问」语义不变。

1. 分组标签「最近访问」。
2. 最近行（最多 4）：symbol（mono）+ 当前项「当前」徽标；点行即切换。
3. 空态：「还没有访问过其他社区」。
4. 分隔线。
5. 「父币」+ 右侧父币 symbol；根代币时整行禁用，右侧写「{根父币 symbol}（根）」（本地为 `TestWETH`）并附小字「当前已是根代币」。
6. 「子币」+ 右侧「{N} 个」+ chevron → 子币抽屉：`childTokens(parentTokenAddress, offset, 20, false)` 分页，「加载更多」，空态「这个社区还没有子币」。
7. 分隔线。
8. 「复制本页链接」（分享 / 移动端兜底要用）。

**没有**：锚定（pin）、「其他子币」二级入口、「代币信息」页、地址与复制。层级最多两层（弹层 → 子币抽屉）。

### 1.6 右弹层：钱包与身份 NFT（行项完整顺序）

1. 「钱包地址」+ 完整地址（`font-mono text-xs break-all`，**整段地址本身可点击复制**，走 §4.7 的全局地址组件：点击后 2 秒「已复制」，失败写「复制失败，请手动选中地址」，`title` 为完整地址）。
2. 分隔线。
3. 身份行（整行可点 → 我的 NFT）：有身份 = 名称 + `#{memberId}` + 右侧「查看」；已连接但未选 = 「还没有选择身份 NFT」+「去选择」；钱包无 NFT = 「你还没有身份 NFT」+「去铸造」。
   - **身份 NFT 行必须与校验状态一致；未校验时不得显示确定信息，也不得给出前往 NFT 页的入口。** 行内容只取 `useMemberIdentity()` 的 `status`（与右上角药丸同一事实源，ADR-0003）：
     | `status` | 行文案 | 动作 |
     |---|---|---|
     | `loading` | 「读取中…」 | 无（整行不可点，不显示编号） |
     | `error` | 「身份 NFT 暂时读不到」+ 一行说明 | 无（不显示「查看」；弹层没有重试模式，因此不新增按钮） |
     | `unconfigured` | 「这个环境还没有部署身份 NFT 合约」 | 无 |
     | `empty` | 无身份行（同 §1.6 第 3 条） | 「去铸造」 |
     | `needs-selection` | 「还没有选择身份 NFT」 | 「去选择」 |
     | `ready` | 名称 + `#{memberId}` | 「查看」 |
   - 缓存的选择不是事实：`loading` / `error` / `unconfigured` 时即使本地存有 tokenId，也不得渲染名称、`#id` 或「查看」入口（否则与药丸的「—」矛盾，且入口只会落到读不到数据的页面）。
4. 「LOVE20」余额（按 `decimals()` 展示 2 位，精确值）+ 「BNB」余额（4 位）+ 小字「BNB 用于支付网络手续费」。
5. 分隔线。
6. 「进行中的操作 {n}」（仅有任务时出现）→ 任务抽屉（§4.2）。
7. 「合约地址」→ 弹层：链 ID、LOVE20、MemberNFT、Airdrop、Router、交易对地址 + 区块浏览器链接 + 逐项复制（信任信号，B-5）。
8. 分隔线。
9. 「断开连接」（危险色）。
10. 页脚小字：「当前身份 NFT 保存在这台设备；换浏览器需要重新选择。」

**没有**：主题切换（主题不放在钱包弹层，见 §3.9「主题」独立页）、网络选择器、ENS、头像、切换钱包地址列表（换地址 = 断开再连）。

## §2 代币社区上下文

### 2.1 唯一事实源

- `?symbol=` 是当前社区的唯一事实源。**不持久化「当前代币」**（与 TKM 的 `localStorage._currentToken` 相反）；刷新、分享、返回都只认 URL。
- `?from` / `?to` 是兑换页自己的兑换对参数（§3.5），与 `?symbol=` 并行：切换社区不改写 from/to，切换 from/to 也不改写 `?symbol=`。
- 缺省或空：读环境包 `firstTokenAddress` 的 `symbol()` 后 `history.replaceState` 补上 `?symbol=`，不新增历史记录。
- 写入 URL 的 symbol 永远来自链上 `symbol()`（如 dev 链的 `TestLOVE20`），不接受用户手输；用户手改 URL 走 §2.5。
- **社区名 = `symbol()`；`name()` 只用于技术详情/调试信息，不进主界面。** 桌面侧栏品牌行、右上角 chip、含社区名的页面标题与元信息行都渲染 `symbol()`（如 `TestLOVE20`），不渲染 `name()`；没有选中/解析到社区时回退到协议标签「LOVE20协议」——它命名协议，不是代币社区。LOVE20 社区被选中时，社区名就是它自己的 `symbol()`「LOVE20」；其他社区则用各自的 `symbol()`。`name()` 是 `<子币 symbol>@<父币 symbol>` 的复合技术标识（如 `TestLOVE20@TestWETH`），不是显示名。
- 解析：`Launch.tokenAddressBySymbol(symbol)`；返回 `0x0` 即不存在。解析成功后保留其余 query（如 `?tx=`）。

### 2.2 切换判定表

| 场景 | 行为 |
|---|---|
| 首页 / 我的 NFT / 铸造身份 NFT / 空投铸造 / 兑换代币 / 应用 | 原地 `replace` 当前路径 + 新 `?symbol=`，保留其他 query，不整页刷新 |
| 占位页（治理 / 行动 / 我的；`/group` 旧深链） | 同上；URL 保持可分享，页面内容不变 |
| 未知路由 | `replace` 首页 + 新 symbol |
| 目标是当前社区 | 关闭弹层，不发任何请求 |
| 有 pending 交易 | 允许切换；任务继续，头部下方「进行中的操作」条保留，可回到原页看收据 |
| 页面正处于报价 / 输入 | 中止在途请求；兑换页保留 `from`/`to` 与输入金额（`?symbol=` 与兑换方向相互独立），报价按新区块/倒计时重取；其他页清空金额输入并回骨架（不同币价格不可复用） |
| 正处于收据态 | 允许切换；先提示「上一笔交易已经上链，收据仍可在『进行中的操作』里查看」 |

### 2.3 最近访问

- 键：`love20:v1:<chainId>:<launchAddress>:<wallet>:recentCommunities`（统一缓存封装，组件内禁止裸用 `localStorage`）。
- 值：`[{ symbol, address, at }]`；**上限 4**、按 `address` 去重、最新在前、排除当前项；解析成功后写入，切换时 merge 并置顶。
- 脏数据 / 反序列化失败 → 清空该键自身，不阻塞首屏。未连接时不读写（与 ADR-0003「未连接时代币面板不可用」一致）。
- **symbol 搜索直接切换**（§1.5）：命中的社区走同一个 `switchSymbol` → `?symbol=` replace + 写入最近访问，不新增持久化键、不新增第二套「当前社区」。

### 2.4 切换后重取 / 不重取

| 立即重取（query key 含 `tokenAddress`） | 不重取 |
|---|---|
| `symbol()` / `decimals()`（`name()` 仅在技术详情/调试需要时读取，不参与显示）、`parentToken()`、`childTokens()` 总数、`factory.getPair()` 与 `getReserves()`、报价、当前币余额 | 钱包与链、身份 NFT 列表与当前身份 NFT、LOVE20 余额、MemberNFT 铸造报价（按首币计价，与社区无关）、空投资格（空投代币固定为首币） |

### 2.5 错误页

- **symbol 不存在**：标题「没有找到这个代币社区」+ 原样展示 `?symbol=FOO`（mono）+ 「链接里的代币符号可能拼错了，或者这个代币还没发射。」主 CTA「回到首币社区」（replace 首币）；次入口：最近访问（最多 4 条，直接切换）；底部文字链「复制当前链接」。
- **链上读取失败**（不是找不到）：标题「暂时读不到链上数据」+ 「网络可能不稳，你的资产没有变化。」+ 主 CTA「重试」+ 次「回首页」；保留上次成功的数据并标注「上次更新于 X 分钟前」，不把旧数据当新数据。
- Launch 地址缺失属于构建期错误，不出现在界面。

## §3 八个页面

> 通用：未连接时页面不跳转，页内给「连接钱包」；链不对由外壳拦截（§1.4）：页头药丸是唯一的切换控件，三个任务页的页内卡只保留一句说明 + 「回首页」，不再放第二个切换按钮（§0.7：回首页仍是出口，不构成死路）。所有金额读取中一律骨架，不渲染 `0`。收据见 §4.3。**下文「LOVE20」指首币，界面一律渲染链上 `symbol()`（dev 链为 `TestLOVE20`）。** 同理，下文出现的「BNB」是 BSC 生产部署的原生币示例，界面一律渲染环境包 `nativeCurrency.symbol`（本地 anvil 为 `ETH`，BSC 为 `BNB`），不写死字符串。

页面清单：§3.1 首页 · §3.2 我的 NFT · §3.3 铸造身份 NFT · §3.4 空投铸造 · §3.5 兑换代币 · §3.6 应用 · §3.7 我的 · §3.8 关于 · §3.9 主题。

### 3.1 首页

**用户一句话目标**：打开就看到问候和「有没有需要我处理的事」；没有就保持干净。
**定位（2026-11-11 / 2026-11-12 owner 决定）**：首页是**问候 + 提醒流**，不是导航页。导航入口在「应用」目录（§3.6）；余额与账户信息在「我的」（§3.7），身份 NFT 的完整信息在「我的 NFT」（§3.2），首页只保留一句问候。没有重要信息或事项需要提醒时，首页就是一句问候，没有任何填充句，也没有页脚。
**进入条件与前置**：可未连接浏览；`?symbol=` 缺省补首币；身份取自本地选择并已按 `ownerOf` 校验。空投资格来自快照懒加载 chunk（见下），**不进入首屏包，也不阻塞问候与无身份提醒**。

**区块顺序（自上而下，每一块都条件渲染）**
1. **未连接 → 连接入口** — 说明「一个钱包可以拥有多个身份 NFT，身份 NFT 才是参与凭证。」+「连接钱包」（与右上角药丸是同一个连接动作与状态，不新增第二套连接入口）。
2. **问候（常驻，页面 `h1`）** — 单行、`truncate`、**不是链接**。连接且有当前身份 NFT → 「你好，{memberName}」；连接但无身份 NFT、持有但未选择、读取中 → 「你好」；未连接 → 「你好」。问候不显示余额、不显示 `#memberId`；余额详情在「我的」（§3.7），身份 NFT 详情在「我的 NFT」（§3.2）。
3. **提醒卡（按固定顺序，仅适用时出现）**
   - **无身份 NFT**：「你还没有身份 NFT」+「铸造身份 NFT」→ `/mint`。
   - **持有身份 NFT 但未选择**：「你还没有选择身份 NFT」+「选择身份 NFT」→ `/my-nft`（保留当前 `?symbol=`）。与「无身份 NFT」互斥，固定在它之后、空投卡之前。
   - **身份读取中**：在提醒卡位置渲染紧凑骨架（短句「读取身份 NFT 中…」+ 两行骨架），不显示长文案，也不显示会失败的 CTA；避免首页从「只有问候」闪成提醒卡。
   - **身份读取失败**：「身份 NFT 暂时读不到」+ 一行原因「网络可能不稳，你的身份 NFT 没有变化。」+「重试」；「重试」调用身份读取模型的 `refetch`，真的重新读取。RPC / 本地链不可达时也落到这里，**页面不得静默只剩问候**。
   - **环境未部署身份 NFT 合约**：「这个环境还没有部署身份 NFT 合约」+「这里暂时不能铸造身份 NFT。」；不给「铸造身份 NFT」等会失败的 CTA，也不给「重试」（重试不能部署合约）。同一句在 `/my-nft` 复用。
   - **有空投资格且未铸造**：「你有空投资格，可铸造 {X} {symbol}」+「空投铸造」→ `/airdrop`（保留当前 `?symbol=`）。`X` 来自 `claimableAmount`；金额或首币 symbol/decimals 读不到时**省略金额分句**（只写「你有空投资格」），绝不把「—」写进句子里。
   - **有未确认交易**：「1 笔交易还没确认」+「查看」。**M0 未实现**：今天三个写流程各自持久化自己的记录（`mintTask` / `airdropClaim` / `swapReceipt`），没有统一的 pending-tx 读取模型；在出现单一持久化 pending 辅助函数前，这张卡不渲染，也不伪造数量（见 `home-page.tsx` 的 TODO）。
4. **没有适用项** — 只有问候。**不写**「现在没有需要你处理的事。」或任何等价占位句；没有提醒卡，也没有实心按钮。
5. **没有页脚**（owner 2026-11-12）— 首页不再渲染「开源文档」链接，也不再有「技术详情」折叠。开源文档、版本号、链 ID / RPC 与全部合约地址都在 `/about`（§3.8）；首页不再重复这套样板。

**已移除（2026-11-11 / 2026-11-12）**：三个常驻入口行（我的 NFT / 空投铸造 / 兑换代币，已在 `/apps`）；首页细行与其上的余额（问候取代；余额去 §3.7）；独立的身份卡；旧的「现在没有需要你处理的事。」空态句；页脚「开源文档」链接与「技术详情」折叠（2026-11-12，改由 `/about` 承担）。首页不再按 LOVE20 余额不足追加提醒，也不出现「无需操作」静默态之外的额外说明。

**快照加载与提醒卡显隐**
- 空投快照 JSON 是**首屏渲染之后才 `import()` 的懒加载 chunk**：问候与无身份提醒先可用，快照数据就绪后空投提醒卡原地出现；**不预留占位、不显示骨架、不阻塞问候**。
- 快照未就绪 → 不显示空投提醒卡；钱包不满足资格 → 不显示卡，也不写「无资格」。
- chunk 读取失败 → 不显示空投提醒卡；首页保持干净（不额外造一行错误文案）。

**实心按钮**：一屏最多一个实心按钮。只有第一张出现的提醒卡提供它：无身份卡与「未选择身份 NFT」卡互斥、都在空投卡之前，所以有任一张时它用实心、空投卡用描边；只有空投卡时它是实心。未连接时实心按钮是「连接钱包」。问候永远不是实心按钮。

**状态与错误**

| 身份状态 | 首页表现（问候 `h1` 常驻） |
| --- | --- |
| `disconnected` | 连接入口卡 +「你好」；没有身份提醒卡 |
| `loading`（已连接） | 「读取身份 NFT 中…」+ 紧凑骨架卡；无 CTA |
| `error`（已连接） | 「身份 NFT 暂时读不到」+ 一行原因 +「重试」（`refetch`）；RPC 不可达也走这里 |
| `unconfigured`（已连接） | 「这个环境还没有部署身份 NFT 合约」+「这里暂时不能铸造身份 NFT。」；无 CTA |
| `empty` | 「你还没有身份 NFT」+「铸造身份 NFT」→ `/mint` |
| `needs-selection` | 「你还没有选择身份 NFT」+「选择身份 NFT」→ `/my-nft` |
| `ready` | 「你好，{memberName}」；没有身份提醒卡 |

- **问候只在 `ready`（`ownerOf` 已校验）时点出身份名称**：其余状态（含本地缓存了 tokenId 但正在读取、读取失败、未部署、无身份、未选择、未连接）一律「你好」——缓存的选择不是事实，与 §1.4 药丸/钱包弹层的规则一致，避免首页点名而药丸显示「—」。
- **「首页在任何身份读取状态下都不允许只显示问候语」**：`loading` / `error` / `unconfigured` 都必须给出骨架、原因或环境说明；只有 `ready` 且没有提醒事项时，首页才允许只保留问候。
- 任何未知值用「—」；身份读取错误在首页就地说明并重试，其他页面的重试入口仍留在「我的」与各任务页。

**验收**
- 未连接打开：左侧社区标识可见；看到问候 `h1`「你好」与「连接钱包」；不再有 `/me` 细行。
- 连接后有身份 NFT、无事可做：左上标识消失；`h1` 显示「你好，{memberName}」；首页不显示余额；页面只有问候，实心按钮 = 0，没有页脚，也没有「现在没有需要你处理的事。」。
- 连接后无身份 NFT：`h1` 为「你好」；出现「你还没有身份 NFT」+「铸造身份 NFT」，点击进入 `/mint`。
- 连接后身份读取中：`h1` 为「你好」；提醒卡位置出现骨架卡「读取身份 NFT 中…」，页面不是裸问候。
- 连接后 RPC / 本地链不可达：`h1` 为「你好」；出现「身份 NFT 暂时读不到」+ 一行原因 +「重试」；点「重试」会重新读取，恢复后出现正常提醒卡。
- 连接后环境未部署身份 NFT 合约：出现「这个环境还没有部署身份 NFT 合约」+「这里暂时不能铸造身份 NFT。」；不出现「铸造身份 NFT」或「重试」。
- 连接后持有身份 NFT 但未选择：`h1` 为「你好」；出现「你还没有选择身份 NFT」+「选择身份 NFT」，点击进入 `/my-nft` 并保留 `?symbol=`；此时不出现无身份卡。
- 有资格：出现「你有空投资格，可铸造 {X} {symbol}」+「空投铸造」，点击进入 `/airdrop` 并保留 `?symbol=`；金额未知时句子里没有「—」。
- 无资格：空投提醒卡不出现，首页只剩问候。
- 身份 NFT 被转走后刷新：中性提示语义由「我的」承担；首页问候回落到「你好」，并出现无身份提醒，不出现指向旧身份的操作。
- 快照 chunk 晚于首屏：问候先可用，提醒卡在数据就绪后出现，不遮挡、不阻塞问候。
- 任一屏最多一个实心按钮；390px 下问候保持单行并被截断，不换行。

### 3.2 我的 NFT

**用户一句话目标**：看清我有几个身份、现在用哪个，并立即换一个。
**进入条件与前置**：需连接（页内连接）；从「应用」目录或钱包弹层身份行进入。身份 NFT 列表 = `balanceOf(wallet)` + `tokenOfOwnerByIndex(wallet, i)`（Multicall3 批量）+ `memberName(tokenId)`。

**布局（参照参考实现的同页，只取结构）**
- `<md`：**卡片行**，一个身份 NFT 一张卡，卡内依次是 `NFT #memberId`、`memberName`、当前身份 NFT pill 与操作。
- `≥md`：**表格**，列为 NFT 编号 / 名称 / 操作。
- 两种形态共用同一排序：**当前身份 NFT 第一，其余按 `memberId` 升序**；当前行整行着色（accent tint）并带「当前」pill。
- 持有数量始终显示真实值，**不因 N ≤ 3 隐藏**；写操作进行中**不禁用整张表**（见状态）。

**区块顺序**
1. **摘要条** — 只写「持有 {N} 个身份 NFT」，不重复当前身份 NFT 名字；空态不渲染摘要条（空态卡已给结论）。数据：`balanceOf`。
2. **说明段（两行内）** — 「每个身份 NFT 都是一个独立的身份，可以在多个社区使用。换钱包不会改身份 NFT，只有转让才换控制者。」
3. **身份 NFT 列表** — 卡片行（<md）/ 表格（≥md）；字段只有 `NFT #memberId`、`memberName`、当前 pill、操作。`tokenURI` 返回空字符串，**不渲染图片、不请求任何图片源**。
4. **行内操作** —
   - 「使用此身份 NFT」：**纯本地选择**，写入本地当前身份 NFT 并立即更新页面，**不发起链上交易、不签名、不等待**；成功后该行置顶并着色。当前行只保留「当前」pill + 行底色 + 一个禁用的行内按钮（不再写一遍「当前身份 NFT」文字）。
   - 「转让」：打开转让抽屉（收款人三选一：**按地址 / 按身份 NFT ID / 按身份 NFT 名字**，输入框左侧的小下拉与代币转账页是同一个共享控件 `shared/ui/identity-input-mode`，校验同源 `shared/lib/identity-input`，两页文案/键盘/错误一致），警告「转让会改变这个身份 NFT 的控制者。身份 NFT 的历史与质押仍留在身份 NFT 上，随身份 NFT 一起换控制者、不单独转移。」（owner 2026-11-14：不再写「不可撤销」这类冗余提示）确认后 `safeTransferFrom(你, 对方, memberId)`；成功的收据写「已转让给 0x…」；若转的是当前身份 NFT，同时清除本地选择——还有其他身份就回到「未选择身份 NFT」，没有则回落到无身份形态。
     - **按地址**：校验 `0x` + 40 位、非零、非自己。
     - **按身份 NFT ID**：`#id` → `ownerOf(id)`；不存在 / 属于自己 / 读取失败各有明确文案与重试；解析出的 owner 地址可点击复制（§4.7）。
     - **按身份 NFT 名字**（owner 2026-11-12，防名称混淆）：用合约 O(1) 的 `memberId(name)` 直接解析（合约内部自行做 `normalizeName` 规范化，输入原样传入）；返回 0 或调用 revert 即「这个身份 NFT 不存在」。名称→id 结果在本会话内缓存（缓存键按规范化名，大小写不同不重复查），不轮询；持有人始终重新读 `ownerOf`，并读一次 `memberName(id)` 在确认区展示链上规范名。**解析成功后必须二次确认**：显示「名称「{name}」→ 身份 NFT #{id}」「收款人 {短地址}」与「名称相近或看起来相同的身份 NFT 可能存在，名称不是唯一依据」；用户勾选「我确认 #{id} 就是正确的身份 NFT」之前，「转让」保持禁用。找不到 / 属于自己 / 解析失败（可重试）均是具体文案，不用泛化错误。
5. **底部** — 「铸造新身份 NFT」（描边按钮）。不再有「回首页」文字链（owner 2026-11-14；回首页交给底部标签栏与页头返回），也不再有不折叠的高级区：MemberNFT 合约地址在 `/about`（§3.8）。

### 3.3 铸造身份 NFT

**用户一句话目标**：用一个名字铸出身份 NFT，事前知道要花多少、还差什么、下一步去哪。

**区块顺序**
1. **名称输入** — 标签「给身份 NFT 起个名字」，不再放同字占位符；上限字节数由 `MAX_NAME_LENGTH()` 读取（不硬编码；按 UTF-8 字节校验，不用 `maxLength`，否则中文会被截错）；下方实时「{n}/{MAX_NAME_LENGTH} 字节」（dev 参数为 `32`）+ 一行规则「中文 3 字节、英文与数字 1 字节；名字越短，价格越高」。**dev / test 变体**在规则行下方再显示命名约束「名称必须以 Test 开头」（`T` 大小写敏感），并做行内校验：不以 `Test` 开头时显示一行原因「为了让测试身份 NFT 和真实身份 NFT 一眼能分开。」并禁用提交（阻断式，不是警告）；同时检查行改写为「✗ 还没加 Test 前缀」，避免和常驻规则行逐字重复；判断依据是构建变体（环境包），不是支付代币 `symbol()` 是否以 `Test` 开头。**prod 变体没有这条约束，也不显示该行**。字节上限在三个变体都是完整的 `MAX_NAME_LENGTH()`，不存在 `-4` 调整。

4. **资金分支卡（仅不足时出现）** — 见下。

6. **收据** — 成功后整页替换为收据（§4.3）：`#{memberId}` + 链上 `memberName`、实际支付（来自 `MemberMinted.cost`）、哈希、下一步。

### 3.4 空投铸造

**用户一句话目标**：三十秒内知道自己有没有、能铸造多少、现在能不能铸造，并一次完成。
**进入条件与前置**：需连接；S6 已铸造态的金额必须能在**任意设备**上显示（不得依赖本机缓存，见 [CI-014](../contract-issues/014-airdrop-claimed-amount-not-readable.md)）；资格来自 Merkle 快照（share + proof），快照来源按代币分两条路径（见下），文档按需懒加载、**不进首屏包**。空投代币固定为首币 LOVE20，**与当前社区无关**，切换社区不改变本页内容。页头标题只写「空投铸造」，**不设副标题或解释句**；「本次空投：LOVE20」是状态卡首行的一行元信息，快照机制收进「规则」折叠。界面任何位置都不写「领取」；合约动作 `claim` 只保留在代码、合约与术语表里。

**数据源与快照（2026-11-12 起）**
- 合约是 `AirdropDistributor`（地址簿 `airdropDistributor`，`/about` 标签「空投分发器」）。`claim(tokenAddress, share, proof)` 只付给 `msg.sender`，**没有 account 参数**；账户永远是当前连接的钱包。
- 报价与状态：`claimableAmount(token, account, share, proof)`、`isClaimed(token, account)`、`claimedAmount(token, account)`（一次 `eth_call`，不再扫事件）。每 token 的根、轮次、份额与池额全部来自**一次** `airdropInfo(token)`：`merkleRoot`、`claimableFromRound`、`snapshotUri`、`totalClaimedShare`、`totalRemainingShare`、`totalClaimedAmount`、`remainingAmount`；`TOTAL_SHARE()` 仍是链上常量。
- 快照来源：**创世代币**的 `airdropInfo(genesisToken).snapshotUri` 由合约保证永久为空（[CI-017](../contract-issues/017-genesis-snapshot-uri-locked.md)），所以用构建内置的 `public/airdrop/<variant>.json`；使用前必须核对文档 `merkleRoot` 与链上 `airdropInfo(genesisToken).merkleRoot` **完全相等**，不一致按 S2「空投资格暂时读不到」+「重试」处理，绝不显示数字。空 URI 对创世**不是错误**。
- **后续 Launch 的代币**：沿用同一套代码，优先从链上 `airdropInfo(token).snapshotUri` 拉取 JSON（仅接受 http(s)），同样先用 `airdropInfo(token).merkleRoot` 校验 root；失败态可重试。
- **轮次门槛**：`Phase.currentPhase() < airdropInfo(token).claimableFromRound` 时 `claim` 会回滚 `ClaimRoundNotReached`。此时页面显示独立门槛态（见 S5-G），不显示金额、不出现「空投铸造」。等待时间只用「剩余区块 × 观测秒/块」估算成「约 X 分钟」（`observations(0,2,true)`，不足两条时退回 `TARGET_SECONDS / currentPhaseBlocks`），**不得显示绝对时间戳**。

**区块顺序**
1. **状态与金额卡** — 七态之一（见下）或轮次门槛态；首行元信息「本次空投：LOVE20」；金额行「预计可得 {X} LOVE20」+ 小字「按铸造时的池子余额与剩余份额计算，别人铸造后金额会变。」数据：`claimableAmount(LOVE20, wallet, share, proof)`、`airdropInfo(LOVE20).remainingAmount`、`airdropInfo(LOVE20).claimableFromRound`。
2. **主按钮区** — 仅「可铸造」态出现「空投铸造」；轮次门槛态没有任何铸造 CTA。
3. **规则折叠** — 「首币与当前社区无关」「快照来源」；空投合约地址在 `/about`（§3.8），折叠里不再重复；「为什么金额会变」已在金额卡内联小字里说过，折叠不再重复。
4. **收据** — 铸造成功后整页替换（§4.3）。

**状态**：S0 未连接 / S1 加载 / S2 错误 / S3 空（无资格）/ S4 暂不可铸造 / S5 可铸造 / S6 已铸造；S5 之前另有门槛态 **S5-G 轮次未到**（不改变 S0–S6 的编号：轮次到了就进入 S5）。pending 走 §4.2（铸造中 → 已上链），成功即 S6 收据（§4.3），失败回到 S5 + 错误卡。

- 内置创世快照的 root 与链上不一致时，页面显示「空投资格暂时读不到」+「重试」，**不显示任何份额或金额**；创世 URI 为空本身不产生错误。

### 3.5 兑换代币

**用户一句话目标**：把任意一种代币换成另一种，事前知道会走哪条路径、能拿到多少、最少拿到多少。
**进入条件与前置**：需连接；**任意代币 ↔ 任意代币**，包括链原生币、包装原生币与任意已发现的社区代币，不再限定原生币买入。代币集合只来自链上与环境包：社区代币用 `Launch.tokens(offset, limit, reverse)` 分页发现，用 `Launch.parentToken(token)` / `Launch.childTokens(parent, offset, 20, reverse)` 还原父子树，用 `Launch.tokenAddressBySymbol(symbol)` 做符号精确查找；除环境包提供的原生币与包装原生币两个条目外，**不维护任何硬编码代币清单**。`?from=<symbol>&to=<symbol>` 决定兑换对并写入 URL，可深链分享；`?symbol=` 仍是当前社区上下文，与 from/to 相互独立。缺省时 `from` 取环境包原生币、`to` 取当前社区代币（`?symbol=` 解析结果，解析不到回退首币），解析完成后把这两个缺省值 `replace` 进 URL。原生币用环境包配置的符号寻址（本地 anvil 为 `ETH`，BSC 为 `BNB`），不写死「BNB」。from/to 任一未知、相同或解析不到 → 中性错误态（见下），不崩溃、不白屏。

**区块顺序**
1. **兑换卡（顶部，两行）** —
   - 「从」：金额输入 + 代币选择器（显示 `symbol()`）+ 当前代币余额 + 「全部」快捷键；输入原生币时「全部」按「余额 − 预留网络手续费」计算并标注「约」。
   - 中间 ⇅ 方向按钮：交换 from/to 并重报价；原生币与包装原生币互逆时仍用同一按钮。
   - 「到」：只读金额（标签「预计可得」）+ 代币选择器（只显示 `symbol()`）+ **到账代币余额**（owner 2026-11-14：「到」这个代币也应该显示余额）。余额行与「从」侧同一规则、同一个 `swapBalanceLine`：`余额 {symbol} {amount}`，最多 6 位小数（截断不四舍五入）、精度标签 18 位不写、非 18 位（含 0/6/8/24…）在余额下方单独一行写「精度 {n} 位」、未知写「—」、0 正常写 `0`；读取中显示骨架，读取失败写「读不到余额」。
   两个选择器打开同一个「选择代币」抽屉：分组「原生币 / 包装原生币 / 社区代币」；社区代币按 `Launch.tokens` 分页（每页 20，「加载更多」），顶部搜索框用 `Launch.tokenAddressBySymbol` 精确匹配 symbol。选中即用 `replace` 写回 `?from`/`?to`，保留 `?symbol=` 与其他 query，不新增历史记录。
   **两个选择器互斥（owner 2026-11-14）**：选择器不提供另一侧当前已选的代币 —— 列表里没有、搜索也查不到，列表顶部写一行「另一侧已选 {symbol}，这里不能再选；想换过来请用中间的交换方向。」。若程序化路径（深链重写、恢复动作）仍选到重复代币，按「交换方向」处理：`?from`/`?to` 直接互换并 `replace` 写回。因此正常选择路径永远不会进入「这个兑换对不可用」态；只有深链本身写了相同 symbol 时才保留中性错误态。
2. **信息块（全页唯一）** — 主信息三行：
   - 「1 {FROM} ≈ {rate} {TO}」；
   - 「路径 {A} → {B} → {C}」（低权重、单行，最多 3 跳；即使只有 1 跳也显示，例如 `TestWETH → TestLOVE20`）；
   - 「最少到账 {minOut} {TO}」+「最多可接受的价格变化 [0.1% / 0.5% / 1.0% / 自定义]」（默认 0.5%）。
   以上为主信息；手续费率能读到才写「手续费率 {fee}%」，读不到只写「以链上费率为准」；价格影响 >1% 才显示「价格影响 约 {x}%」，读不到就不显示该行。任何情况下都不猜数字。
   报价状态：只显示剩余 `{n}s` 倒计时（同一行不再写「更新于 {n} 秒前」）；随新区块或 30 秒定时重报价。倒计时归零且新报价未返回时，标「报价已过期」并禁用主按钮，直到新报价返回。
3. **授权步骤（兑换卡内部，ERC20 输入时）** — 金额行下方就是 `授权 {symbol}`（§4.1 全局文案）。授权确认后同一位置变只读的 `已授权`；已是长期授权则显示禁用的 `已长期授权`（无需操作）。原生币输入没有授权步骤。
4. **主按钮** — 一个主操作位「兑换」，在信息块之后；需要授权时禁用，授权确认后解锁。不再有吸底按钮栏，也不再有编号式「1 授权 / 2 兑换」。明细见「执行阶梯」。
5. **收据 / 错误卡** — 成功后整页替换为收据（§4.3）：实际到账金额从回执中交易对的 `Swap` 事件解析（按方向取 `amount0In/amount1In/amount0Out/amount1Out`），ERC20 输入另核对 `Transfer`，**不用报价当结果**；原生币 ↔ 包装原生币的收据取 `WETH9` 的 `Deposit`/`Withdrawal` 金额。失败卡保留 from/to 与金额，给「重新报价并重试」，说明「没有成交，只消耗了网络手续费」。不再有高级折叠：交易对与 Router 地址在 `/about`（§3.8）；价格保护参数与路径 / 最少到账仍留在上方信息块。

**路径解析**
- 交易对图是一棵以包装原生币为根的父子树：每个社区代币只与自己的父币有 Uniswap V2 交易对（`Launch` 建币时 `createPair(token, parent)`）。在 `factory.getPair(a, b)` 能确认的交易对图上找**最短路径**（通常就是 A 上溯到最近公共祖先再下行到 B）；相邻两枚代币必须 `factory.getPair(a, b) != 0x0` 且 `getReserves()` 两边储备都非零。原生币在路由里以包装原生币参与（`Router.WETH()`），界面显示仍写原生币符号。
- 最多 **3 跳**。例：`WBNB → 父币 → 子币`；本地为 `TestWETH → TestLOVE20`。无路径、超过 3 跳、或路径上任一交易对储备为零 → 该方向不可兑换，说明卡在哪一跳，给「换个代币」与「回首页」。
- 原生币 ↔ 包装原生币是 **1:1 包装/解包**，不经过交易对、无手续费与价格影响（`WETH9.deposit` / `withdraw`）；界面汇率行只写「1 X = 1 Y（包装/解包，不经过交易对）」，「无手续费」只由手续费行承担。界面仍用「兑换」按钮与同一套收据。

**报价与保护**
- 报价只调 `Router.getAmountsOut(amountIn, path)`，不在前端复刻 AMM 公式；提交前再读一次，用最新报价重算 `amountOutMin = quote × (1 − 容忍度)`（向下取整）。
- 「最多可接受的价格变化」默认 0.5%，可见档位 0.1% / 0.5% / 1.0% / 自定义；改变档位立即重算「最少到账」。自定义值限制在 0.01%–50%（超出给行内错误），不把「授权缓冲」当滑点。
- 价格影响用 `getReserves` 隐含的边际价与 `getAmountsOut` 成交均价之差估算；> 1% 时显示「价格影响 约 {x}%」，> 10% 时追加红色提示「这笔兑换会明显改变池子价格，继续前请确认。」与「继续」二次确认（提示里不再重复百分比）。≤1% 不显示这一行。
- **手续费率不写死**：从 `Stake` 合约读两个 1e18 定点参数 `SWAP_FEE_FOR_LP_RATIO` / `SWAP_FEE_FOR_PROTOCOL_RATIO`，费率 = 两者之和（合约构造时保证 `lp > proto`、`lp + proto < 1e18`）；能读到才显示「手续费率 {fee}%（已含在报价里）」，百分比 2 位小数、向下截断（本地 `3e15 + 0` → `0.30%`）。读不到（地址簿没有 Stake、getter 失败、参数违反合约不变量）不显示百分比，只写「以链上费率为准」。本地 anvil 为 0.30%、BSC PancakeSwap 为 0.25%，这两个数字只作为部署事实，不作为常量进入报价或计算；台账里「1e18 − lp − proto」是净比例（0.997），不是费率，见 `docs/product/three-line/swap-fee.md` §0.1。
- 报价随新区块或 30 秒定时刷新；信息块只显示倒计时（不再显示「更新于」）。倒计时归零即把报价标为「报价已过期」并禁用主按钮；新报价返回后恢复。失败可见重试，不静默用旧报价提交。

**执行阶梯**

| 输入 / 输出 | 授权 | 调用 |
|---|---|---|
| ERC20 → 任意 | 是：授权额 = 本次输入金额，精确到 wei，不加缓冲、不授权无限额 | `swapExactTokensForTokens`（ERC20 输出）或 `swapExactTokensForETH`（原生币输出） |
| 原生币 → ERC20 | 否：单按钮「兑换」 | `swapExactETHForTokens` |
| 原生币 ↔ 包装原生币 | 否 | `WETH9.deposit` / `withdraw`，1:1 |

- ERC20 输入且 allowance 不足：两段式「1 授权」→ 授权确认后停在本页，阶段 1 收成「✓ 已授权」，同位置变「2 兑换」或「兑换」；授权额精确等于 `amountIn`，不改写成报价或加缓冲。
- 授权与兑换的按钮文案走 §4.2 三态：`授权中…` → `确认中…` → 成功/失败；兑换同。原生币输入没有授权阶段。

**状态**
- 未连接：「连接钱包后兑换。」+「连接钱包」。
- 未配置（test/prod 空地址簿）：「这个环境还没有配置兑换。」+「回首页」；不发起任何链上请求，不崩溃。
- 加载：余额、路径与报价显示骨架，不渲染 `0`。
- 空输入：主按钮禁用，无报错。
- 报价中：主按钮禁用 + 金额骨架。
- 可兑换。
- 余额不足：「{FROM} 不够，还差约 {x}」；原生币输入同时提示需预留网络手续费。
- 池子为空（见下）。
- 无路径 / 超过 3 跳：「这个方向没有可用的兑换路径。」+「换个代币」+「回首页」。
- from/to 未知或相同：「这个兑换对不可用。」+「链接里的代币符号可能不存在，或者这个代币还没发射。」+「选择代币」+「回首页」。
- 报价失败：「价格暂时读不到。」+「重试」。
- 价格影响 > 10%：红色提示 + 需二次确认。
- 授权中 / 确认中 / 上链中 / 成功（收据）/ 失败（错误卡）。

**池子为空（本协议的真实默认态）**
发射代币时只 `createPair` 建池，不注入流动性，所以新社区大概率无储备。文案：标题「这个兑换对还没有可兑换的流动性。」+ 说明「发射代币时只创建了交易对，没有注入资金，所以现在换不了。」+ 主「换个代币」（打开代币抽屉）+ 次「回首页」+ 高级「查看交易对地址」。**不承诺通知，不出现「稍后重试」这种无信息的按钮。**

**主 CTA 与次要入口**
- 一个主操作位：「兑换」；需要授权时先完成卡内的 `授权 {symbol}`（§4.1），再点「兑换」。页面底部不再有「回首页」文字链；回首页交给底部标签栏与页头返回。
- 页面只有两个代币选择器、两个金额、一个主操作位、一个信息块；**不做订单簿、限价单、K 线或图表**。

**死路处理**：空池、无路径、from/to 无效、余额不足、报价失败、报价过期都有明确下一步；失败重试必须重新报价并刷新 `amountOutMin`；不出现只有一句话的终局。
**加载骨架**：输入框可先输入；选择器显示骨架；信息块 3 行灰条 + 按钮灰块；余额与报价就绪后原地替换，不整页 spinner。
**验收**
- 用户可以从任意已发现代币换到任意另一种（含原生币、包装原生币与社区代币），反向同样可用。
- 深链 `?from=ETH&to=TestLOVE20` 能直接打开并报价；`?symbol=` 切换社区不改变 from/to，也不清空金额。
- from/to 写错或指向不存在的 symbol 时，看到中性错误与「选择代币」，页面不白屏、不崩溃。
- 用户能看到路径（如 `TestWETH → TestLOVE20`）与「最少到账」，默认「最多可接受的价格变化」为 0.5%，改成 1.0% 后「最少到账」立刻变化。
- 报价倒计时归零后出现过期标记，主按钮禁用，直到新报价返回。
- ERC20 输入需要授权时：授权按钮在兑换卡金额行下方、文案 `授权 {symbol}`，兑换按钮在其后且禁用；授权额等于本次输入金额；原生币输入不出现授权步骤。已长期授权时按钮显示 `已长期授权` 且无需操作，兑换可直接进行。
- 池子为空时看到专门说明与「换个代币」「回首页」两条出路。
- 成功后显示的实际到账来自回执中交易对的 `Swap` 事件（原生币 ↔ 包装原生币取 `WETH9` 的 `Deposit`/`Withdrawal`），不是用报价当结果。

### 3.10 代币转账

**用户一句话目标**：把一种代币转给一个地址（或一个身份 NFT 的持有人），事前看清余额、金额与收款方，事后拿到可核对的回执。
**进入条件与前置**：从「应用」目录「代币」分类的「代币转账」行进入（`/transfer?symbol=`），也支持直接深链；目录条目 `requires: null`——普通转账只需要钱包，不依赖任何协议合约，所以任何地址簿状态下都可用。**必须连接钱包**；未连接显示「连接钱包后转账。」+ 连接按钮，网络不对显示一句「切换到这个应用使用的网络后再转账。」+ 回首页。页面标题「代币转账」。

**代币集合（只来自链上与环境包，不维护硬编码清单）**
- **原生币**（环境包符号，本地 `ETH`）；
- **社区代币**：与兑换页同一个 `Launch.tokens` 分页（每页 20 + 「加载更多」）与 `Launch.tokenAddressBySymbol` 精确查找；
- **包装原生币**：地址簿 `weth` 的 `symbol()/decimals()`；
- **LP 代币**：地址簿 `pair` 的 `symbol()/decimals()`（本地 `UNI-V2`）；
- **自定义 ERC20**：在代币抽屉底部输入 `0x` + 40 位地址 → 「添加代币」→ 先校验 bytecode，再读 `symbol()/decimals()`；合约不存在 / 读不到 → 人话错误（「这个地址上没有合约，不能作为代币。」/「读不到这个代币的名称或精度，暂时不能转账。」）且不产生代币条目。
选择器分组固定为 原生币 → 社区代币 → 包装原生币 → 流动性凭证 → 自定义代币；搜索按 `symbol()` 子串过滤 + 精确 symbol 查询。**精度只在 `decimals ≠ 18` 时显示**（「精度 {n} 位」）；没有社区代币时该分组显示「还没有发现社区代币。」，页面降级为原生币 + 自定义 ERC20，不白屏。

**区块顺序（一张卡片，owner 2026-11-14：先收款方，再代币数量）**
1. **收款方行** — 输入框左侧一个小下拉切换三种模式：「按地址」/「按身份 NFT ID」/「按身份 NFT 名字」。模式**显式决定**输入含义，不从文本猜。这个下拉+输入框是与「转让身份 NFT」抽屉**同一个共享控件**（`shared/ui/identity-input-mode` + `shared/lib/identity-input`）：两页的标签、占位符、键盘类型、按模式校验与错误文案完全一致，切模式会清空上一模式的解析结果与确认勾选。**按身份 NFT ID 与按名字的输入各存一份**：切到名字模式不会把 ID 模式下输入的 `#2` 当成名字去查（D6，2026-11-14），切回来也不丢已经输入的另一份文本；地址模式的输入同样独立保留。
   - 按地址：`0x` + 40 位、校验非零、非自己；错误文案分别是「收款地址格式不对，需要 0x 开头的 40 位地址。」/「收款地址不能是零地址。」/「不能转给自己。」。
   - 按身份 NFT ID：只收纯数字编号（可带 `#`，如 `#12`）；名字文本直接给人话错误「请输入身份 NFT 编号，例如 #12。」，不发起解析；解析复用「转让身份 NFT」的 `ownerOf(id)`。
   - 按身份 NFT 名字：一律走合约 `memberId(name)`，**纯数字名字不会被当成 ID**（防止有人注册了 `123456` 的名字而 ID 不是 `123456`）；解析后再读 `memberName(id)` 展示链上规范名。
   - 两种身份模式解析成功后显示「身份 NFT #{id} {name}」+「收款人 0x…」（收款地址可点击复制，§4.7），并且必须勾选「我确认 #{id} 及上面的收款地址都正确」才能提交（名称可能混淆，ID + 地址是唯一依据）；该确认块与转让抽屉共用同一个展示组件。**ID 模式下 `memberName` 还没返回时，确认块不出现**（行内显示「正在读取身份名字…」），既不能勾选也不能提交——慢 RPC 下不允许在看不到规范名时确认（D7，2026-11-14）。
2. **代币数量行** — 第一行是**余额数字本身**（例 `99,799,100`）：不写「代币」标题、不写 symbol、不写「余额」二字；右侧是当前代币下拉（显示 symbol），点开是代币选择器（含自定义 ERC20）；精度只在 ≠18 时写在余额下方。下面金额输入（大字号，`inputMode=decimal`）+ 「全部」；原生币「全部」= 余额 − 预留网络手续费（`0.001`，写「约」），**可花余额为 0 时「全部」禁用**（不产生注定非法的 `0`，D5，2026-11-14）；超过余额时行内写「{symbol} 不够，还差 {x}」并禁用主按钮；`0` 写「金额必须大于 0。」、负数/非数字写「请输入有效的金额。」；小数位超过精度时**按精度向下截断**并提示「已按精度截断到 {n} 位小数。」（不四舍五入）。**余额读不到时主按钮禁用**，按钮下方写「余额暂时读不到，稍后重试。」并提供「重新读取余额」（D3，2026-11-14）——余额未知不能假装可以提交。
3. **资产保护（收款方命中时条件出现）** — 收款方是地址簿已知合约（router / stake / vote / submit / mint / launch / groupChat / lpExecutor / airdropDistributor / pair / weth / multicall3 / memberNFT 等）时显示「这是「{合约名}」合约地址」+「转进合约的代币很可能取不回来。」+ 勾选「我确认要转到「{合约名}」合约地址」（未勾选主按钮禁用）；合约名用 `/about` 同一套标签，一个合约不出现两个叫法。收款方是**任意有 bytecode 但不是地址簿条目**的地址时只显示「这个地址是一个合约」+「转进合约的代币可能取不回来，请确认你清楚它的用途。」（警告不阻断，用户可能确实要转）。
4. **主操作位** — 唯一实心按钮「确认转账」（钱包确认时「转账中…」），有界等待走 §4.2 的 `tx-watch` 恢复卡（「重新查询」/「重新提交」，90 秒上限）。**在途交易持久化（D1，2026-11-14）**：钱包返回哈希的瞬间就把 `{hash, token, amount, recipient, confirmed:false}` 落盘；刷新后首帧恢复 pending 卡片并继续 watch 同一个哈希，**同一笔在途/已成交时主按钮禁用**（下方「这笔转账还在确认中，确认后可以再转下一笔。」），不允许再发一笔。恢复卡出现后主按钮同样禁用并写「上面这笔还没有结果，请先用上面的「重新提交」或「重新查询」处理。」，绝不做成可点但静默的死按钮（D2，2026-11-14）。
5. **回执** — 成功后整页替换为回执（移动端底部 sheet、桌面端页面内卡片）：`已转出 {金额} {symbol}`、收款人（按身份 NFT 时附「身份 NFT #{id} {name}」；收款地址可点击复制完整地址，§4.7）、交易哈希（复制 + 浏览器链接）。**只有一个按钮「知道了」**（§4.3）；点击后关闭回执、留在原页并收成成功条「转账完成 / 已转出 {金额} {symbol}」，同时刷新余额。回执数字来自这笔交易实际携带的 wei 金额，不是估算。**成功条带交易哈希**（等宽显示、可复制、有浏览器链接时给「在区块浏览器里查看」）。**刷新后恢复成功条**（金额 + 哈希），但**回执 sheet 不重复弹出**——回执是一次性页面状态，与铸造/兑换同口径（D4，2026-11-14）。

**执行阶梯**：ERC20 直接调用 `transfer(to, amount)`，**没有授权阶段，界面不出现「授权」**；原生币是普通转账。同一时刻只允许一笔写操作在途。

### 3.11 代币授权

**用户一句话目标**：看清这个代币被哪些合约允许扣款、各自能扣多少，并随时把不用的授权撤掉。
**进入条件与前置**：从「应用」目录「代币」分类的「代币授权」行进入（`/approvals?symbol=`），也支持直接深链；目录条目 `requires: null`——ERC20 `allowance`/`approve` 对任何代币都可用，spender 行由本环境地址簿决定，所以任何地址簿状态下都可用。**必须连接钱包**；未连接显示「连接钱包后查看授权。」+ 连接按钮，网络不对显示「切换到这个应用使用的网络后再查看授权。」+ 回首页。页面标题「代币授权」。

**代币集合**：与代币转账同一套（社区代币分页 + 精确搜索 / 包装原生币 / LP 代币 / 自定义 ERC20），但**不含原生币**（原生币没有授权概念）。**默认代币在社区代币目录首次加载结束之后才决定**：取第一个社区代币；目录已 settled 但为空或读取失败时才回退到包装原生币 → LP（否则首次进入/刷新会先落到余额 0 的包装原生币并一直停在那里）。自定义 ERC20 校验 bytecode 并读 `symbol()/decimals()`；**代币按地址去重**：添加的地址若已在社区/包装原生币/LP 里，直接选中那个内置项，选择器不再出现第二个同名项，并在添加框下写「{symbol} 已经在「{分组}」里，不用重复添加。」。选中后显示 `{symbol} 余额 {格式化金额}`；精度只在 `decimals ≠ 18` 时在余额行右侧写「精度 {decimals} 位」，18 位不写。

**区块顺序**（owner 2026-11-14 整改：除了页首的代币上下文行，下面四块严格按 ①→④ 排列）
0. **代币行（页面上下文）** — 代币选择器 + 余额 + 精度。不选代币就看不了额度，所以它永远在四块之上。
1. **默认使用长期授权** — 页内第一块：一个开关（checkbox），勾选后本页把「长期授权」按钮画成更醒目的描边主样式（不再是行内徽标、也不出现「推荐」二字）；布尔值持久化在 `love20:tokenApprovalUseUnlimitedByDefault`（`1`/`0`，沿用旧库语义），只记在这台设备上，不随钱包/社区变化。
2. **授权说明** — 一段说明段落 + 三条人话要点：授权是什么、额度可随时撤销、长期授权几乎无限只给信任的合约开；界面不出现 allowance / approve / 函数名。
3. **自定义地址** — 输入 `0x` + 40 位 spender：非法地址即时写「这是一个无效的地址，需要 0x 开头的 40 位地址。」、零地址写「授权地址不能是零地址。」、自己钱包写「这是你自己的钱包地址，授权给自己没有意义。」；合法地址立即查额度，无额度写「这个地址没有授权额度。」，有额度显示金额与「撤销」「长期授权」；已是长期授权时授权按钮转只读的「已长期授权」（禁用，与 §4.1 全局文案一致）。地址本身点击即复制（§4.7 共享地址组件）。
4. **常用合约列表** — spender 固定取地址簿：兑换路由（`router`）/ 质押（`stake`）/ 投票（`vote`）/ 提交行动（`submit`）/ 铸造（`mint`）/ 发射（`launch`）/ 一键加池（`hub`）/ 扩展 LP（`lpExecutor`）/ 批量转账（`batchTransfer`）/ 链群聊天（`groupChat`）；**列表全部展开、不折叠**：每行 = 中文名 + 一句话用途 + 当前额度 + 缩略合约地址（完整地址在 `title`，点击即复制并给「已复制」反馈；统一走 §4.7 共享地址组件，不保留页面内自造的复制实现）+ 「撤销」「长期授权」。额度三态固定：`未授权` / `长期授权`（`≥ 2^255`，按钮写入 `maxUint256`）/ `具体额度`（`{formatTokenAmount} {symbol}`，最多 6 位小数、只截断不四舍五入；`0 < 额度 < 最小可见精度` 写 `< 0.000001 {symbol}`，绝不显示成 0）。极长额度（如 `2^255 − 1`）在行内单行截断显示（省略号），完整文本放在 `title`，不许撑破一行。「撤销」写入 `0`；已长期授权的行授权按钮保持禁用但文案改成「已长期授权」（owner 2026-11-14：禁用的「长期授权」会被读成"还没完成"）。

**执行阶梯**：每行只有两种写值——长期授权 = `approve(spender, maxUint256)`、撤销 = `approve(spender, 0)`；点击后先出现确认 sheet（写明当前额度 → 确认后额度、这个地址、后果与「确认长期授权」/「确认撤销」/「取消」），确认后走 `tx-watch` 90 秒有界等待（「重新查询」/「重新提交」）。成功后列表原地刷新，页面顶部出现可关闭的成功条「已撤销「{合约名}」的授权。」/「已把「{合约名}」设为长期授权，可随时撤销。」；关闭后留在 `/approvals`，列表仍是链上真值。同一时刻只允许一笔写操作在途。

**状态** — 未连接 / 网络不对 / 代币目录读取中（「正在读取代币列表…」，不落「还没有可以查看的代币」）/ **网络读不到**（「暂时读不到网络数据」+ 正文「…这不是没有代币，请检查网络后重新读取。」+「重新读取」，余额行「余额暂时读不到」；网络恢复后点「重新读取」直接自愈，不需要刷新页面；**不得**把网络故障写成「还没有可以查看的代币」或「先在代币选择里添加一个 ERC20 代币地址」）/ 额度读取中（行内「读取授权额度中…」）/ 读取失败（「授权额度暂时读不到」+「重新读取」）/ 未授权 / 长期授权 / 具体额度 / 自定义地址校验失败 / 钱包确认中 / 上链确认中 / 恢复卡 / 成功条 / **发送失败（错误在确认弹层内可见**：失败结论 +「这次没有产生交易。可以再点一次上面的按钮重试，或点「取消」先关掉这个窗口。」；弹层不收起、按钮恢复可点、额度不变，关闭弹层后页面底部错误条仍在）。错误文案不出现 allowance、approve、gas、nonce、revert、selector 或原始 hex。

**主 CTA 与次要入口**：这是列表管理页，没有底部主 CTA；唯一实心按钮是确认 sheet 里的「确认长期授权」，撤销用红描边「确认撤销」；次入口只有「回首页」。

### 3.12 批量转账

**用户一句话目标**：把一种资产一次转给多个收款方，事前逐行核对地址与金额，并清楚「一笔失败整批不到账」。
**进入条件与前置**：从「应用」目录「代币」分类的「批量转账」行进入（`/batch-transfer?symbol=`），也支持直接深链；目录条目 `requires: batchTransfer`——本构建地址簿没有批量转账合约时该行禁用并写原因（「这个环境还没有部署批量转账合约。」），页面本身同态（不显示假表单）。**必须连接钱包**；未连接「连接钱包后批量转账。」+ 连接按钮，网络不对「网络不对。」+「切换到这个应用使用的网络后再批量转账。」+ 回首页。**首屏即判网络**（owner 2026-11-14 QA D11）：已注入钱包但链不对时，不必先「连接钱包」，页面与头部（「网络不对，点此切换」）首屏就落网络不对态。页面标题「批量转账」。

**区块顺序**（owner 2026-11-14 09:30 整理，参考旧库 `batch-transfer.tsx`：资产/币种 → 收款清单 → 逐行错误就地 → 合计与余额对比 → 主按钮 → 预余额核对 → 高级选项折叠）
1. **资产行** — 原生币 / 代币 二选一（原生币默认）；代币模式出现代币选择器（与代币转账同一套社区代币分页 + 搜索 / 包装原生币 / LP），余额 `{symbol} 余额 {格式化金额}` + 「精度 {decimals} 位」（仅 `decimals ≠ 18` 时显示，18 位不写），桌面/移动同一行内排布，不再单独占一块。金额规则与 §4/全局一致：非零但被 6 位显示规则截成 0 的写 `< 0.000001`（绝不显示成 0，D3）；代币模式还没解析出代币时余额行写「代币余额暂时读不到，换个代币或重试读取。」，**不回落**成「ETH 余额 —」（D9）。余额读不到属于可恢复态：旁边给「重新读取」。
2. **收款方文本域** — 每行「地址 金额」，用空白或逗号分隔，支持直接粘贴多行；占位符示范两行。逐行错误在文本域下方按行号就地列出：`第 N 行：缺少金额。` / `第 N 行：地址格式不对，需要 0x 开头的 40 位地址。` / `第 N 行：金额格式不对。` / `第 N 行：金额必须大于 0。` / `第 N 行：收款地址不能是零地址。` / `第 N 行：不能转给自己。` / `第 N 行：不能转给批量转账合约本身。`。**重复地址不再合并**：后出现的行写 `第 N 行：与第 M 行重复，这一行先不计入，请删掉其中一行。`，该行不进入收款方列表、不计入合计，主按钮禁用，由用户删行后恢复；小数按 decimals 向下截断并写「金额已按精度截断到 {decimals} 位小数。」。
3. **合计与余额对比** — `{N} 行，{M} 个收款方` + `合计 {formatTokenAmount} {symbol}`（极小非零金额同样写 `< 0.000001`，D3）+ 固定一行「整批一起执行：有一笔失败，全部都不会到账。」；合计超过可花余额时写 `{symbol} 不够，还差 {短差}`（原生币另写「需要预留一点 {symbol} 支付网络手续费。」），主按钮禁用。**发送方余额读不到且合计 > 0 时**写「余额暂时读不到，还不能判断够不够转，请先重试读取。」+「重新读取」，**主按钮禁用**（D8：不把「读不到」当成「够转」）。
4. **合约收款方警告（条件出现）** — 任意收款方有 bytecode 时出现「有收款方是合约地址」警告（不强制勾选，由预演/链上结果给结论）；位置在主按钮之前，因为它影响「要不要提交」的判断。
5. **授权行（仅代币）** — 三态且互斥：读到了才写 `已允许批量转账合约使用 {当前额度} / 本次需要 {合计} {symbol}`；额度不足时主按钮是第一阶段「授权 {symbol}」，并写「这笔批量转账需要先授权一次，授权确认后再提交批量转账。」；额度足够时写「额度已足够，不需要再次授权。」，主按钮直接是「批量转账」。**额度读不到**时只写单一句「额度暂时读不到，无法判断是否需要授权，请重试读取。」+「重新读取」并禁用主按钮，**不得**同屏出现「额度已足够」（D2），也不得把额度写 0。
6. **主按钮** — 在流内的唯一主操作位（不吸底，§4）；错误卡与等待卡紧跟其后，同一屏内可看到。
7. **预余额核对表（主按钮之后，条件出现）** — 逐行 = 收款方（缩写 + 合约徽标）+ 金额 + 当前余额；当前余额来自批量转账合约的 `nativeBalances(address[])` / `erc20Balances(token, address[])`，一次读取整批；读不到显示「—」（不当 0），表下写「收款方余额暂时读不到，提交后仍会逐行核对到账差额。」并给「重新读取」（D6）；行金额同样遵守 `< 0.000001` 规则。
8. **高级选项（默认折叠）** — 「每行执行预算」默认 30000（原生）/ 60000（代币），范围 21000–1000000/收款方，且 `行数 × 预算 ≤ 30000000`；越界写「每行执行预算至少 21,000。」/「每行执行预算最多 1,000,000。」/「这批交易的计算上限超过一个区块的容量，请减少收款方或调低每行执行预算。」并禁用主按钮。
9. **回执（交易已上链，只有一个「知道了」按钮，§4.3）** — 整页/抽屉回执：`合计转出 {formatTokenAmount} {symbol}`（极小非零写 `< 0.000001`）+ `{N} 个收款方` + 逐行「收款方 / 金额 / 到账前 → 到账后 / 差额」；差额只允许四种形态：`+X`（与应到账额逐 wei 相等；非零但低于 6 位精度写 `< 0.000001`，不写 `+0`）、`未变化`、`{X}（异常）` 高亮、读不到 `—`。**结论按核对结果三态**（D1）：全部逐行核对通过才写「整批一起执行：上表每一行都已到账。」；有 N 行余额读取失败（提交前或到账后）写「到账核对不完整：有 N 行余额读取失败，未能核对，请到区块浏览器确认交易结果。」并把图标换成警告色；核对到但差额不符写「到账核对发现异常：有 N 行的差额与应到账额对不上，请到区块浏览器确认。」。代币模式下链上仍有残留授权（先按合计授权、再改小清单提交）时追加「链上还保留 {X} {symbol} 的授权，可到「代币授权」页撤销。」（D7）。关闭回执留在原页，上方出现成功条「已转出 {合计} {symbol}」。
10. **失败** — 发送前先在链上预演整批：预演失败不发交易、不扣手续费，错误卡按行定位：`第 N 行收款方拒收了这笔转账（对方可能是不接收 {symbol} 的合约）。整批没有转出，你的资产没有变化。` 或 `第 N 行的执行预算不够，这一批没有转出。可以在高级选项里调高每行执行预算。`；余额/额度竞态写「{symbol} 不够，整批没有转出。」/「批量转账额度还不够 {symbol}，请先完成授权再提交。」；交易上链但回滚写「交易上链了，但没有成功。整批没有到账，你的资产没有变化。」。钱包拒绝写「你在钱包里点了取消，这一批没有转出。」。任何错误都保留输入，可直接改行重试。

**状态**：未配置 / 未连接 / 网络不对（已注入钱包在其它链时首屏即此态，D11）/ 余额与额度读取中（骨架，不渲染 0）/ 余额或额度读不到（单一「读不到」结论 + 「重新读取」，余额未知时禁止提交，D6/D8）/ 空输入（「还没有可用的收款方。按上面的格式每行填一个。」）/ 逐行错误（含千分位金额按数值解析、精度截断为 0 的专用文案，D4/D5）/ 重复地址提示（阻塞提交，删行后解除）/ 超余额 / 预算越界 / 需授权 / 授权确认中 / 授权已足够 / 批量确认中 / 回执（核对完整 / 不完整 / 异常三态）/ 错误卡（含「重新提交」「重新查询」恢复）。**整批原子是硬约束**：页面任何位置都不出现「部分成功」「分批到账」「失败的几行稍后补发」。

**主 CTA 与次要入口**：整页一个主操作位——代币模式额度不足时是全局文案 `授权 {symbol}`，额度足够或原生币模式是「批量转账」/「确认批量转账」；额度已是长期授权时额度行写「已长期授权…不需要再次授权」。页面底部不再有「回首页」文字链。回执只有「知道了」一个按钮（§4.3）。

### 3.13 流动性池

**用户一句话目标**：把两种代币放进池子赚手续费，或者输入要拿回的流动性凭证数量把对应的两种代币撤出来；输入之后只看「预计获得多少流动性凭证 / 预计收到约多少」，过程量要展开才看。
**进入条件与前置**：从「应用」目录「代币」分类的「流动性池」行进入（`/liquidity?symbol=`），也支持直接深链；目录条目 `requires: router`——本构建地址簿没有 Router/Factory 时该行禁用并写原因。**添加与撤出必须连接钱包**；未连接「连接钱包后添加流动性。」+ 连接按钮，网络不对「切换到这个应用使用的网络后再添加流动性。」+ 回首页。「社区流动性查询」不连接也能看。页面标题「流动性池」。

**区块顺序**
1. **当前代币抬头** — 只显示「当前社区代币 {symbol}」，**页内不再提供社区代币下拉**（owner 2026-11-14：右上角社区切换已经能换，页内再来一份是冗余）。自定义代币地址收在折叠的「换个代币地址」里（读 bytecode + `symbol()`/`decimals()`，非合约 / 读不到给人话原因；**零地址 / 没有合约的地址**也要给「这个地址上没有合约，不能作为代币。」，不能点了没反应），用于查看还没进社区目录的池子。**自定义代币只在当前社区内有效**：右上角切社区时清空自定义选择，抬头 / 池子 / 查询跟随新社区；URL 的 `?symbol=` 在链上解析不到社区时显示「读不到这个社区。」+「重试」，**不拿目录第一个代币顶替**（QA D4/D5/D9）。

## §4 横切交互规范

### 4.1 授权 → 执行：按钮阶梯
- 只在需要时出现第一阶段：`allowance(wallet, memberNFT) ≥ 本次应付` 时直接显示单按钮「铸造」，回访用户永远只看到一次确认。兑换页同理：`allowance(wallet, router) ≥ amountIn` 时直接显示「兑换」。
- 铸造的授权额 = 本次报价 × 1.01（按需 + 1% 缓冲），不授权无限额；**兑换的授权额 = 本次输入金额，精确到 wei，不加缓冲**（§3.5）。文案必须写「只是允许合约最多扣这么多，不会立刻扣钱」。
- **授权文案全局统一（owner 2026-11-14）**：任何页面给某个代币授权的按钮都写 `授权 {symbol}`（`copy-pages.ts` 的 `copy.approve`），只有代币不同；进行中 `授权中…` → `确认中…`。不再出现「1. 授权」「1 授权」「1 允许使用 {symbol}」等变体。
- **授权按钮永远在流内、永远显示、且先于主按钮**（owner 2026-11-14）：兑换页的授权步骤放进兑换卡内部（金额行下方），主按钮「兑换」在信息块之后；铸造 / 流动性 / 批量转账同理，先决条件按钮在前、主按钮在后。移动端不再有 fixed 吸底按钮栏（`StickyAction` 已删除，改为流内的 `ActionStack`），`--sticky-action-height` 一并删除。
- **已长期授权时按钮仍显示**：授权额度 ≥ 2^255 时按钮就地显示 `已长期授权`（禁用、无需操作）；额度已够但不是长期授权时显示 `已授权`。额度读不到时显示 `读取授权额度中…`。
- 阶段 1 成功后**不跳转、不刷新、不弹 toast**：授权按钮原地变 `已授权`，主按钮解锁。
- **禁止**把授权缓冲写成「滑点」：参考实现的「滑点：0.1%」实为授权缓冲，不是价格滑点，属于错误标签。
- 用户拒签，或授权后价格上行使额度不够 → 按钮回到可点，文案「授权不够这次使用，需要再授权一次」，不跳页、不清空输入。

### 4.2 交易 pending 语法
- 三态，措辞固定：**等待你在钱包确认** → **已提交，等待上链** → **已上链 / 没有成功**。不把三者合并成一个「加载中」；授权阶段同样走这三态，按钮写「授权中…」。
- 任务对象 `{ id, kind, tokenAddress, memberId?, amount?, hash?, state, startedAt }` 存本地；有 hash 时刷新用 `getTransactionReceipt` 恢复；无 hash 视为未提交，中性文案「上次的操作没有提交」。
- 展示位置：按钮内文案 + 头部下方 36px 任务条；也**不做全屏 LoadingOverlay**，不锁页面（参考实现的全屏遮罩是漏斗漏点）。
- pending 中允许切页、切社区；任务条常驻，点击回到发起页。同一时刻只允许一个写操作在途，其余**写操作**按钮禁用并注明「有一个操作正在进行」；纯本地选择（如「使用此身份 NFT」）不受影响。
- 先落本地收据、再刷新数据，避免「数据已变但用户没看到收据」。
- **发送即固定链上 nonce（owner 2026-11-14）**：每笔写操作（**含刷新后的第一笔**）在提交前用页面正在监听的那条链读一次 `latest` nonce 并作为显式 nonce 提交 —— 与恢复卡「重新提交」同一条路径。钱包自己的 nonce 缓存再旧，也不会让首笔交易落在队列缺口里（真实浏览器里表现为「这笔交易还卡在钱包里」，点「重新提交」才上链）。nonce 缺口判定读取 **`pending`** 计数（排队在同钱包另一笔交易之后的交易不算缺口），且同一缺口必须**持续 10 秒**才出「这笔交易还卡在钱包里」恢复卡，避免一次滞后的链读把页面冻在恢复卡上。
- **回执关闭必须释放全部发送守卫（owner 2026-11-14）**：点「知道了」后除收起成功条外，还要清掉 hook 里的 receipt / pending / 授权态与本地未确认记录，否则下一次点「兑换」会被「有一笔回执还在」的守卫静默吞掉（表现为「完成一次兑换后再输入金额点兑换没反应」）。

### 4.3 成功收据（取代 toast + 2 秒跳走）
- 收据是**页面内状态**：不自动跳转、不 2 秒消失。标题 + 你得到什么 + 哈希。
- 必备字段：结果（铸造成功 / 兑换完成 / 已铸造）· **你得到什么**（`#memberId` + 链上 `memberName` / 实际到账数量 / 已铸造金额）· 实际支付（若有）· 交易哈希（复制 + 浏览器链接）。
- **回执只有一个按钮「知道了」（owner 2026-11-14）**：点击后关闭回执 + 留在当前页，页面顶部收成成功条（成功条是纯信息，不再带第二个按钮）。回执里不再出现「回首页」「再兑换一次」「再转一笔」「去我的 NFT」等第二个按钮；导航交给页头返回与底部标签栏。
- **离开页面再回来不重复显示（owner 2026-11-14）**：回执是**一次性页面状态**。已确认的交易不再写回本地记录（swap / mint / airdrop 在拿到回执时清除记录），再次进入页面只显示表单或 S6「已铸造」链上状态，不会从本地记录恢复成弹层。未确认的 pending 仍按 §4.2 恢复。
- 所有数字来自本笔交易回执：`MemberMinted.cost/name/memberId`、ERC20 `Transfer`、`AirdropClaimed.amount`；**不用前端估算值**。

### 4.4 错误文案映射（消费 `registry/errors.json`）
- 原则：**写结果与下一步，不写机制**。不出现 gas、allowance、nonce、revert、selector、`0x…` 堆栈、HTTP 状态码。
- 三层：`selector → 英文错误名（errors.json）→ 中文结论 + 下一步`；未收录的 selector 落到「交易被合约拒绝」+ 哈希 + 「重试」。

| 情形 | 文案（结论 + 下一步） |
|---|---|
| 用户取消（4001） | 「你在钱包里点了取消，没有扣款。」/ 重试 |
| 网络手续费不足 | 「BNB 不够付手续费。请先转一点 BNB 进来。」/ 复制地址 |
| 代币余额不足 | 「LOVE20 不够，还差 {x}。」/ 空投铸造、兑换 |
| 授权不足 | 「授权额度不够这次使用。」/ 再授权一次 |
| `NameAlreadyExists` | 「这个名字已经被用了。」/ 换一个名字 |
| `NameTooLong` / `NameInvalidCharacters` | 「名字太长 / 含有不可用的字符。」/ 修改名字 |
| 流动性不足 / 价格变动保护 | 「价格变化太大，这笔交易没有成交。」/ 重新报价 |
| 超时 / RPC 失败 | 「网络没有及时响应，交易状态未知。」/ 查看哈希 + 重试（不重复发送） |

### 4.5 估算类信息标注
- 三档标记：**预计**（空投可铸造金额、铸造价格、兑换报价与最少到账）、**约**（手续费预留、价格影响、任何倒计时）、**精确**（余额、已铸造金额、已上链数量）。
- 每个预计值必须带半句「为什么会变」：空投「别人铸造后金额会变」；铸造「价格随已铸造数量变化」；兑换「价格随池子变化」。
- 基于 Phase 的倒计时只能用「区块差 × 观测出块时间」估算，写「约 X 分钟」，并说明时间片长度会被协议调整（`Phase` 以区块计量，不是时间戳）。M0 页面不显示轮次倒计时；此规则适用于后续页面。
- 提交前重读一次链上；报价超过 30 秒视为过期，需重新报价。

### 4.6 移动端钱包兜底阶梯
- 顺序：① 用系统浏览器打开（Universal Link / `window.open`）② 扫码（二维码内容 = **当前页面 URL**，不是 WalletConnect URI；M0 只有注入钱包）③ 复制链接 ④ 说明「在钱包 App 内置浏览器里粘贴此链接」。
- 触发：应用内浏览器 UA 命中 → **连接之前**显示顶部横幅；没有 `window.ethereum` → 连接按钮直接打开兜底抽屉，不转圈、不报错。
- 抽屉文案：「这个浏览器里没有钱包。用下面任意一种方式打开，就能连接。」+ 三个按钮 + 一行「已经装了钱包？在钱包 App 的浏览器里粘贴这个链接。」
- 桌面放大二维码，移动优先 Universal Link 与复制；二维码本地生成，不调用第三方服务。没有兜底就不放「连接钱包」按钮——任何「点了没反应」都是漏斗漏点。

### 4.7 全局地址复制（owner 2026-11-14 09:30）

「所有出现的合约地址、钱包地址，都应该支持点击复制」：实现上只有**一个**共享组件 `src/shared/ui/copyable-address.tsx`（`CopyableAddress`），页面与弹层不得再各自实现复制按钮/复制状态。

- **形态**：地址文本本身是一个按钮，`display="short"` 时缩写（正文默认 4+4，列表行 6+4），`display="full"` 时整段等宽显示（`0x` 之后每 4 个十六进制字符一个 `<wbr>` 软换行点 + `text-wrap: balance`；390 px 不溢出，换行时末行至少是一个 4 字符组、不出现单字符孤行，QA 2026-11-14 B7）；`title` 永远是完整地址。
- **行为**：点击后用 `copyText()`（`navigator.clipboard`，失败回退隐藏 textarea + `execCommand`）复制**完整地址**；成功在地址右侧原地写「已复制」2 秒，失败写「复制失败，请手动选中地址」——不存在点了没反应的地址。
- **可访问性**：`aria-label` 为「复制地址：{中文名}」，复制成功后变「地址已复制：{中文名}」；反馈区 `aria-live="polite"`。地址按钮不做成实心主按钮（不参与 §4.1 的主操作位）。
- **覆盖范围**：关于页每个合约地址、代币授权（自定义 spender + 常用合约列表每行）、代币转账解析出的身份收款人、转让抽屉解析出的收款人、转账回执的收款人、钱包菜单的钱包地址、我的页钱包地址、批量转账预检与回执的每行地址、身份列表「已转让给」里的地址。社区菜单与连接药丸不直接展示可复制地址（药丸的地址复制在钱包弹层，§1.4/§1.6）。
- **一致性**：同一地址在缩略与完整两种形态下复制出的字符串逐字相同；页面之间只有缩写位数差异，不存在两套「已复制」文案。

## §6 M0 验收脚本大纲

**前置**：`vite preview --base=/<repo>/` 跑构建产物（不是 dev server）；Playwright + 注入型测试钱包（EIP-1193 stub + 本地私钥签名）；链 = 本地 anvil 31337，`make bootstrap` 起链并 seed：首币池注入 **200,000 LOVE20 + 100 WETH**（`SEED_LIQUIDITY_TOKEN_AMOUNT=2e23`、`SEED_LIQUIDITY_PARENT_TOKEN_AMOUNT=1e20`，见 ADR-0004）；dev 的地址与 ABI 只读 `anvil/export/deployments/anvil31337_dev.json` 与 `anvil/export/abis/*.json`（前端消费副本 `src/config/deployments/anvil31337_dev.json`）。fixture 的 anvil 0–9 号账户都在快照内（0–4 已铸造，5–9 有份额未铸造），所以主流程必须用**不在快照内**的新私钥（先从一个 anvil 账户转一点原生币（anvil：ETH）作 gas）。GitHub owner 与仓库名已定（`LOVE20BSC/interface-dev` / `interface-test` / `interface`，见 ADR-0002 §4），环境变体由 CI 按仓库名关键字选择（含 `dev` → dev，否则含 `test` → test，否则 prod；`vars.VITE_ENV` 可覆盖），发布命令为 `pnpm release-to <target>`（ADR-0002 §4）；**只有里程碑最终排期〔待定〕**。`--base` 由 CI 变量注入，脚本不得硬编码。

1. **打开 `/` → 未连接 → 连接**：未连接态 = 左侧社区标识 + 问候「你好」+「连接钱包」；底部 5 tab 可见；治理/行动占位页显示「即将上线」、一句说明与「回首页」，无空白、无半成品表单。点「连接钱包」→ 左侧标识隐藏、药丸变为两区，URL 补上 `?symbol=<首币>`。

13. **无资格 → 该卡不出现**：换一个不在快照内的新钱包（同样由 anvil 账户转原生币（anvil：ETH）作 gas）→ 首页不出现资格卡，也没有「无资格」字样或「无需操作」；回到刚铸造完份额的 anvil #5 刷新 → 卡片同样消失（`claimableAmount` 已为 0）。
14. **错误腿**：重名 → 「这个名字已经被用了。」；超额兑换 → 「{原生币} 不够…」；拒绝签名 → 「你在钱包里点了取消，没有扣款。」；三条都不出现 gas / allowance / nonce / `0x`。

15. **全局地址复制 / 身份输入三模式 / 社区 symbol 搜索（owner 2026-11-14 09:30）**：关于页任一合约地址、代币授权任一 spender、代币转账解析出的身份收款人、转让抽屉解析出的收款人、转账回执收款人、钱包菜单钱包地址——点击后原地出现「已复制」，剪贴板内容 = 完整地址（§4.7）；`/transfer` 与转让抽屉左下拉都在「按地址 / 按身份 NFT ID / 按身份 NFT 名字」之间切换，ID 模式输入名字给「请输入身份 NFT 编号，例如 #12。」且不发解析，名字模式输入同一字符串解析到对应 id + owner（纯数字名字不当 ID）；社区菜单输入 symbol：精确命中直接切换并关闭菜单，前缀命中列出候选，未知 symbol 给「没有找到这个 symbol 的社区。」且 URL 不变。

**阻塞点（必须显式处理，不得让脚本假装通过）**
- **零资产路径**：dev 参数下 7 字节名字的铸造价约 `1e21`（1000 LOVE20）。本地 bootstrap 已给首币池注入 **200,000 LOVE20 + 100 WETH**（`SEED_LIQUIDITY_TOKEN_AMOUNT=2e23`、`SEED_LIQUIDITY_PARENT_TOKEN_AMOUNT=1e20`，见 ADR-0004），初始价约 `0.0005` WETH/LOVE20；买够一次铸造约需 `0.5` WETH（含 0.3% 手续费，按初始池价估算），所以经济上闭合。但步骤 5 的 `0.05` 原生币（anvil：ETH）只够买约 100 LOVE20，不足一次铸造：要么把该步金额提到约 `0.6` 原生币，要么保留步骤 7 的空投注入。采用哪种〔待定〕。这是步骤 7 存在的原因。
- **dev/test 名称规则**：本地是 dev 变体，铸造名必须以 `Test` 开头（`T` 大小写敏感）；E2E 输入用 `Teste2e-member`，断言链上 `memberName` 与输入逐字相同（`core@72a1604` 后合约不再改写名字）。prod 变体没有该规则。
- 移动端连不上本地 anvil（钱包拒绝 `http:` RPC）；真机验收走测试网或 HTTPS 隧道。
- 铸造价、空投金额、兑换报价都是「预计」→ 脚本断言标签与格式，不断言具体数值；数值断言只用于回执解析结果。
