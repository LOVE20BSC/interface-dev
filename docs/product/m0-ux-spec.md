# M0 交互规格（UX Spec）

> 状态：Draft v3 · 已按 owner 决定更新首页、我的 NFT、铸造身份 NFT、空投铸造与兑换代币（§3.1–§3.5） · 适用：M0（身份漏斗 + 空投 + 通用代币兑换） · 读者：UI 工程师、验收
> 证据：`.research/tkm-connect-and-nav.md`、`.research/tkm-funnel-pages.md`、`.research/membernft-identity.md`、`.research/dex-and-anvil.md`、`.research/domain-model.md`、`.research/static-hosting-and-ux.md`、`GLOSSARY.md`、`docs/adr/0001..0003`、`docs/product/m0-scope.md`。
> 边界：本文件只写界面与交互。技术栈、构建、三环境注入见 ADR-0001/0002；**本文件未出现的合约方法一律视为不存在**（例如没有链上「默认身份」、`tokenURI` 不含任何内容、没有事件索引）。


## §0 设计原则

1. **新手视角（Lite 默认）**：界面不出现 gas、approve、allowance、nonce、revert、滑点、区块、合约等词；「高级视图」默认折叠，只放地址、哈希、轮次与浏览器链接（B-3；M0 的实现是 `/about` 的「合约地址」页 + 钱包弹层的合约地址，不做全局开关；各业务页不再重复技术详情折叠）。所有中文过 `GLOSSARY.md` 六条纪律。
2. **身份优先**：首屏先回答「我是谁」，再回答「我能做什么」。未连接也要能读懂这是什么；已连接先解析身份，身份决定文案、CTA 与语气（ADR-0003 §4）。
3. **一页一任务**：每页只有一个主 CTA；次要入口最多两个，且不与主 CTA 同色同权。一个页面不承载两条完整流水线。
4. **结论先于细节（渐进披露）**：先给「能不能做 / 要花多少 / 还差什么」，明细收进折叠区。默认一屏回答完，不要求用户先读规则。
5. **不把合约函数映射成界面**：按用户任务组织（拿到身份 / 空投铸造 / 买到币），一个任务可调多个方法；合约有而用户不需要的能力（融合、默认身份、限额）不出现。反过来，一个方法可拆成多个界面状态（claim 前的资格判定）。
6. **不显示未知值为 0**：加载用骨架，未知用「—」，失败说「读不到」。余额、价格、倒计时、可铸造金额绝不先渲染 `0`（ADR-0003；B-1）。
7. **不制造死路**：每个任务页的空 / 错 / 无资格状态必须有且仅有一个「下一步」按钮，外加一个返回入口；导航页（首页）由常驻入口承担下一步，不另造「无需操作」静默态；不存在只有一句话的页面（B-11）。
8. **估算必须标注**：由报价、池子、区块时间推出来的数字写「预计 / 约」并给出会变的原因；链上精确值（余额、已铸造金额）不标。估算值在提交前重读一次链上。

## §1 应用外壳

### 1.1 布局、断点与安全区

- 断点 `md = 768px`（与 ADR-0001 一致）。`<md` 底部标签栏；`≥md` 左侧可折叠侧栏，**不转换**底部栏（TKM 的做法）。
- 内容区 `max-w-[32rem]` 居中、左右 16px 内边距；桌面侧栏占宽（展开 232px / 图标轨 64px），内容区不因侧栏而拉伸成宽表。
- `viewport-fit=cover`；`--nav-h: calc(64px + env(safe-area-inset-bottom))`；页面容器 `padding-bottom: calc(var(--nav-h) + 8px)`，`md:pb-8`；头部 `padding-top: max(8px, env(safe-area-inset-top))`。
- 头部高 56px，`sticky top-0` + 背景模糊 + 1px 下边框；滚动时内容不穿过头部。
- 底部栏 `fixed bottom-0`，`min-height` 含安全区，`z-40`；弹层 `z-50`，弹层底部同样加安全区内边距。

### 1.2 一级导航（5 项，同一份配置）

| # | 标签 | 路由 | 图标（lucide） | M0 状态 |
|---|---|---|---|---|
| 1 | 首页 | `/?symbol=` | `House` | 可用 |
| 2 | 治理 | `/governance?symbol=` | `Vote` | 占位 |
| 3 | 行动 | `/actions?symbol=` | `ListChecks` | 占位 |
| 4 | 应用 | `/apps?symbol=` | `LayoutGrid` | 可用（功能页目录） |
| 5 | 我的 | `/me?symbol=` | `UserRound` | 可用（身份 + 余额） |

- **「应用」取代「链群」（2026-11-11 owner 决定）**：第 4 项是功能页目录 `/apps?symbol=`（图标 `LayoutGrid`），把创世空投、身份 NFT、代币兑换以及今后独立的功能页集中管理。**未来页面只加一条目录数据，不加导航代码**；功能页多起来后按条目的 `category` 自动分组（≥2 个分类才出现分组标题）。`/group` 路由保留给旧深链（占位页，不 404），但底栏不再出现「链群」。

- 移动端：24px 图标 + 11px 标签，激活态用实心图标 + 强调色；**不做中央凸起**——凸起会把一个不可用功能伪装成主入口（参考实现把「社区行动」凸起，实际是 M2 能力）。
- 桌面侧栏：5 项同序，激活项左侧 3px 指示条；顶部折叠按钮，折叠状态记在 `love20:v1:<chainId>:ui:<wallet>:sidebar`；底部放版本号 + 测试网徽标 + 「合约地址」入口（与钱包弹层同一弹层）。
- **占位页不是空白**：标题 + 「即将上线」徽标 + 一句将提供什么 + 「回首页」。徽标已经说明「现在没有」，正文不重复。文案：治理「用身份 NFT 对提案投票，按治理轮结算。M0 只做身份 NFT 与兑换。」；行动「链群行动、链群服务、LP 行动。」；`/group` 旧深链「链群是身份 NFT 组成的协作单位。」。我的不再是占位页：它承接身份与余额（§3.7），底栏与侧栏也不再给它「即将上线」标记。
- 底部栏不显示徽标计数；经典「红点」留给以后有真实未读时再用。

### 1.3 页面头部规则

| 页面类型 | 左 | 中 | 右 |
|---|---|---|---|
| 一级（首页） | 移动端（<md）：**未连接时**社区 `symbol()`（无社区/未知回退「LOVE20协议」）；已连接（含错网络）隐藏。桌面（≥md）：「首页」文字标签（社区名在左侧栏顶部） | — | 完整药丸（chip + 地址/身份）；已连接时它是移动端页头唯一的社区名位置 |
| 二级（我的 NFT / 铸造身份 NFT / 空投铸造 / 兑换代币 / 应用） | 返回按钮 44×44 | 标题，单行 `truncate`，最长 8 字 | 药丸：chip 收成 28px 首字符圆徽（<480px），右触发区保留 |
| 占位页 | 返回按钮 44×44 | 标签名（治理 / 行动；`/group` 旧深链为「链群」） | 药丸：chip 收成 28px 首字符圆徽（<480px），右触发区保留 |
| 收据态（页面内状态） | 「关闭」→ 首页 | 结果标题（铸造成功 / 兑换完成 / 已铸造） | 紧凑药丸（仅右触发区） |

- **移动端首页：未连接保留左侧标识，连上后由右上角 chip 承担（2026-11-11 owner 决定）**：未连接时右上角只有「连接钱包」，左侧社区标识是移动端唯一社区名；连上后（含错网络）左侧标识隐藏，社区名由右上角药丸的 chip 承载。桌面端仍由左侧栏顶部字标承载，二级页与占位页由标题承载。左侧标识是文字标签，不是第二个首页链接；不新增第二处社区名或第二个连接入口。
- 返回：有历史 → `back`；无历史（直接打开深链）→ 回首页。始终有返回，深链不产生无出口页面。
- 页内标题只描述页面，不重复社区名；社区名在 chip 里。避免「铸造身份 NFT · FOO」这种双标题。「铸造身份 NFT」正好 8 个字符（4 个汉字 + 空格 + 3 个拉丁字母），390 px 页头实测不截断。
- **社区名 = `symbol()`；`name()` 只用于技术详情/调试信息，不进主界面。** 只要界面出现「当前社区的名字」——桌面侧栏品牌行、右上角社区 chip、含社区名的页面标题、任何元信息行——一律渲染链上 `symbol()`（如 `TestLOVE20`）。没有选中/未知社区时，这些位置回退到协议标签「LOVE20协议」——它命名的是协议，不是一个代币社区；LOVE20 社区被选中时，社区名就是它自己的 `symbol()`「LOVE20」。页内标题原则上仍不重复社区名（见上一条）；若某个页内标题确实带上社区，用 `symbol()`。`name()` 是形如 `<子币 symbol>@<父币 symbol>` 的复合技术标识（如 `TestLOVE20@TestWETH`），不是显示名，不得用作社区名。
- **浏览器标签页标题**：有当前社区时 `<页面> · <社区 symbol>`；没有选中/未知社区时只写「LOVE20协议」。社区名同样取 `symbol()`，不用 `name()`。
- 药丸在手机与桌面位置相同（右上角），不做第二处连接入口；移动端社区名只由未连接时的左侧标识或连上后的药丸 chip 承载。

### 1.4 右上角连接药丸

一个容器、三种状态、两个触发区（照 TKM，但去掉主题与锚定）：

| 状态 | 外观与文案 |
|---|---|
| 未连接 | 单个按钮「连接钱包」，点击直接 `eth_requestAccounts`；进行中「连接中…」；点击后若 3 秒内仍无注入钱包 → 打开 §4.6 兜底抽屉（不显示死按钮「检测钱包中…」） |
| 链不对 | 红色描边按钮「网络不对，点此切换」→「切换中…」；`wallet_switchEthereumChain`，4902 时 `wallet_addEthereumChain`（参数来自环境包），成功自动重连 |
| 已连接 | `[SYMBOL ▾] │ [0x1234…abcd / 身份 NFT 名 ⌄]`；两区各自可点，互不触发 |

- 左触发区（chip）：`max-w-[96px]` `truncate`，`font-mono text-[13px]`；二级页且视口 <480px 时收成 28px 首字符圆徽，其余情况显示完整 chip；两种形态都可点。chip 文案一律为当前社区 `symbol()`（§2.1），不是 `name()`；没有选中/解析到社区时，chip 文案回退到协议标签「LOVE20协议」（§1.3）。
- 右触发区：上行地址（mono 13，缩写 4+4），下行身份 NFT 名或「未选择身份 NFT」（11px 灰）；有进行中交易时右上角 6px 琥珀点（§4.2）。
- 弹层形态：`<md` 为底部抽屉（抓手 + 安全区 + 最大高 70dvh，可滚动）；`≥md` 为锚定弹层（代币 240px，钱包 288px，右对齐）。同一时刻只开一个。
- 未连接时整个药丸就是一个「连接钱包」按钮：不渲染两个触发区，也不做灰掉的假入口。

### 1.5 左弹层：代币社区（行项完整顺序）

1. 分组标签「最近访问」。
2. 最近行（最多 4）：symbol（mono）+ 当前项「当前」徽标；点行即切换。
3. 空态：「还没有访问过其他社区」。
4. 分隔线。
5. 「父币」+ 右侧父币 symbol；根代币时整行禁用，右侧写「{根父币 symbol}（根）」（本地为 `TestWETH`）并附小字「当前已是根代币」。
6. 「子币」+ 右侧「{N} 个」+ chevron → 子币抽屉：`childTokens(parentTokenAddress, offset, 20, false)` 分页，「加载更多」，空态「这个社区还没有子币」。
7. 分隔线。
8. 「复制本页链接」（分享 / 移动端兜底要用）。

**没有**：锚定（pin）、「其他子币」二级入口、「代币信息」页、地址与复制。层级最多两层（弹层 → 子币抽屉）。

### 1.6 右弹层：钱包与身份 NFT（行项完整顺序）

1. 「钱包地址」+「复制」→ 2 秒「已复制」；下方完整地址 `font-mono text-xs break-all`。
2. 分隔线。
3. 身份行（整行可点 → 我的 NFT）：有身份 = 名称 + `#{memberId}` + 右侧「查看」；已连接但未选 = 「还没有选择身份 NFT」+「去选择」；钱包无 NFT = 「你还没有身份 NFT」+「去铸造」。
   - **身份 NFT 行必须与校验状态一致；未校验时不得显示确定信息，也不得给出前往 NFT 页的入口。** 行内容只取 `useMemberIdentity()` 的 `status`（与右上角药丸同一事实源，ADR-0003）：
     | `status` | 行文案 | 动作 |
     |---|---|---|
     | `loading` | 「读取中…」 | 无（整行不可点，不显示编号） |
     | `error` | 「身份 NFT 暂时读不到」+ 一行说明 | 无（不显示「查看」；弹层没有重试模式，因此不新增按钮） |
     | `unconfigured` | 「这个环境还没有部署身份 NFT 合约」 | 无 |
     | `empty` | 无身份行（同 §1.6 第 3 条） | 「去铸造」 |
     | `needs-selection` | 「还没有选择身份 NFT」 | 「去选择」 |
     | `ready` | 名称 + `#{memberId}` | 「查看」 |
   - 缓存的选择不是事实：`loading` / `error` / `unconfigured` 时即使本地存有 tokenId，也不得渲染名称、`#id` 或「查看」入口（否则与药丸的「—」矛盾，且入口只会落到读不到数据的页面）。
4. 「LOVE20」余额（按 `decimals()` 展示 2 位，精确值）+ 「BNB」余额（4 位）+ 小字「BNB 用于支付网络手续费」。
5. 分隔线。
6. 「进行中的操作 {n}」（仅有任务时出现）→ 任务抽屉（§4.2）。
7. 「合约地址」→ 弹层：链 ID、LOVE20、MemberNFT、Airdrop、Router、交易对地址 + 区块浏览器链接 + 逐项复制（信任信号，B-5）。
8. 分隔线。
9. 「断开连接」（危险色）。
10. 页脚小字：「当前身份 NFT 保存在这台设备；换浏览器需要重新选择。」

**没有**：主题切换、网络选择器、ENS、头像、切换钱包地址列表（换地址 = 断开再连）。

## §2 代币社区上下文

### 2.1 唯一事实源

- `?symbol=` 是当前社区的唯一事实源。**不持久化「当前代币」**（与 TKM 的 `localStorage._currentToken` 相反）；刷新、分享、返回都只认 URL。
- `?from` / `?to` 是兑换页自己的兑换对参数（§3.5），与 `?symbol=` 并行：切换社区不改写 from/to，切换 from/to 也不改写 `?symbol=`。
- 缺省或空：读环境包 `firstTokenAddress` 的 `symbol()` 后 `history.replaceState` 补上 `?symbol=`，不新增历史记录。
- 写入 URL 的 symbol 永远来自链上 `symbol()`（如 dev 链的 `TestLOVE20`），不接受用户手输；用户手改 URL 走 §2.5。
- **社区名 = `symbol()`；`name()` 只用于技术详情/调试信息，不进主界面。** 桌面侧栏品牌行、右上角 chip、含社区名的页面标题与元信息行都渲染 `symbol()`（如 `TestLOVE20`），不渲染 `name()`；没有选中/解析到社区时回退到协议标签「LOVE20协议」——它命名协议，不是代币社区。LOVE20 社区被选中时，社区名就是它自己的 `symbol()`「LOVE20」；其他社区则用各自的 `symbol()`。`name()` 是 `<子币 symbol>@<父币 symbol>` 的复合技术标识（如 `TestLOVE20@TestWETH`），不是显示名。
- 解析：`Launch.tokenAddressBySymbol(symbol)`；返回 `0x0` 即不存在。解析成功后保留其余 query（如 `?tx=`）。

### 2.2 切换判定表

| 场景 | 行为 |
|---|---|
| 首页 / 我的 NFT / 铸造身份 NFT / 空投铸造 / 兑换代币 / 应用 | 原地 `replace` 当前路径 + 新 `?symbol=`，保留其他 query，不整页刷新 |
| 占位页（治理 / 行动 / 我的；`/group` 旧深链） | 同上；URL 保持可分享，页面内容不变 |
| 未知路由 | `replace` 首页 + 新 symbol |
| 目标是当前社区 | 关闭弹层，不发任何请求 |
| 有 pending 交易 | 允许切换；任务继续，头部下方「进行中的操作」条保留，可回到原页看收据 |
| 页面正处于报价 / 输入 | 中止在途请求；兑换页保留 `from`/`to` 与输入金额（`?symbol=` 与兑换方向相互独立），报价按新区块/倒计时重取；其他页清空金额输入并回骨架（不同币价格不可复用） |
| 正处于收据态 | 允许切换；先提示「上一笔交易已经上链，收据仍可在『进行中的操作』里查看」 |

### 2.3 最近访问

- 键：`love20:v1:<chainId>:<launchAddress>:<wallet>:recentCommunities`（统一缓存封装，组件内禁止裸用 `localStorage`）。
- 值：`[{ symbol, address, at }]`；**上限 4**、按 `address` 去重、最新在前、排除当前项；解析成功后写入，切换时 merge 并置顶。
- 脏数据 / 反序列化失败 → 清空该键自身，不阻塞首屏。未连接时不读写（与 ADR-0003「未连接时代币面板不可用」一致）。

### 2.4 切换后重取 / 不重取

| 立即重取（query key 含 `tokenAddress`） | 不重取 |
|---|---|
| `symbol()` / `decimals()`（`name()` 仅在技术详情/调试需要时读取，不参与显示）、`parentToken()`、`childTokens()` 总数、`factory.getPair()` 与 `getReserves()`、报价、当前币余额 | 钱包与链、身份 NFT 列表与当前身份 NFT、LOVE20 余额、MemberNFT 铸造报价（按首币计价，与社区无关）、空投资格（空投代币固定为首币） |

### 2.5 错误页

- **symbol 不存在**：标题「没有找到这个代币社区」+ 原样展示 `?symbol=FOO`（mono）+ 「链接里的代币符号可能拼错了，或者这个代币还没发射。」主 CTA「回到首币社区」（replace 首币）；次入口：最近访问（最多 4 条，直接切换）；底部文字链「复制当前链接」。
- **链上读取失败**（不是找不到）：标题「暂时读不到链上数据」+ 「网络可能不稳，你的资产没有变化。」+ 主 CTA「重试」+ 次「回首页」；保留上次成功的数据并标注「上次更新于 X 分钟前」，不把旧数据当新数据。
- Launch 地址缺失属于构建期错误，不出现在界面。

### 3.1 首页

**用户一句话目标**：打开就看到问候和「有没有需要我处理的事」；没有就保持干净。
**定位（2026-11-11 / 2026-11-12 owner 决定）**：首页是**问候 + 提醒流**，不是导航页。导航入口在「应用」目录（§3.6）；身份 NFT 与余额的完整信息在「我的」（§3.7），首页只保留一句问候。没有重要信息或事项需要提醒时，首页就是一句问候，没有任何填充句，也没有页脚。
**进入条件与前置**：可未连接浏览；`?symbol=` 缺省补首币；身份取自本地选择并已按 `ownerOf` 校验。空投资格来自快照懒加载 chunk（见下），**不进入首屏包，也不阻塞问候与无身份提醒**。

**区块顺序（自上而下，每一块都条件渲染）**
1. **未连接 → 连接入口** — 说明「一个钱包可以拥有多个身份 NFT，身份 NFT 才是参与凭证。」+「连接钱包」（与右上角药丸是同一个连接动作与状态，不新增第二套连接入口）。
2. **问候（常驻，页面 `h1`）** — 单行、`truncate`、**不是链接**。连接且有当前身份 NFT → 「你好，{memberName}」；连接但无身份 NFT、持有但未选择、读取中 → 「你好」；未连接 → 「你好」。问候不显示余额、不显示 `#memberId`；余额与身份 NFT 详情在「我的」（§3.7）。
3. **提醒卡（按固定顺序，仅适用时出现）**
   - **无身份 NFT**：「你还没有身份 NFT」+「铸造身份 NFT」→ `/mint`。
   - **持有身份 NFT 但未选择**：「你还没有选择身份 NFT」+「选择身份 NFT」→ `/my-nft`（保留当前 `?symbol=`）。与「无身份 NFT」互斥，固定在它之后、空投卡之前。
   - **身份读取中**：在提醒卡位置渲染紧凑骨架（短句「读取身份 NFT 中…」+ 两行骨架），不显示长文案，也不显示会失败的 CTA；避免首页从「只有问候」闪成提醒卡。
   - **身份读取失败**：「身份 NFT 暂时读不到」+ 一行原因「网络可能不稳，你的身份 NFT 没有变化。」+「重试」；「重试」调用身份读取模型的 `refetch`，真的重新读取。RPC / 本地链不可达时也落到这里，**页面不得静默只剩问候**。
   - **环境未部署身份 NFT 合约**：「这个环境还没有部署身份 NFT 合约」+「这里暂时不能铸造身份 NFT。」；不给「铸造身份 NFT」等会失败的 CTA，也不给「重试」（重试不能部署合约）。同一句在 `/my-nft` 复用。
   - **有空投资格且未铸造**：「你有空投资格，可铸造 {X} {symbol}」+「空投铸造」→ `/airdrop`（保留当前 `?symbol=`）。`X` 来自 `claimableAmount`；金额或首币 symbol/decimals 读不到时**省略金额分句**（只写「你有空投资格」），绝不把「—」写进句子里。
   - **有未确认交易**：「1 笔交易还没确认」+「查看」。**M0 未实现**：今天三个写流程各自持久化自己的记录（`mintTask` / `airdropClaim` / `swapReceipt`），没有统一的 pending-tx 读取模型；在出现单一持久化 pending 辅助函数前，这张卡不渲染，也不伪造数量（见 `home-page.tsx` 的 TODO）。
4. **没有适用项** — 只有问候。**不写**「现在没有需要你处理的事。」或任何等价占位句；没有提醒卡，也没有实心按钮。
5. **没有页脚**（owner 2026-11-12）— 首页不再渲染「开源文档」链接，也不再有「技术详情」折叠。开源文档、版本号、链 ID / RPC 与全部合约地址都在 `/about`（§3.8）；首页不再重复这套样板。

**已移除（2026-11-11 / 2026-11-12）**：三个常驻入口行（我的 NFT / 空投铸造 / 兑换代币，已在 `/apps`）；首页细行与其上的余额（问候取代；余额去 §3.7）；独立的身份卡；旧的「现在没有需要你处理的事。」空态句；页脚「开源文档」链接与「技术详情」折叠（2026-11-12，改由 `/about` 承担）。首页不再按 LOVE20 余额不足追加提醒，也不出现「无需操作」静默态之外的额外说明。

**快照加载与提醒卡显隐**
- 空投快照 JSON 是**首屏渲染之后才 `import()` 的懒加载 chunk**：问候与无身份提醒先可用，快照数据就绪后空投提醒卡原地出现；**不预留占位、不显示骨架、不阻塞问候**。
- 快照未就绪 → 不显示空投提醒卡；钱包不满足资格 → 不显示卡，也不写「无资格」。
- chunk 读取失败 → 不显示空投提醒卡；首页保持干净（不额外造一行错误文案）。

**实心按钮**：一屏最多一个实心按钮。只有第一张出现的提醒卡提供它：无身份卡与「未选择身份 NFT」卡互斥、都在空投卡之前，所以有任一张时它用实心、空投卡用描边；只有空投卡时它是实心。未连接时实心按钮是「连接钱包」。问候永远不是实心按钮。

**状态与错误**

| 身份状态 | 首页表现（问候 `h1` 常驻） |
| --- | --- |
| `disconnected` | 连接入口卡 +「你好」；没有身份提醒卡 |
| `loading`（已连接） | 「读取身份 NFT 中…」+ 紧凑骨架卡；无 CTA |
| `error`（已连接） | 「身份 NFT 暂时读不到」+ 一行原因 +「重试」（`refetch`）；RPC 不可达也走这里 |
| `unconfigured`（已连接） | 「这个环境还没有部署身份 NFT 合约」+「这里暂时不能铸造身份 NFT。」；无 CTA |
| `empty` | 「你还没有身份 NFT」+「铸造身份 NFT」→ `/mint` |
| `needs-selection` | 「你还没有选择身份 NFT」+「选择身份 NFT」→ `/my-nft` |
| `ready` | 「你好，{memberName}」；没有身份提醒卡 |

- **问候只在 `ready`（`ownerOf` 已校验）时点出身份名称**：其余状态（含本地缓存了 tokenId 但正在读取、读取失败、未部署、无身份、未选择、未连接）一律「你好」——缓存的选择不是事实，与 §1.4 药丸/钱包弹层的规则一致，避免首页点名而药丸显示「—」。
- **「首页在任何身份读取状态下都不允许只显示问候语」**：`loading` / `error` / `unconfigured` 都必须给出骨架、原因或环境说明；只有 `ready` 且没有提醒事项时，首页才允许只保留问候。
- 任何未知值用「—」；身份读取错误在首页就地说明并重试，其他页面的重试入口仍留在「我的」与各任务页。

**验收**
- 未连接打开：左侧社区标识可见；看到问候 `h1`「你好」与「连接钱包」；不再有 `/me` 细行。
- 连接后有身份 NFT、无事可做：左上标识消失；`h1` 显示「你好，{memberName}」；首页不显示余额；页面只有问候，实心按钮 = 0，没有页脚，也没有「现在没有需要你处理的事。」。
- 连接后无身份 NFT：`h1` 为「你好」；出现「你还没有身份 NFT」+「铸造身份 NFT」，点击进入 `/mint`。
- 连接后身份读取中：`h1` 为「你好」；提醒卡位置出现骨架卡「读取身份 NFT 中…」，页面不是裸问候。
- 连接后 RPC / 本地链不可达：`h1` 为「你好」；出现「身份 NFT 暂时读不到」+ 一行原因 +「重试」；点「重试」会重新读取，恢复后出现正常提醒卡。
- 连接后环境未部署身份 NFT 合约：出现「这个环境还没有部署身份 NFT 合约」+「这里暂时不能铸造身份 NFT。」；不出现「铸造身份 NFT」或「重试」。
- 连接后持有身份 NFT 但未选择：`h1` 为「你好」；出现「你还没有选择身份 NFT」+「选择身份 NFT」，点击进入 `/my-nft` 并保留 `?symbol=`；此时不出现无身份卡。
- 有资格：出现「你有空投资格，可铸造 {X} {symbol}」+「空投铸造」，点击进入 `/airdrop` 并保留 `?symbol=`；金额未知时句子里没有「—」。
- 无资格：空投提醒卡不出现，首页只剩问候。
- 身份 NFT 被转走后刷新：中性提示语义由「我的」承担；首页问候回落到「你好」，并出现无身份提醒，不出现指向旧身份的操作。
- 快照 chunk 晚于首屏：问候先可用，提醒卡在数据就绪后出现，不遮挡、不阻塞问候。
- 任一屏最多一个实心按钮；390px 下问候保持单行并被截断，不换行。

### 3.2 我的 NFT

**用户一句话目标**：看清我有几个身份、现在用哪个，并立即换一个。
**进入条件与前置**：需连接（页内连接）；从「应用」目录、`我的`页身份块（§3.7）或钱包弹层身份行进入。身份 NFT 列表 = `balanceOf(wallet)` + `tokenOfOwnerByIndex(wallet, i)`（Multicall3 批量）+ `memberName(tokenId)`。

**布局（参照参考实现的同页，只取结构）**
- `<md`：**卡片行**，一个身份 NFT 一张卡，卡内依次是 `NFT #memberId`、`memberName`、当前身份 NFT pill 与操作。
- `≥md`：**表格**，列为 NFT 编号 / 名称 / 操作。
- 两种形态共用同一排序：**当前身份 NFT 第一，其余按 `memberId` 升序**；当前行整行着色（accent tint）并带「当前」pill。
- 持有数量始终显示真实值，**不因 N ≤ 3 隐藏**；写操作进行中**不禁用整张表**（见状态）。

**区块顺序**
1. **摘要条** — 只写「持有 {N} 个身份 NFT」，不重复当前身份 NFT 名字；空态不渲染摘要条（空态卡已给结论）。数据：`balanceOf`。
2. **说明段（两行内）** — 「每个身份 NFT 都是一个独立的身份，可以在多个社区使用。换钱包不会改身份 NFT，只有转让才换控制者。」
3. **身份 NFT 列表** — 卡片行（<md）/ 表格（≥md）；字段只有 `NFT #memberId`、`memberName`、当前 pill、操作。`tokenURI` 返回空字符串，**不渲染图片、不请求任何图片源**。
4. **行内操作** —
   - 「使用此身份 NFT」：**纯本地选择**，写入本地当前身份 NFT 并立即更新页面，**不发起链上交易、不签名、不等待**；成功后该行置顶并着色。当前行只保留「当前」pill + 行底色 + 一个禁用的行内按钮（不再写一遍「当前身份 NFT」文字）。
   - 「转让」：打开转让抽屉（收款人三选一：**按地址 / 按身份 NFT ID / 按身份 NFT 名字**），警告「转让会改变这个身份 NFT 的控制者。身份 NFT 的历史与质押仍留在身份 NFT 上，随身份 NFT 一起换控制者、不单独转移；转让不可撤销。」确认后 `safeTransferFrom(你, 对方, memberId)`；成功的收据写「已转让给 0x…」；若转的是当前身份 NFT，同时清除本地选择——还有其他身份就回到「未选择身份 NFT」，没有则回落到无身份形态。
     - **按地址**：校验 `0x` + 40 位、非零、非自己。
     - **按身份 NFT ID**：`#id` → `ownerOf(id)`；不存在 / 属于自己 / 读取失败各有明确文案与重试。
     - **按身份 NFT 名字**（owner 2026-11-12，防名称混淆）：用合约 O(1) 的 `memberId(name)` 直接解析（合约内部自行做 `normalizeName` 规范化，输入原样传入）；返回 0 或调用 revert 即「这个身份 NFT 不存在」。名称→id 结果在本会话内缓存（缓存键按规范化名，大小写不同不重复查），不轮询；持有人始终重新读 `ownerOf`，并读一次 `memberName(id)` 在确认区展示链上规范名。**解析成功后必须二次确认**：显示「名称「{name}」→ 身份 NFT #{id}」「收款人 {短地址}」与「名称相近或看起来相同的身份 NFT 可能存在，名称不是唯一依据」；用户勾选「我确认 #{id} 就是正确的身份 NFT」之前，「转让」保持禁用。找不到 / 属于自己 / 解析失败（可重试）均是具体文案，不用泛化错误。
5. **底部** — 「铸造新身份 NFT」（描边按钮）+「回首页」（文字）。不再有高级折叠：MemberNFT 合约地址在 `/about`（§3.8）。

**状态**：未连接「连接钱包后查看你的身份 NFT。」+ 说明「没有身份 NFT 也能先看看这里能做什么。」+ 连接按钮 · 加载（3 行骨架 + 摘要骨架）· 空「你还没有身份 NFT。」+ 说明「铸造需要一个名字和少量 LOVE20。」+ 主 CTA「铸造身份 NFT」· 错误「身份 NFT 列表暂时读不到。」+「重试」· 未部署「这个环境还没有部署身份 NFT 合约」+「这里暂时不能铸造身份 NFT。」（无 CTA；与首页同一句）· 身份失效（行内标「已失效」并不可选，同时清除本地选择）· 转让中（**仅该行**显示「转让中…」；其余行的「使用此身份 NFT」照常可用，其余行的「转让」按 §4.2 的单一写操作约束禁用并注明原因，**整表不禁用**）。「使用此身份 NFT」是本地选择，没有「切换中」等待态。
**主 CTA 与次要入口**：有身份时无主 CTA（列表即内容），唯一实心按钮是空态的「铸造身份 NFT」；每行操作为文字/描边按钮。「转让」为危险色并二次确认。
**死路处理**：空态给「铸造身份 NFT」；错误态给「重试」；失效行给「重新选择」。任何一行都不允许只有名字没有操作。
**加载骨架**：摘要条灰块 + 3 行等高行（名称 60% 宽、`#id` 30%、右侧按钮方块）。
**验收**
- 窄屏（<md）为卡片行，宽屏（≥md）为 NFT 编号 / 名称 / 操作 三列表格。
- 持有 2 个身份 NFT：2 行，当前项置顶、整行着色并带「当前」pill；当前行没有「使用此身份 NFT」按钮，只留禁用按钮。
- 空钱包：只有空态卡（「你还没有身份 NFT。」+ 说明 +「铸造身份 NFT」），上方没有「持有 0 个身份 NFT」摘要条。
- 持有 ≤3 个身份 NFT 时数量仍显示真实值，不隐藏。
- 转让抽屉可按名字解析：输入已存在的名字后看到「名称「…」→ 身份 NFT #id」与收款人短地址，未勾选确认前「转让」禁用，勾选后启用；输入不存在的名字显示「没有找到这个名称对应的身份 NFT。」。
- 点「使用此身份 NFT」后无需签名立即生效，置顶与着色移动到该行；回首页看到新名字。
- 无身份：看到「铸造身份 NFT」并能进入铸造页。
- 转让确认后：该行消失；若转的是当前身份 NFT，本地选择被清除——还有其他身份时回到「未选择身份 NFT」，没有时回落到无身份形态；转的不是当前身份 NFT 则当前身份 NFT 不变；警告写明只换控制者、历史与质押留在身份 NFT 上。
- 转让进行中：整张表不被禁用，只有相关行的写操作受限；其他行仍可「使用此身份 NFT」。
- 刷新后当前身份 NFT 仍是上次所选（`ownerOf` 校验通过）。

### 3.3 铸造身份 NFT

**用户一句话目标**：用一个名字铸出身份 NFT，事前知道要花多少、还差什么、下一步去哪。
**进入条件与前置**：需连接 + 链正确；还没有身份 NFT 的用户是主客群。价格按 LOVE20 计价，与当前社区无关。

**区块顺序**
1. **名称输入** — 标签「给身份 NFT 起个名字」，不再放同字占位符；上限字节数由 `MAX_NAME_LENGTH()` 读取（不硬编码；按 UTF-8 字节校验，不用 `maxLength`，否则中文会被截错）；下方实时「{n}/{MAX_NAME_LENGTH} 字节」（dev 参数为 `32`）+ 一行规则「中文 3 字节、英文与数字 1 字节；名字越短，价格越高」。**dev / test 变体**在规则行下方再显示命名约束「名称必须以 Test 开头」（`T` 大小写敏感），并做行内校验：不以 `Test` 开头时显示一行原因「为了让测试身份 NFT 和真实身份 NFT 一眼能分开。」并禁用提交（阻断式，不是警告）；同时检查行改写为「✗ 还没加 Test 前缀」，避免和常驻规则行逐字重复；判断依据是构建变体（环境包），不是支付代币 `symbol()` 是否以 `Test` 开头。**prod 变体没有这条约束，也不显示该行**。字节上限在三个变体都是完整的 `MAX_NAME_LENGTH()`，不存在 `-4` 调整。
2. **检查行** — 「检查中…」/「✓ 可以用」/「✗ 这个名字已经被用了（#{existingId}）」/「✗ 太长了」/「✗ 含有不可用的字符」/「✗ 还没加 Test 前缀」（仅 dev/test；常驻规则行仍是「名称必须以 Test 开头」）。数据：`isNameUsed(name)`（防抖 400ms，传用户输入的原始名字）→ 提交前以 `mint` 的 `eth_call` 模拟为准。
3. **费用卡** — 「铸造价格 **预计** {cost} LOVE20」+「我的 LOVE20：{balance}」+ 余额旁的小文字链「去兑换代币」+ 不足时「还差 {diff}」+ 一行小字「价格随已铸造数量变化，提交时以链上为准。」（不再另写「与当前社区无关」；币种已由金额与余额的 `symbol()` 标明）。`去兑换代币` 是次级文字入口：与余额同一行、不描边、不填充，视觉权重低于铸造主 CTA；跳转 §3.5 兑换代币页并预填 `?symbol=<LOVE20>&from=<原生币>&to=<LOVE20>`（与下方资金分支同一落点）。数据：`calculateMintCost(name)`、`LOVE20.balanceOf`。
4. **资金分支卡（仅不足时出现）** — 见下。
5. **按钮区** — 两段式「1 授权」「2 铸造」（§4.1）；下方折叠一行「为什么要两次确认？第一次只是允许合约扣款，不会立刻扣钱；第二次才是铸造。」
6. **收据** — 成功后整页替换为收据（§4.3）：`#{memberId}` + 链上 `memberName`、实际支付（来自 `MemberMinted.cost`）、哈希、下一步。

**资金分支卡（余额不足时的唯一分叉）**

| 条件 | 文案 | 按钮 |

| 空投可铸造 | 「你还有空投份额可以铸造，预计 {X} LOVE20，铸造后就够了。」 | 空投铸造（主） |

**状态**：未连接「连接钱包后铸造身份 NFT。」+ 连接按钮 · 名称空（按钮禁用，无报错）· 检查中（按钮禁用）· 不可用（按钮禁用 + 原因：重名 / 太长 / 非法字符 / dev-test 未以 `Test` 开头）· 余额不足（显示分支卡，主按钮改为分支 CTA）· 待授权「1 授权」· 授权中「授权中…」· 已授权（阶段 1 消失，只留「铸造」）· 待铸造「2 铸造」· 铸造中「铸造中…」· 成功（收据）· 失败（错误卡 + 重试，保留名字）。

- 用户余额不足时，应看到「还差多少」和一条明确出路（空投铸造或兑换），且该出路指向 LOVE20；有资格时分支按钮为「空投铸造」。

- 用户完成授权后，应停在本页、按钮原地变为「铸造」，不跳转、不刷新。
- 用户铸造成功后，应看到含 `#id`、名字、实际支付与哈希的收据，并能一键去「我的 NFT」。
- 用户刷新页面时若有未完成交易，应看到恢复后的 pending 或收据，而不是空白表单。

### 3.4 空投铸造

**用户一句话目标**：三十秒内知道自己有没有、能铸造多少、现在能不能铸造，并一次完成。
**进入条件与前置**：需连接；S6 已铸造态的金额必须能在**任意设备**上显示（不得依赖本机缓存，见 [CI-014](../contract-issues/014-airdrop-claimed-amount-not-readable.md)）；资格来自部署时固定的 Merkle 快照（share + proof，按需 `import()` 的快照 JSON，**不进首屏包**）。空投代币固定为首币 LOVE20，**与当前社区无关**，切换社区不改变本页内容。页头标题只写「空投铸造」，**不设副标题或解释句**；「本次空投：LOVE20」是状态卡首行的一行元信息，快照机制收进「规则」折叠。界面任何位置都不写「领取」；合约动作 `claim` 只保留在代码、合约与术语表里。

**区块顺序**
1. **状态与金额卡** — 七态之一（见下）；首行元信息「本次空投：LOVE20」；金额行「预计可得 {X} LOVE20」+ 小字「按铸造时的池子余额与剩余份额计算，别人铸造后金额会变。」数据：`claimableAmount(LOVE20, wallet, share, proof)`、`balanceOf(airdrop)`。
2. **主按钮区** — 仅「可铸造」态出现「空投铸造」。
3. **规则折叠** — 「首币与当前社区无关」「快照来源」；空投合约地址在 `/about`（§3.8），折叠里不再重复；「为什么金额会变」已在金额卡内联小字里说过，折叠不再重复。
4. **收据** — 铸造成功后整页替换（§4.3）。

**状态**：S0 未连接 / S1 加载 / S2 错误 / S3 空（无资格）/ S4 暂不可铸造 / S5 可铸造 / S6 已铸造；pending 走 §4.2（铸造中 → 已上链），成功即 S6 收据（§4.3），失败回到 S5 + 错误卡。

**七态文案（互斥，同屏只显示一条）**

| 状态 | 文案与按钮 |

| S0 未连接 | 「连接钱包后查看你的空投份额。」+「连接钱包」 |
| S1 读取中 | 金额与状态行骨架；不显示 `0` |
| S2 读取失败 | 「空投数据暂时读不到。你的资产没有变化。」+「重试」 |
| S3 无资格 | 「这个钱包不在空投名单里。」+「空投只面向快照时的参与者，不影响你现在参与。」+ 主「用 BNB 兑换 LOVE20」次「回首页」 |

**主 CTA 与次要入口**：整页只有一个实心按钮；S5 是「空投铸造」，其他态的主按钮是各自的出路（连接 / 重试 / 兑换）。次入口固定为「回首页」或「复制链接」。

**加载骨架**：状态行一条短灰条 + 金额一条 40% 灰条 + 按钮整块灰；骨架期间不出现任何数字（`0` 也不渲染）。
**验收**

- 铸造成功后金额应来自本笔交易回执（`AirdropClaimed.amount`），刷新后仍显示「已铸造 {X} LOVE20」；换浏览器、清缓存后用同一钱包打开，数量必须一致。
- 已铸造但换设备打开时，仍应显示真实的已铸造数量（读合约 `claimedAmount`）；该只读方法上线前，允许只显示「已铸造」+ 区块浏览器入口，但不得编造金额、也不得把本机缓存当成链上事实。

### 3.5 兑换代币

**用户一句话目标**：把任意一种代币换成另一种，事前知道会走哪条路径、能拿到多少、最少拿到多少。
**进入条件与前置**：需连接；**任意代币 ↔ 任意代币**，包括链原生币、包装原生币与任意已发现的社区代币，不再限定原生币买入。代币集合只来自链上与环境包：社区代币用 `Launch.tokens(offset, limit, reverse)` 分页发现，用 `Launch.parentToken(token)` / `Launch.childTokens(parent, offset, 20, reverse)` 还原父子树，用 `Launch.tokenAddressBySymbol(symbol)` 做符号精确查找；除环境包提供的原生币与包装原生币两个条目外，**不维护任何硬编码代币清单**。`?from=<symbol>&to=<symbol>` 决定兑换对并写入 URL，可深链分享；`?symbol=` 仍是当前社区上下文，与 from/to 相互独立。缺省时 `from` 取环境包原生币、`to` 取当前社区代币（`?symbol=` 解析结果，解析不到回退首币），解析完成后把这两个缺省值 `replace` 进 URL。原生币用环境包配置的符号寻址（本地 anvil 为 `ETH`，BSC 为 `BNB`），不写死「BNB」。from/to 任一未知、相同或解析不到 → 中性错误态（见下），不崩溃、不白屏。

**区块顺序**
1. **兑换卡（顶部，两行）** —
   - 「从」：金额输入 + 代币选择器（显示 `symbol()`）+ 当前代币余额 + 「全部」快捷键；输入原生币时「全部」按「余额 − 预留网络手续费」计算并标注「约」。
   - 中间 ⇅ 方向按钮：交换 from/to 并重报价；原生币与包装原生币互逆时仍用同一按钮。
   - 「到」：只读金额（标签「预计可得」）+ 代币选择器（只显示 `symbol()`，不显示余额）。
   两个选择器打开同一个「选择代币」抽屉：分组「原生币 / 包装原生币 / 社区代币」；社区代币按 `Launch.tokens` 分页（每页 20，「加载更多」），顶部搜索框用 `Launch.tokenAddressBySymbol` 精确匹配 symbol。选中即用 `replace` 写回 `?from`/`?to`，保留 `?symbol=` 与其他 query，不新增历史记录。
2. **信息块（全页唯一）** — 主信息三行：
   - 「1 {FROM} ≈ {rate} {TO}」；
   - 「路径 {A} → {B} → {C}」（低权重、单行，最多 3 跳；即使只有 1 跳也显示，例如 `TestWETH → TestLOVE20`）；
   - 「最少到账 {minOut} {TO}」+「最多可接受的价格变化 [0.1% / 0.5% / 1.0% / 自定义]」（默认 0.5%）。
   以上为主信息；手续费率能读到才写「手续费率 {fee}%」，读不到只写「以链上费率为准」；价格影响 >1% 才显示「价格影响 约 {x}%」，读不到就不显示该行。任何情况下都不猜数字。
   报价状态：只显示剩余 `{n}s` 倒计时（同一行不再写「更新于 {n} 秒前」）；随新区块或 30 秒定时重报价。倒计时归零且新报价未返回时，标「报价已过期」并禁用主按钮，直到新报价返回。
3. **主按钮** — 一个主操作位：ERC20 输入且 `allowance(wallet, router) < amountIn` 时为两段式「1 授权」「2 兑换」，授权确认后阶段 1 收成「✓ 已授权」、同位置只留「兑换」；原生币输入或 allowance 已足够时从开始就是单按钮「兑换」。明细见「执行阶梯」。
4. **收据 / 错误卡** — 成功后整页替换为收据（§4.3）：实际到账金额从回执中交易对的 `Swap` 事件解析（按方向取 `amount0In/amount1In/amount0Out/amount1Out`），ERC20 输入另核对 `Transfer`，**不用报价当结果**；原生币 ↔ 包装原生币的收据取 `WETH9` 的 `Deposit`/`Withdrawal` 金额。失败卡保留 from/to 与金额，给「重新报价并重试」，说明「没有成交，只消耗了网络手续费」。不再有高级折叠：交易对与 Router 地址在 `/about`（§3.8）；价格保护参数与路径 / 最少到账仍留在上方信息块。

**路径解析**
- 交易对图是一棵以包装原生币为根的父子树：每个社区代币只与自己的父币有 Uniswap V2 交易对（`Launch` 建币时 `createPair(token, parent)`）。在 `factory.getPair(a, b)` 能确认的交易对图上找**最短路径**（通常就是 A 上溯到最近公共祖先再下行到 B）；相邻两枚代币必须 `factory.getPair(a, b) != 0x0` 且 `getReserves()` 两边储备都非零。原生币在路由里以包装原生币参与（`Router.WETH()`），界面显示仍写原生币符号。
- 最多 **3 跳**。例：`WBNB → 父币 → 子币`；本地为 `TestWETH → TestLOVE20`。无路径、超过 3 跳、或路径上任一交易对储备为零 → 该方向不可兑换，说明卡在哪一跳，给「换个代币」与「回首页」。
- 原生币 ↔ 包装原生币是 **1:1 包装/解包**，不经过交易对、无手续费与价格影响（`WETH9.deposit` / `withdraw`）；界面汇率行只写「1 X = 1 Y（包装/解包，不经过交易对）」，「无手续费」只由手续费行承担。界面仍用「兑换」按钮与同一套收据。

**报价与保护**
- 报价只调 `Router.getAmountsOut(amountIn, path)`，不在前端复刻 AMM 公式；提交前再读一次，用最新报价重算 `amountOutMin = quote × (1 − 容忍度)`（向下取整）。
- 「最多可接受的价格变化」默认 0.5%，可见档位 0.1% / 0.5% / 1.0% / 自定义；改变档位立即重算「最少到账」。自定义值限制在 0.01%–50%（超出给行内错误），不把「授权缓冲」当滑点。
- 价格影响用 `getReserves` 隐含的边际价与 `getAmountsOut` 成交均价之差估算；> 1% 时显示「价格影响 约 {x}%」，> 10% 时追加红色提示「这笔兑换会明显改变池子价格，继续前请确认。」与「继续」二次确认（提示里不再重复百分比）。≤1% 不显示这一行。
- **手续费率不写死**：优先读交易对/部署暴露的费率字段，能读到才显示「手续费率 {fee}%」并注明「已含在报价里」；读不到就不显示百分比，只写「以链上费率为准」。本地 anvil 为 0.30%、BSC PancakeSwap 为 0.25%，这两个数字只作为部署事实，不作为常量进入报价或计算。
- 报价随新区块或 30 秒定时刷新；信息块只显示倒计时（不再显示「更新于」）。倒计时归零即把报价标为「报价已过期」并禁用主按钮；新报价返回后恢复。失败可见重试，不静默用旧报价提交。

**执行阶梯**

| 输入 / 输出 | 授权 | 调用 |
|---|---|---|
| ERC20 → 任意 | 是：授权额 = 本次输入金额，精确到 wei，不加缓冲、不授权无限额 | `swapExactTokensForTokens`（ERC20 输出）或 `swapExactTokensForETH`（原生币输出） |
| 原生币 → ERC20 | 否：单按钮「兑换」 | `swapExactETHForTokens` |
| 原生币 ↔ 包装原生币 | 否 | `WETH9.deposit` / `withdraw`，1:1 |

- ERC20 输入且 allowance 不足：两段式「1 授权」→ 授权确认后停在本页，阶段 1 收成「✓ 已授权」，同位置变「2 兑换」或「兑换」；授权额精确等于 `amountIn`，不改写成报价或加缓冲。
- 授权与兑换的按钮文案走 §4.2 三态：`授权中…` → `确认中…` → 成功/失败；兑换同。原生币输入没有授权阶段。

**状态**
- 未连接：「连接钱包后兑换。」+「连接钱包」。
- 未配置（test/prod 空地址簿）：「这个环境还没有配置兑换。」+「回首页」；不发起任何链上请求，不崩溃。
- 加载：余额、路径与报价显示骨架，不渲染 `0`。
- 空输入：主按钮禁用，无报错。
- 报价中：主按钮禁用 + 金额骨架。
- 可兑换。
- 余额不足：「{FROM} 不够，还差约 {x}」；原生币输入同时提示需预留网络手续费。
- 池子为空（见下）。
- 无路径 / 超过 3 跳：「这个方向没有可用的兑换路径。」+「换个代币」+「回首页」。
- from/to 未知或相同：「这个兑换对不可用。」+「链接里的代币符号可能不存在，或者这个代币还没发射。」+「选择代币」+「回首页」。
- 报价失败：「价格暂时读不到。」+「重试」。
- 价格影响 > 10%：红色提示 + 需二次确认。
- 授权中 / 确认中 / 上链中 / 成功（收据）/ 失败（错误卡）。

**池子为空（本协议的真实默认态）**
发射代币时只 `createPair` 建池，不注入流动性，所以新社区大概率无储备。文案：标题「这个兑换对还没有可兑换的流动性。」+ 说明「发射代币时只创建了交易对，没有注入资金，所以现在换不了。」+ 主「换个代币」（打开代币抽屉）+ 次「回首页」+ 高级「查看交易对地址」。**不承诺通知，不出现「稍后重试」这种无信息的按钮。**

**主 CTA 与次要入口**
- 一个主操作位：「兑换」；需要授权时是「1 授权」→「兑换」（§4.1 的两段式）。次入口只有「回首页」。
- 页面只有两个代币选择器、两个金额、一个主操作位、一个信息块；**不做订单簿、限价单、K 线或图表**。

**死路处理**：空池、无路径、from/to 无效、余额不足、报价失败、报价过期都有明确下一步；失败重试必须重新报价并刷新 `amountOutMin`；不出现只有一句话的终局。
**加载骨架**：输入框可先输入；选择器显示骨架；信息块 3 行灰条 + 按钮灰块；余额与报价就绪后原地替换，不整页 spinner。
**验收**
- 用户可以从任意已发现代币换到任意另一种（含原生币、包装原生币与社区代币），反向同样可用。
- 深链 `?from=ETH&to=TestLOVE20` 能直接打开并报价；`?symbol=` 切换社区不改变 from/to，也不清空金额。

- ERC20 输入需要授权时，授权额等于本次输入金额；原生币输入不出现授权步骤。

## §4 横切交互规范

### 4.1 授权 → 执行：按钮阶梯
- 只在需要时出现第一阶段：`allowance(wallet, memberNFT) ≥ 本次应付` 时直接显示单按钮「铸造」，回访用户永远只看到一次确认。兑换页同理：`allowance(wallet, router) ≥ amountIn` 时直接显示「兑换」。
- 铸造的授权额 = 本次报价 × 1.01（按需 + 1% 缓冲），不授权无限额；**兑换的授权额 = 本次输入金额，精确到 wei，不加缓冲**（§3.5）。文案必须写「只是允许合约最多扣这么多，不会立刻扣钱」。
- 阶段 1 成功后**不跳转、不刷新、不弹 toast**：同一位置的按钮就地变为「铸造」，阶段 1 收成一行「✓ 已授权」。
- 按钮文案固定：`1 授权` → `授权中…`（钱包确认）→ `上链中…` → `已授权`；`2 铸造` 在授权确认前禁用，确认后同位置变 `铸造` → `铸造中…`。兑换页同构，阶段 2 是 `2 兑换` / `兑换` → `兑换中…`。
- **禁止**把授权缓冲写成「滑点」：参考实现的「滑点：0.1%」实为授权缓冲，不是价格滑点，属于错误标签。
- 用户拒签，或授权后价格上行使额度不够 → 按钮回到可点，文案「授权不够这次使用，需要再授权一次」，不跳页、不清空输入。

### 4.2 交易 pending 语法
- 三态，措辞固定：**等待你在钱包确认** → **已提交，等待上链** → **已上链 / 没有成功**。不把三者合并成一个「加载中」；授权阶段同样走这三态，按钮写「授权中…」。
- 任务对象 `{ id, kind, tokenAddress, memberId?, amount?, hash?, state, startedAt }` 存本地；有 hash 时刷新用 `getTransactionReceipt` 恢复；无 hash 视为未提交，中性文案「上次的操作没有提交」。
- 展示位置：按钮内文案 + 头部下方 36px 任务条；也**不做全屏 LoadingOverlay**，不锁页面（参考实现的全屏遮罩是漏斗漏点）。
- pending 中允许切页、切社区；任务条常驻，点击回到发起页。同一时刻只允许一个写操作在途，其余**写操作**按钮禁用并注明「有一个操作正在进行」；纯本地选择（如「使用此身份 NFT」）不受影响。
- 先落本地收据、再刷新数据，避免「数据已变但用户没看到收据」。

### 4.3 成功收据（取代 toast + 2 秒跳走）
- 收据是**页面内状态**：不自动跳转、不 2 秒消失。标题 + 你得到什么 + 哈希 + 两个下一步。
- 必备字段：结果（铸造成功 / 兑换完成 / 已铸造）· **你得到什么**（`#memberId` + 链上 `memberName` / 实际到账数量 / 已铸造金额）· 实际支付（若有）· 交易哈希（复制 + 浏览器链接，收在高级里）· 下一步（主「回首页」或「去我的 NFT」，次「再去兑换」或「去铸造」）。
- 所有数字来自本笔交易回执：`MemberMinted.cost/name/memberId`、ERC20 `Transfer`、`AirdropClaimed.amount`；**不用前端估算值**。
- 收据可刷新、可后退、不会被切换社区清掉；刷新后从本地任务恢复。

### 4.4 错误文案映射（消费 `registry/errors.json`）
- 原则：**写结果与下一步，不写机制**。不出现 gas、allowance、nonce、revert、selector、`0x…` 堆栈、HTTP 状态码。
- 三层：`selector → 英文错误名（errors.json）→ 中文结论 + 下一步`；未收录的 selector 落到「交易被合约拒绝」+ 哈希 + 「重试」。

| 情形 | 文案（结论 + 下一步） |
|---|---|
| 用户取消（4001） | 「你在钱包里点了取消，没有扣款。」/ 重试 |
| 网络手续费不足 | 「BNB 不够付手续费。请先转一点 BNB 进来。」/ 复制地址 |
| 代币余额不足 | 「LOVE20 不够，还差 {x}。」/ 空投铸造、兑换 |
| 授权不足 | 「授权额度不够这次使用。」/ 再授权一次 |
| `NameAlreadyExists` | 「这个名字已经被用了。」/ 换一个名字 |
| `NameTooLong` / `NameInvalidCharacters` | 「名字太长 / 含有不可用的字符。」/ 修改名字 |
| 流动性不足 / 价格变动保护 | 「价格变化太大，这笔交易没有成交。」/ 重新报价 |
| 超时 / RPC 失败 | 「网络没有及时响应，交易状态未知。」/ 查看哈希 + 重试（不重复发送） |

### 4.5 估算类信息标注
- 三档标记：**预计**（空投可铸造金额、铸造价格、兑换报价与最少到账）、**约**（手续费预留、价格影响、任何倒计时）、**精确**（余额、已铸造金额、已上链数量）。
- 每个预计值必须带半句「为什么会变」：空投「别人铸造后金额会变」；铸造「价格随已铸造数量变化」；兑换「价格随池子变化」。
- 基于 Phase 的倒计时只能用「区块差 × 观测出块时间」估算，写「约 X 分钟」，并说明时间片长度会被协议调整（`Phase` 以区块计量，不是时间戳）。M0 页面不显示轮次倒计时；此规则适用于后续页面。
- 提交前重读一次链上；报价超过 30 秒视为过期，需重新报价。

### 4.6 移动端钱包兜底阶梯
- 顺序：① 用系统浏览器打开（Universal Link / `window.open`）② 扫码（二维码内容 = **当前页面 URL**，不是 WalletConnect URI；M0 只有注入钱包）③ 复制链接 ④ 说明「在钱包 App 内置浏览器里粘贴此链接」。
- 触发：应用内浏览器 UA 命中 → **连接之前**显示顶部横幅；没有 `window.ethereum` → 连接按钮直接打开兜底抽屉，不转圈、不报错。
- 抽屉文案：「这个浏览器里没有钱包。用下面任意一种方式打开，就能连接。」+ 三个按钮 + 一行「已经装了钱包？在钱包 App 的浏览器里粘贴这个链接。」
- 桌面放大二维码，移动优先 Universal Link 与复制；二维码本地生成，不调用第三方服务。没有兜底就不放「连接钱包」按钮——任何「点了没反应」都是漏斗漏点。

## §5 不照抄清单

来源：`.research/tkm-funnel-pages.md` 的 Do not copy 段与跨页结论，`.research/tkm-connect-and-nav.md` 的弹层结构。

| # | 参考实现的表现 | 我们的替代 |
|---|---|---|
| 1 | 铸造成功后 toast + 2 秒自动跳回列表，成功瞬间被丢掉，哈希与「得到了什么」都看不到 | 页面内收据（§4.3）：哈希 + 得到什么 + 两个下一步 |

| 3 | 余额读取时整页 `LoadingIcon`，表单完全不可用 | 表单先可填，费用卡与按钮用骨架，数字就绪后原地替换 |
| 4 | 参考实现原文：空投「无可领取空投。」与「活动结束后可领取。」都是终局，无原因、无出路 | 七态 + 区分「池子空 / 份额为 0 / 不在名单」+ 主按钮给出路 |
| 5 | 两个按钮只靠 `1.` `2.` 编号表达顺序，从不解释为什么两次 | 折叠一行「第一次只是允许扣款，第二次才是铸造」 |

| 7 | 神秘 UI：失败只有一行红字且无重试；`balance <= 3` 时隐藏持有数量 | 错误卡 + 重试 + 原因；数量永远显示真实值（含 ≤3） |
| 8 | 代币弹层多层入口（锚定 / 返回父币 / 其他子币 / 子币列表 / 代币信息） | 父币 + 子币 + 最近访问 + 复制链接，最多两层，无锚定 |

## §6 M0 验收脚本大纲

**前置**：`vite preview --base=/<repo>/` 跑构建产物（不是 dev server）；Playwright + 注入型测试钱包（EIP-1193 stub + 本地私钥签名）；链 = 本地 anvil 31337，`make bootstrap` 起链并 seed：首币池注入 **200,000 LOVE20 + 100 WETH**（`SEED_LIQUIDITY_TOKEN_AMOUNT=2e23`、`SEED_LIQUIDITY_PARENT_TOKEN_AMOUNT=1e20`，见 ADR-0004）；dev 的地址与 ABI 只读 `anvil/export/deployments/anvil31337_dev.json` 与 `anvil/export/abis/*.json`（前端消费副本 `src/config/deployments/anvil31337_dev.json`）。fixture 的 anvil 0–9 号账户都在快照内（0–4 已铸造，5–9 有份额未铸造），所以主流程必须用**不在快照内**的新私钥（先从一个 anvil 账户转一点原生币（anvil：ETH）作 gas）。GitHub owner 与仓库名已定（`LOVE20BSC/interface-dev` / `interface-test` / `interface`，见 ADR-0002 §4），环境变体由 CI 按仓库名关键字选择（含 `dev` → dev，否则含 `test` → test，否则 prod；`vars.VITE_ENV` 可覆盖），发布命令为 `pnpm release-to <target>`（ADR-0002 §4）；**只有里程碑最终排期〔待定〕**。`--base` 由 CI 变量注入，脚本不得硬编码。

1. **打开 `/` → 未连接 → 连接**：未连接态 = 左侧社区标识 + 问候「你好」+「连接钱包」；底部 5 tab 可见；治理/行动占位页显示「即将上线」、一句说明与「回首页」，无空白、无半成品表单。点「连接钱包」→ 左侧标识隐藏、药丸变为两区，URL 补上 `?symbol=<首币>`。
2. **无身份 NFT → 铸造身份 NFT**：首页问候为「你好」，提醒流显示「你还没有身份 NFT」+「铸造身份 NFT」。点「铸造身份 NFT」→ `/mint`。「我的」页同时显示无身份与「铸造身份 NFT」入口（§3.7）。
3. **进入铸造页（从我的 NFT 空态的「铸造身份 NFT」）** → 名称可输入；费用卡出现「预计 {cost} LOVE20」，下方「我的 LOVE20：0」被标成不足；余额旁有次级「去兑换代币」文字链；不出现整页 spinner。
4. **输入 7+ 字节且以 `Test` 开头的名字**（如 `Teste2e-member`）→ 检查行「可以用」；再输入一个不以 `Test` 开头的名字 → 规则行「名称必须以 Test 开头」仍在，检查行出现「✗ 还没加 Test 前缀」且不能提交；余额不足 → 资金分支卡出现。
5. **点分支卡「用 BNB 兑换」**（本地 anvil 按环境包渲染为「用 ETH 兑换」）→ 落在兑换页且 URL 同时带 `?symbol=<首币>&from=<原生币>&to=<首币>`（不是当前子币）；在「从」输入 `0.05` 原生币（本地 anvil 为 `ETH`）→ 见「预计可得」、路径行与更小的「最少到账」。
6. **兑换** → 依次见「等待你在钱包确认」→「已提交，等待上链」→「已上链」；收据显示实际到账（回执中交易对的 `Swap` 事件；ERC20 输入另见 `Transfer`）与哈希。
7. **前置注入（环境准备，不是用户路径）**：让测试钱包获得 ≥ 一个铸造价的 LOVE20（约 1000 LOVE20）：把步骤 5 的兑换金额提到约 `0.6` 原生币（anvil：ETH），或给测试钱包空投份额；采用哪种〔待定〕，见阻塞点 1。
8. **回铸造页 → 「1 授权」** → 授权确认后**停在本页**，按钮就地变「铸造」，出现「✓ 已授权」。
9. **「铸造」** → 收据：`#{memberId}` + 链上 `memberName` + 实际支付（`MemberMinted.cost`）+ 哈希；点「去我的 NFT」。
10. **我的 NFT** → 摘要「持有 1 个身份 NFT」（一个也显示数量，不隐藏）；`<md` 为卡片行（`NFT #id` + 名字 + 当前徽标），`≥md` 为 NFT 编号 / 名称 / 操作 三列表格；该行「当前」徽标且置顶着色；断开再连，身份仍被选中。
11. **有身份 → 问候 + 我的**：回首页 → `h1` 为「你好，{memberName}」，首页不显示余额、没有「切换身份 NFT」；从底栏进入「我的」看到名字、`NFT #{memberId}`、余额与「兑换」；点「切换身份 NFT」→ 我的 NFT。
12. **有资格 → 空投提醒卡出现且可点**：第二账号（anvil #5：fixture 给了 share、尚未铸造，而且没有身份 NFT——顺带验证提醒卡与身份无关）→ 首页先渲染问候与无身份提醒，快照 chunk 就绪后出现空投提醒卡（「你有空投资格，可铸造 {X} {symbol}」+「空投铸造」，不遮挡问候；两张卡同时存在时只有第一张用实心按钮）→ 进入空投铸造页 → S5 可铸造 → 点「空投铸造」→ 收据金额 = 回执 `AirdropClaimed.amount`；刷新后仍为 S6「已铸造」；换设备（清本地）后只显示「已铸造」。
13. **无资格 → 该卡不出现**：换一个不在快照内的新钱包（同样由 anvil 账户转原生币（anvil：ETH）作 gas）→ 首页不出现资格卡，也没有「无资格」字样或「无需操作」；回到刚铸造完份额的 anvil #5 刷新 → 卡片同样消失（`claimableAmount` 已为 0）。
14. **错误腿**：重名 → 「这个名字已经被用了。」；超额兑换 → 「{原生币} 不够…」；拒绝签名 → 「你在钱包里点了取消，没有扣款。」；三条都不出现 gas / allowance / nonce / `0x`。

**阻塞点（必须显式处理，不得让脚本假装通过）**
- **零资产路径**：dev 参数下 7 字节名字的铸造价约 `1e21`（1000 LOVE20）。本地 bootstrap 已给首币池注入 **200,000 LOVE20 + 100 WETH**（`SEED_LIQUIDITY_TOKEN_AMOUNT=2e23`、`SEED_LIQUIDITY_PARENT_TOKEN_AMOUNT=1e20`，见 ADR-0004），初始价约 `0.0005` WETH/LOVE20；买够一次铸造约需 `0.5` WETH（含 0.3% 手续费，按初始池价估算），所以经济上闭合。但步骤 5 的 `0.05` 原生币（anvil：ETH）只够买约 100 LOVE20，不足一次铸造：要么把该步金额提到约 `0.6` 原生币，要么保留步骤 7 的空投注入。采用哪种〔待定〕。这是步骤 7 存在的原因。
- **dev/test 名称规则**：本地是 dev 变体，铸造名必须以 `Test` 开头（`T` 大小写敏感）；E2E 输入用 `Teste2e-member`，断言链上 `memberName` 与输入逐字相同（`core@72a1604` 后合约不再改写名字）。prod 变体没有该规则。
- 移动端连不上本地 anvil（钱包拒绝 `http:` RPC）；真机验收走测试网或 HTTPS 隧道。
- 铸造价、空投金额、兑换报价都是「预计」→ 脚本断言标签与格式，不断言具体数值；数值断言只用于回执解析结果。
