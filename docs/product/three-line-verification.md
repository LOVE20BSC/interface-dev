# 三线校验规范（理论线 → 合约线 → 前端线）

> owner 2026-11-14 硬要求：数据校验必须三条线**相互独立**，且**以理论线为基准**。理论线不得迎合合约实际值或页面实际显示值——它只回答「按公式和初始状态，正确答案是多少」。

适用范围：所有会读写链上数值的页面（转账、批量转账、流动性池、代币授权，以及后续任何交易页）。

## 三条线是什么

| 线 | 谁算 | 允许读什么 | 不允许做什么 |
| --- | --- | --- | --- |
| 1 理论线 | 人 + 纯算术脚本（`docs/product/three-line/<page>.md` 里的公式与 Python/纸笔） | 只有：初始状态快照（交易前余额/储备/精度/费率）、页面输入的参数、协议公式（ERC20 加减、Uniswap V2 恒定乘积、Hub 报价公式） | 读页面、读合约结果后再「倒推」答案；用 `cast` 或 UI 的输出当预期值 |
| 2 合约线 | 脚本（`cast` / viem）直接打链 | 只读链上真实数值 | 复用前端的计算结果；把前端的显示值当链上真值 |
| 3 前端线 | Playwright 驱动真实页面（注入钱包） | 只读页面渲染出来的文字/状态 | 在断言里放「差不多」「包含」这类宽松匹配；读合约后再拼答案 |

判定：**三线同一用例的数值必须完全相等**。不相等就是缺陷，先查「谁的公式错了」，不允许改理论线去迁就实现。

## 固定执行环境（保证三线同链同账户）

- **验证链**：每次会话/任务临时起一条专用链，**端口 8566**，从 block 0 clean bootstrap（与已提交部署地址逐字节相同）：
  ```bash
  make -C ../anvil bootstrap PORT=8566        # 约 1 分钟；结束时链在 http://127.0.0.1:8566
  # 用完： make -C ../anvil stop PORT=8566 && make -C ../anvil clean PORT=8566
  ```
  **禁止用 8545（人工链）跑任何校验**，也禁止用 8555（e2e 链）做本规范的合约线写入（e2e 链路有自己的快照语义）。
- **账户**：anvil 固定账户（mnemonic `test test … junk`），**只升级需要的两个**：
  - `#1 0xf39Fd6e51aad88F6F4ce6aB8827279cffFb92266`（有身份 NFT，e2e 默认发送方）
  - `#5 0x9965507D1a55bcC2695C58ba16FB37d819B0A4dc`（收款方/对照账户）
  其余账户按用例需要显式列出。
- **状态隔离**：每个用例前 `anvil_snapshot`，用例后 `anvil_revert`，让用例之间的初始状态完全一致（`cast rpc anvil_snapshot` / `cast rpc anvil_revert <id>`）。
- **前端线**用同一端口渲染：`E2E_ANVIL_RPC=http://127.0.0.1:8566 pnpm e2e`（`e2e/README.md`「覆盖端点」一节允许；套件不会自己起链）。

## 每个任务的交付物（缺一不可）

1. `docs/product/three-line/<page>.md`
   - §0 环境：验证链端口、账户、初始状态（块高、余额、储备、totalSupply、精度）。
   - §1 理论线：用例表（输入 → 公式 → 期望的前后数值，精确到 wei）、舍入规则说明。**必须在写页面前完成**，并在文档里留下「先于实现完成」的时间戳/commit。
   - §2 合约线：每个用例的 `cast` 命令、交易哈希、读回的数值、与理论线的差值（必须 0，非 0 要给公式级解释）。
   - §3 前端线：对应 `e2e/*.spec.ts` 名称、页面显示的具体字符串（如 `1.5 TestLOVE20`）、与理论线的差值（必须 0）。
   - §4 三线对照表：`用例 | 理论值 | 合约值 | 前端值 | 结论`，结论只能是 ✅ 或 ❌（❌ 时写明是缺陷或「合约不支持，已停页记录」）。
2. `scripts/verify/<page>-contract.mjs`（或 `e2e/<page>-contract.spec.ts`）：可重复执行的**合约线**断言脚本，退出码非 0 即失败。
3. `e2e/<page>-numbers.spec.ts`：**前端线**自动断言（精确匹配理论值）。
4. 截图：移动端 390×844、桌面端 1280×800（浅色 + 深色），放进 `docs/product/screenshots/`。

## 用例设计规则（理论线）

- 每个页面至少覆盖：**正常路径 2 个**（含 1 个非整数金额/非整百比例）、**边界 2 个**（余额不足/输入为 0/最大按钮）、**失败回滚 1 个**（交易 revert 后状态不变），批量转账另加**多行混合**（合法行 + 非法行）与**重复地址**，流动性池另加**首次建池（空储备）**与**按比例撤出**。
- 每个用例写清：初始状态 → 输入 → 交易的中间量（如 swap 段实际消耗、LP 精度损失、手续费）→ 终态。
- 舍入：金额输入按 `decimals` 向下截断；LP 最小流动性 1000 被永久锁定；Uniswap V2 手续费 0.30%（本地 dex `SWAP_FEE_FOR_LP_RATIO=3000000000000000`、协议费 0）；Hub 报价 `quoteLp` 返回 `expectedLiquidity` 与 `suggested*Min`。
- 理论线不得写「以链上为准」；若发现合约实现与标准公式不同，**先记录差异**（可能是合约缺陷 → `docs/contract-issues/`），不是改预期值。

## 与门禁的关系

- 三线文档与两个断言脚本是页面任务的**验收条件**，不完整不得结案。
- Lead 复核方式：按文档重跑 §1 的算术、重跑 §2 脚本、重跑 §3 spec，三者必须与文档一致。
