页面显示规则（与实现绑定，先于实现定下）：

- 所有金额走 `shared/lib/format.ts` 的 `formatTokenAmount`（整数部分千分位、小数最多 **6** 位、只截断不四舍五入、去掉末尾 0）。
- 输入解析：每行 `地址 金额`，分隔符为空白或逗号（`0x…,0.2` / `0x…, 0.2` 都接受）；空行忽略；小数超过 `decimals` 时向下截断并在页面提示「已按精度截断」。
- **重复地址（不合并、阻止提交）**：同一地址出现在多行时，后出现的行在文本域下方标出「第 N 行：与第 M 行重复，这一行先不计入，请删掉其中一行。」；该行不生成收款方、不计入合计，主按钮保持禁用，直到用户自己删掉其中一行。合约收到的 `recipients` 永远是用户确认后的唯一地址列表。
- **收款方余额**：提交前用 `nativeBalances(address[])` / `erc20Balances(token, address[])` 一次读回，作为「当前余额」列；交易确认后重读同一批地址，逐行显示差额 `+X` / `未变化` / 异常（差额 ≠ 应到账金额时高亮）。
- **原生可花余额**（仅用于「合计超余额」拦截，不展示手续费）：`available = ETH 余额 − max(0.001 ETH, 收款方数 × gasLimit × 1 gwei)`；`0.001 ETH` 是 `NATIVE_FEE_RESERVE_WEI`，`1 gwei` 是保守的 gas 价假设（页面不显示这个数字，也不显示手续费）。
- `gasLimit` 默认值：原生 **30000**/收款方，ERC20 **60000**/收款方（高级选项可改；范围 21000–1000000/收款方，且 `收款方数 × gasLimit ≤ 30000000`，即单块 gas 上限）。
- 整批原子：页面任何位置都不出现「部分成功」。

## §1 理论线（手算，先于实现）

### 用例 A：原生 5 行，重复地址先拦截 → 删行后 4 个唯一收款方（正常路径 1）

输入（发送方 #6，5 行文本）：

| 行 | 文本 | 解析 |
| --- | --- | --- |
| 1 | `0x9965507D1a55bcC2695C58ba16FB37d819B0A4dc 0.1` | #5 + `100000000000000000` |
| 2 | `0x14dC79964da2C08b23698B3D3cc7Ca32193d9955, 0.2` | #7 + `200000000000000000` |
| 3 | `0x23618e81E3f5cdF7f54C3d65f7FBc0aBf5B21E8f 0.15` | #8 + `150000000000000000` |
| 4 | `0x9965507D1a55bcC2695C58ba16FB37d819B0A4dc 0.05` | **与第 1 行重复**：不合并、不计入，页面标出重复并禁用主按钮 |
| 5 | `0xa0Ee7A142d267C1f36714E4a8F75612F20a79720 0.000001` | #9 + `1000000000000` |

### 用例 C：一行非法（边界 1，前端拦截，不发交易）

输入（发送方 #1，ERC20 模式）：

| 行 | 文本 | 判定 | 页面文本 |
| --- | --- | --- | --- |
| 1 | `0x9965507D1a55bcC2695C58ba16FB37d819B0A4dc 0.1` | 合法 | — |
| 2 | `0x14dC79964da2C08b23698B3D3cc7Ca32193d9955` | 缺少金额 | `第 2 行：缺少金额。` |
| 3 | `0x23618e81E3f5cdF7f54C3d65f7FBc0aBf5B21E8f abc` | 金额非法 | `第 3 行：金额格式不对。` |

理论判定：解析器返回 2 条逐行错误，主按钮 `确认批量转账` 禁用，不发交易，链上余额不变。

合约侧同义情况（纯读取验证）：`batchTransferNative([#5], [0], 30000)` 回滚 `ZeroAmount(0)`；`batchTransferNative([0x0], [1], 30000)` 回滚 `ZeroRecipient(0)`；`recipients.length ≠ amounts.length` 回滚 `ArrayLengthMismatch(1, 2)`。三种情况都不写链。

### 用例 D：合计超余额（边界 2）

D1 ERC20：发送方 #8（`TestLOVE20` 余额 `0`；#5 在用例 A/B 后已不是 0），输入 `0x70997970C51812dc3A010C7d01b50e0d17dc79C8 1`。

- `shortfall = 1000000000000000000 − 0 = 1000000000000000000`。
- 页面文本：`TestLOVE20 不够，还差 1`；主按钮禁用；不发交易。
- 合约侧：`eth_call batchTransferERC20(TestLOVE20, [#2], [1000000000000000000], 60000)` from #8 → 回滚 `ERC20InsufficientBalance(TestLOVE20, #8, 1000000000000000000, 0)`。

D2 原生：发送方 #6（`ETH` 余额 `10000000000000000000000`），4 行各 `2500.125` → `合计 = 10000500000000000000000`。

- `available = 10000000000000000000000 − max(1000000000000000, 4 × 30000 × 1000000000) = 10000000000000000000000 − 1000000000000000 = 9999999000000000000000`。
- `shortfall = 10000500000000000000000 − 9999999000000000000000 = 501000000000000000`。
- 页面文本：`ETH 不够，还差 0.501` + `需要预留一点 ETH 支付网络手续费。`；主按钮禁用；不发交易。
- 合约侧：`eth_call batchTransferNative([#5], [100000000000000000], 30000)` with `value = 0` → 回滚 `NativeValueMismatch(100000000000000000, 0)`；再以 #6 发 `msg.value = 10000500000000000000000`（超过余额）→ 节点/`eth_call` 报 `insufficient funds`。

### 用例 E：整批 revert 后状态不变（失败回滚 1）

发送方 #6，原生 3 行，其中第 2 行收款方是 `TestLOVE20` 代币合约（`0x8aCd…41FF`，没有 `receive`/payable fallback，拒收原生币）：

| 行 | 文本 | 解析 |
| --- | --- | --- |
| 1 | `0x9965507D1a55bcC2695C58ba16FB37d819B0A4dc 0.1` | #5 + `100000000000000000` |
| 2 | `0x8aCd85898458400f7Db866d53FCFF6f0D49741FF 0.1` | 拒收 → 整批回滚 |
| 3 | `0x14dC79964da2C08b23698B3D3cc7Ca32193d9955 0.1` | 不会执行 |

`合计 = 300000000000000000`。

- 合约执行到第 2 行时 `call{value: 0.1 ETH}` 失败 → `NativeTransferFailed(1, 0x8aCd…41FF, 100000000000000000, keccak256(""), 0)`，整个交易 revert：第 1 行的 `0.1 ETH` 也回滚。
- 理论终态：`#5 = 10000000000000000000000`（不变）、`#7 = 10000000000000000000000`（不变）、代币合约 `ETH = 0`（不变）；发送方扣款 `= fee`（交易上链但回滚）。
- 页面：提交前的预余额 4 列不变；错误文案 `第 2 行收款方拒收了这笔转账（对方可能是不接收 ETH 的合约）。整批没有转出，你的资产没有变化。`（页面在提交前会先做一次链上模拟，模拟即失败，因此不会弹出钱包、不发出交易——这也是「资产没有变化」的证据）。

### 用例 F：资产保护（前端拦截，不发交易）

- 第 N 行地址 = 地址簿 `batchTransfer` 自身（`0xc3e5…3690`）→ 页面错误 `第 N 行：不能转给批量转账合约本身。`，主按钮禁用。
- 任意有 bytecode 的合约地址（用例 E 的代币合约）→ 页面显示「有收款方是合约地址」警告与行内「合约」标记，但不禁止提交（由模拟/链上结果给出最终结论）。
- 空地址 0x0 → `第 N 行：收款地址不能是零地址。`；发送方自己 → `第 N 行：不能转给自己。`；地址格式不对 → `第 N 行：地址格式不对，需要 0x 开头的 40 位地址。`

### 用例 G：高级选项 gasLimit 越界（前端拦截，不发交易）

| 输入 `gasLimit` | 判定 | 页面文本 |
| --- | --- | --- |
| `10000` | 低于下限 | `每行执行预算至少 21000。` |
| `2000000` | 高于上限 | `每行执行预算最多 1000000。` |
| `100000` × 400 行 | 合计超单块容量 | `这批交易的计算上限超过一个区块的容量，请减少收款方或调低每行执行预算。` |

### 舍入与截断规则

- 金额输入按 `decimals` 截断：示例 `1.5000000000000000009` → `1500000000000000000`，页面提示「已按精度截断到 18 位小数。」；不四舍五入。
- 页面展示走 `formatTokenAmount`：小数最多 6 位、**截断**；`99,799,097.999998` 原样、`10000000000000000000001` 会显示成 `10,000`（差额由整数 wei 计算，不依赖显示值）。
- 到账差额一律用「重读余额 − 提交前快照余额」的整数 wei 相减，再做 6 位截断格式化；「未变化」只在差额 == 0 时出现。
