页面显示规则（与实现绑定，先于实现定下）：

1. 三态阈值**写死**：`ZERO` = `0`；`UNLIMITED` ⇔ `value >= 2^255`，`2^255 = 57896044618658097711785492504343953926634992332820282019728792003956564819968`；其余 `0 < value < 2^255` 为「具体额度」。`2^255 - 1` 是**具体额度**，`2^255` 是**长期授权**。
2. 具体额度文本 = `${formatTokenAmount(value, 18)} ${symbol}`：整数部分千分位、小数最多 6 位、只截断不四舍五入（`shared/lib/format.ts`）。
3. 具体额度小于最小可见精度（`10^(18-6) = 1000000000000` wei）时，文本为 `< 0.000001 TestLOVE20`，绝不显示成 `0` 冒充「未授权」。
4. 未授权文本 = `未授权`；长期授权文本 = `长期授权`；读取中 = `读取中…`；读不到 = `暂时读不到`。
5. 页面上不出现 `allowance` / `approve` 字样；spender 地址默认展开（缩略显示，完整地址在 `title`，点击复制给「已复制」反馈）——owner 2026-11-14 整改，原「默认折叠」已废弃。
6. 长期授权按钮写入 `maxUint256 = 2^256 - 1`（与旧库语义一致）；撤销按钮写入 `0`。页面只提供这两种额度，不提供自定义具体额度。已是长期授权的行，授权按钮保持禁用但文案为 `已长期授权`（owner 2026-11-14；与 §4.1 全局只读态一致，禁用的 `长期授权` 会被读成"还没完成"）。

## §1 理论线（手算，先于实现）

### 用例 A：未授权（初始态，正常路径 1）

- 代币 `TestLOVE20`、钱包 #1、spender = `router`，链上初始 `allowance = 0`。
- 页面文本：`未授权`；「长期授权」按钮可点，「撤销」按钮禁用。

### 用例 B：长期授权（正常路径 2，含按钮写值）

- 在用例 A 的页面点「兑换路由」行的「长期授权」，确认后写入 `approve(router, 2^256 - 1)`。
- 理论 `allowance_after = maxUint256` = `115792089237316195423570985008687907853269984665640564039457584007913129639935`。
- 判定 `value >= 2^255` → 页面文本：`长期授权`；「长期授权」按钮禁用，「撤销」按钮可点。

### 用例 C：具体额度按 18 位精度截断（正常路径 3）

- 预置链上夹具（直接用 anvil 账户签名，不经过页面）：`approve(stake, 1234567890123456789)`。
- 理论 `allowance = 1234567890123456789` wei = `1.234567890123456789 TestLOVE20`。
- 显示截断到 6 位小数（不四舍五入）：页面文本 `1.234567 TestLOVE20`。
- 「长期授权」「撤销」都可用。

### 用例 D：撤销归零（失败回滚/边界：撤销后状态）

- 在用例 C 的页面点「质押」行的「撤销」，确认写入 `approve(stake, 0)`。
- 理论 `allowance_after = 0` → 页面文本：`未授权`；「撤销」按钮禁用。

### 用例 E：阈值边界（边界 1）

| spender | 预置 `approve` 值（wei） | 判定 | 页面文本 |
| --- | --- | --- | --- |
| `vote` | `2^255 − 1 = 57896044618658097711785492504343953926634992332820282019728792003956564819967` | 具体额度 | `57,896,044,618,658,097,711,785,492,504,343,953,926,634,992,332,820,282,019,728.792003 TestLOVE20` |
| `submit` | `2^255 = 57896044618658097711785492504343953926634992332820282019728792003956564819968` | 长期授权 | `长期授权` |

### 用例 F：最小可见额度（边界 2）

- 预置 `approve(mint, 1)` → `allowance = 1` wei，`formatTokenAmount(1, 18) = 0`（6 位截断）。
- 为不把「已授权但极小」误显示成「未授权」，页面文本 `< 0.000001 TestLOVE20`。

### 用例 G：自定义地址（spender = EOA `0x9965…A4dc`）

- G1 无额度：初始 `allowance = 0` → 页面文本 `这个地址没有授权额度。`，「长期授权」可用，「撤销」禁用。
- G2 有额度：预置 `approve(0x9965…, 2500000000000000000)` → 理论值 `2.5 TestLOVE20` → 页面文本 `2.5 TestLOVE20`。
- G3 走页面「长期授权」：确认后 `allowance = maxUint256` → 页面文本 `长期授权`。
- 非法输入 `0x1234` → 页面即时提示 `这是一个无效的地址，需要 0x 开头的 40 位地址。`，不发起任何读取/交易。

### 用例 H：授权按钮只写两种值（语义边界）

- 页面「长期授权」= `approve(spender, maxUint256)`；「撤销」= `approve(spender, 0)`；两者都不改代币余额，只改 `allowance`。
- 页面交易回执关闭后留在 `/approvals`，列表金额刷新为上表理论文本。

### 舍入与截断规则

- 链上值全部为 wei 整数；页面显示统一走 `shared/lib/format.ts` 的 `formatTokenAmount(value, 18)`：整数千分位、小数最多 6 位、**截断**（`1.234567890123456789` → `1.234567`，绝不进位）；`1 wei` 不显示 `0`，显示 `< 0.000001`。
- 阈值判定只看 wei 值，不看显示文本：`2^255 − 1` 的文本虽长，仍是具体额度。
