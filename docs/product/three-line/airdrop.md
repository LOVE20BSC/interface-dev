## §1 理论线

按协议，满足配置、轮次、未铸造、有效 proof 与 `0 < s <= R` 时：

```text
amount = floor(B × s / R)
B_after = B - amount
R_after = R - s
C_after = C + amount
wallet_after = wallet_before + amount
```

理论只用上述固定输入和整数运算，不调用 `claimableAmount`、前端计算或格式化函数。页面按 18 位精度换算、千分位、最多 6 位小数向下截断，去掉末尾 0；此处是金额的展示规则，不是链上精度损失。

| 用例 | 输入与理论结果 | 页面应呈现 |
| --- | --- | --- |
| A 正常铸造 / 本地快照 | `floor(B*s/R) = 100000000000000000000000000 wei`；池剩 `400000000000000000000000000`，剩余份额 `400000000000000000`，累计金额 `600000000000000000000000000` | 第 1 行整句 `我的份额 10%，预计可铸造空投 TestLOVE20：`；第 2 行只放数量 `100,000,000`（不重复 symbol）；按钮「立即铸造」；回执与重载后已铸造金额相同；阻断 Pages 也成功且远端请求数为 0 |
| B 非整数 / 追加资金 | 池先变为 `500000001234567890123456789`；`amount = 100000000246913578024691357`，除法余数对应 `4/5 wei`，向下取整；池剩 `400000000987654312098765432`；累计金额 `600000000246913578024691357` | 第 1 行整句 `我的份额 10%，预计可铸造空投 TestLOVE20：`；第 2 行只放数量 `100,000,000.246913`（不重复 symbol）；按钮「立即铸造」；回执同金额；原始金额逐 wei 比较 |
| C 轮次未到 | gate 设为当前轮次之后，合约可铸造金额为 `0`，份额和池余额不变 | `还没到可铸造轮次`，不显示预计金额和铸造按钮 |
| D 池余额为 0 | 本地夹具将池余额转出；`floor(0*s/R)=0`，份额仍为 `s` | `你有一份空投，但空投池还没有代币。`，无铸造按钮 |
| E 余额 1 wei / 舍入为 0 | 本地夹具只留 1 wei；`floor(1*s/R)=0`，份额仍为 `s` | `可铸造金额暂时为 0。`，无铸造按钮 |
| F 已铸造 / 重复调用 | 先按 A 铸造，记录金额为 `100000000000000000000000000`，再次调用失败；可再铸造金额 `0`，不再增加余额或消费份额 | 无本地记录也显示 `已铸造 100,000,000 TestLOVE20`，无铸造按钮 |
| G proof 损坏 / 失败回滚 | 正确 proof 的金额仍是 A；只破坏交易中的 proof，合约拒绝，钱包余额 `0`、`claimedAmount=0`、`isClaimed=false`、池余额 `B`、累计金额 `C`、剩余份额 `R` 全部不变 | 真实失败提示，无成功回执；不是伪造 RPC 成功或错误结果 |
| H 不在快照 | 无该账户有效 proof，可铸造金额 `0` | `这个钱包不在空投名单里。`，无铸造按钮 |

D/E 用 Anvil impersonation 从空投池转出代币建立边界初态；不是协议公开的提款功能。G 的前端线模拟钱包损坏 proof，仍发送给真实合约，并读取实际失败交易。失败交易的 ETH gas 不属于“代币余额不变”。轮次页的动态分钟倒计时不参与金额三线比较。

独立复算（仅标准库整数运算）：

```bash
/usr/bin/python3 - <<'PY'
B, R, s = 5 * 10**26, 5 * 10**17, 10**17
for amount, pool in [(10**26, B), (100000000246913578024691357, B + 1234567890123456789)]:
    assert pool * s // R == amount
    print(amount, pool - amount, R - s, B + amount)
assert 0 * s // R == 0
assert 1 * s // R == 0
PY
```
