## §1 理论线（手算，先于实现）

### §1.1 记号与舍入

| 记号 | 含义 |
| --- | --- |
| `R_A` / `R_B` | 交易对按本次存款方向排列的两侧储备（A = 社区代币，B = WETH / 原生币） |
| `a` / `b` | 用户填写的两侧期望数量（单边模式另一侧为 `0`） |
| `S` | pair `totalSupply()`（deposit 之前） |
| `f` | 手续费后仍参与兑换的比例 = `1 − 0.003 = 0.997 = 997/1000`（Hub `_swapFeeFraction` 约分后 `997e15 / 1e18`） |
| `t` | Hub 先拿去 swap 的输入数量（`amountToSwap`） |
| `y` | swap 输出（`amountOutFromSwap`），走 Router `getAmountOut`：`y = amountIn·997·R_out / (R_in·1000 + amountIn·997)`，向下取整 |
| `(pA, pB)` | prepared = 换完后真正留在 Hub 手里的两侧数量 |
| `(uA, uB)` | usable = `_optimalAmounts` 按储备比截出来的两侧数量 |
| `L` | 本次铸出的 LP，`L = min(uA·S / R_A', uB·S / R_B')`，向下取整；首次注资（`S = 0`）时 `L = sqrt(uA·uB) − 1000` |

舍入：Solidity 全整数运算，每一步除法与 `Math.sqrt` 都向下取整；本文件所有中间量都用同一规则算，不先取整再代入公式。

### §1.2 闭式公式（独立推导，不看 quote）

**单边加池的 swap 量 `t`**：Hub 要求「换完后两侧数量之比 = 换完后池子储备之比」
`(R_A + t) / (R_B − y) = (a − t) / y`（A 侧为输入侧时），代入恒定乘积输出
`y = f·t·R_B / (R_A + f·t)` 后消去 `y`，得到一元二次方程

```
f·t² + R_A·(1 + f)·t − a·R_A = 0
t = ( sqrt( R_A²·(1 + f)² + 4·f·R_A·a ) − R_A·(1 + f) ) / (2·f)
```

（合约 `_amountToSwap` 用 `inner = R_in²·sum² + (4·fn·fd·R_in·imbalance)/(R_out + amountOutAlready)`、`sum = fn + fd`，与上式逐项等价，只是把 `1 + f` 写成分数并约分，避免精度损失。）

- **社区代币侧单边**：`R_in = R_A`、`R_out = R_B`，swap 方向 A→B，`y` 出自 `getAmountOut(t, R_A, R_B)`；`pA = a − t`、`pB = y`、`R_A' = R_A + t`、`R_B' = R_B − y`。
- **原生币侧单边**：`R_in = R_B`、`R_out = R_A`，swap 方向 B→A，`y` 出自 `getAmountOut(t, R_B, R_A)`；`pA = y`、`pB = b − t`、`R_A' = R_A − y`、`R_B' = R_B + t`。

**按比例截断**（`_optimalAmounts`）：`uB = pA·R_B'/R_A'`；若 `uB > pB` 则 `uA = pB·R_A'/R_B'`、`uB = pB`，否则 `uA = pA`。（单边模式下题库给出的 prepared 本身就是配平的，所以 `usable = prepared`。）

**LP 铸出**：`L = min(uA·S / R_A', uB·S / R_B')`（`S ≠ 0`）；首次注资 `L = sqrt(uA·uB) − 1000`。

**我的份额与撤出**（owner 2026-11-14：撤出输入的是 **LP 数量**）：`share = LP / S`；撤出 `lp` 时 `outA = lp·R_A / S`、`outB = lp·R_B / S`（都向下取整，`S`、`R` 取撤出前值）。页面上的 25% / 50% / 75% / 100% 只是快捷按钮：点一下把 `lpForPercent(LP, 比例)` 算出的 **LP 数量填进输入框**（输入框按展示规则截断到 6 位小数，交易仍用完整 18 位，所以 100% 能撤干净），用户仍然可以手改这个数量；页面不显示「最多可撤出」，只显示「预计收到约 X + Y」。
