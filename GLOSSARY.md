# LOVE20 界面领域词汇表（GLOSSARY）

本仓库是 LOVE20（BSC）协议的前端界面。本文件定义**界面语言**：用户看到的中文、这些中文对应的权威术语，以及代码/合约层使用的英文名。

术语权威顺序：`matt-gov/CONTEXT.md`（唯一权威）→ `matt-gov/docs/specs/**` → 组织级 `docs/{acceptance,dev-standards,naming-standards,error-standards}.md`。本文件与 `CONTEXT.md` 冲突时，以 `CONTEXT.md` 为准。

本文件只收领域术语，不含实现细节、函数签名、页面结构与技术选型。交互语言为简体中文；英文仅出现在代码、合约、路径与需要保留原文的专有名词中。

---

## 文案纪律

以下六条为硬约束。写界面文案、错误提示、帮助页、披露页时逐条对照。

**1）中英分工与“激励 / Reward”口径**（`CONTEXT.md` 开篇，逐字）

> **术语约定**：BSC 版中文继续使用“激励”和“铸造激励”，英文合约、接口和状态统一使用 `Reward` 及其派生名称。`Reward` 表示协议按规则准备的激励额度，可被预留、铸造、分配或销毁，不仅指已经到账的金额。

配套（`matt-gov/AGENTS.md`，逐字）：

> 文档、地图、票据、ADR 和讨论结论默认使用中文；合约、函数、接口、仓库、路径、命令和专有名词保留原文。

**2）不得把协议铸造写成“某人发奖励/发代币”**（`CONTEXT.md`「Proposal Target」，逐字）

> **Proposal Target**：Proposal 的激励铸造接收主体。Target 可以是普通地址或合约；合约型 Target 是否接收回调由 `targetMode` 决定。代币由协议按规则铸造，不表述为某人发放代币。

推论：界面上不出现“项目方发放”“官方空投奖励”“某人给你发币”，也不把协议激励写成“领取 / claim / 一键领取”——那会把协议的**铸造**说成用户去**取**。发射者只是**指定接收地址**；`distributor` 的中心化与否只描述它后续的分配方式。空投合约的链上动作确实叫 `claim`，但界面仍统一写“铸造空投份额”，**不得**写成“领取空投”；“领取”只允许出现在引用合约原文的代码/接口说明里，不进入任何面向用户的文案（协议激励语境尤其禁止）。

**3）`Phase` 与 `Round` 不得互为别名**（`naming-standards.md` §九，逐字）

> `Phase` 与 `Round` 是本协议最容易写错的一对：`Phase` 是出块时间片（`currentPhase`、`promisedWaitingPhases`），`Round` 是治理轮（`currentRound`、`round`）。两者不互为别名，也不得用 `period`/`epoch` 代替任何一个。

**4）跨仓一词一义**（`naming-standards.md` §十「跨仓术语」，逐字）

| 概念           | 唯一写法       | 禁用                                              |
| -------------- | -------------- | ------------------------------------------------- |
| 社区代币地址   | `tokenAddress` | `token`（`address` 类型时）、`tokenAddr`、`erc20` |
| 成员身份       | `memberId`     | `account`、`user`、`id`                           |
| 链群           | `groupId`      | `group`（`uint256` 类型时）                       |
| 行动           | `actionId`     | `action`、绑定后的 `proposalId`                   |
| 提案（未绑定） | `proposalId`   | `actionId`                                        |
| 验证人         | `verifierId`   | `validator`                                       |
| 提供者         | `providerId`   | `sponsor`                                         |

**5）中文为主**：界面文案、错误提示、帮助与披露页一律中文；错误名、事件名、ABI 字段、合约名、命令保留英文原文。不写中英并排的冗余标签（如“铸造 Mint”），真需要原文时放在高级视图或括号内。

**6）同一概念一页只能有一个叫法**（`domain-model.md` §4.8 的直接推论）

- 界面写“激励 / 铸造激励 / 预留 / 销毁”，不写“奖励 / 发放 / 空投奖励”。
- 空投页统一写“铸造空投份额 / 已铸造”，不写“领取空投 / 已领取”；`claim` 只作为合约术语存在。
- `memberId` 不写成“账号 ID”或“用户 ID”；`groupId` 不得引出第二套群体身份。
- 按钮、状态徽标、帮助页、错误文案必须用同一个词，不得为了“通俗”另造同义词。

## 用户语言 ↔ 链上术语（仅限界面）

这一节是**翻译表**，不是新术语。左边是可以出现在界面上的说法，右边是它指向的链上概念。

| 界面文案                                  | 链上/领域术语                          | 说明                                                                                      |
| ----------------------------------------- | -------------------------------------- | ----------------------------------------------------------------------------------------- |
| 我的 NFT / 身份 NFT                       | 成员身份 NFT（MemberNFT）              | 一个 NFT = 一个身份；不是头像，不是会员卡。                                               |
| 我的激励                                  | 激励（Reward）                         | 是“已预留 / 已铸造”的额度，不是承诺到账的金额。                                           |
| 铸造激励                                  | 铸造激励（mint reward）                | 按钮写“铸造激励”，不写“领取”，不写“claim”。                                               |
| 已预留                                    | 预留（reserve）                        | 本轮已划出、尚未铸出的额度；后续可能被销毁。                                              |
| 链群行动 / 链群服务 / LP 行动             | GroupAction / GroupService / LP Action | 三个行动类型。LP 没有验证阶段；链群服务复用链群行动的验证结果，其验证阶段不需要用户操作。 |
| 投票阶段 / 加入阶段 / 验证阶段 / 铸造阶段 | 各层 Round 内的阶段                    | “阶段”只指业务阶段。Phase 是时间片，不叫阶段，不出现在主界面。                            |
| 治理第 N 轮                               | 治理轮（governance Round）             | `Phase N` 即治理轮 N；激励在该 Phase 结束后才准备与铸造。                                 |
| 第 N 轮（带层前缀）                       | Round                                  | 不同层的同号轮不相等，界面必须写清是哪一层的第几轮。                                      |
| 时间片                                    | Phase                                  | 只出现在高级视图与“需等待 N 个时间片”这类句子里。                                         |
| 发射新代币                                | 发射（launch）                         | 不写“发币”。                                                                              |
| 首批代币接收地址                          | 分发者（distributor）                  | 不写“项目方”“官方”。它只决定拿到首批代币后怎么分。                                        |
| 铸造空投份额                              | Airdrop Claim（合约 `claim`）          | 页面标题、按钮与状态统一用此词；不写“领取空投”，不写“claim”。                             |
| 技术详情                                  | —                                      | 首页页脚默认折叠的技术信息区，收纳版本号与合约地址；是「高级视图」的一个具名实例。        |
| 高级视图                                  | —                                      | 放轮次序号、合约地址、原始 ID、区块浏览器链接；默认不展开。                               |

## 易混对（写文案前先分清）

| 一对                     | 区别                                                                                                                  |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| 激励 vs 奖励             | 激励是协议按规则准备的额度，可被预留、铸造、销毁；奖励暗示“已经发到手”。界面只用“激励”。                              |
| `Phase` vs 轮次          | 时间片是底层时间轴，无语义；轮次是业务组合出来的编号。二者不互为别名。                                                |
| 治理轮 vs 行动轮         | 治理层偏移为 0；行动层偏移不为 0，同号的治理轮与行动轮不是同一段时间。                                                |
| 链群 vs 代币社区         | 链群是社群协作单位（`groupId`）；代币社区是经济与治理边界（按社区隔离质押、激励、发射次数）。一个社区可以有多个链群。 |
| 成员 vs 控制者           | 成员是身份，控制者是当前能操作它的钱包；转移只换控制者。                                                              |
| 发射次数 vs 发射额度     | 次数是可消耗的整数资格；额度是还没凑满一次的进度。                                                                    |
| 质押融合 vs 发射次数融合 | 两个独立操作，不能合并成一个“合并”按钮。                                                                              |
| 销毁 vs 销毁活动         | 协议的“销毁”是取消预留、使其永不铸出；首页资格卡里的“销毁活动”指产生空投快照份额的那次销毁活动，两者不是同一个动作。 |
| `symbol()` vs `name()`   | 社区名只取 `symbol()`（短、用户认得，如 `TestLOVE20`）；`name()` 是 `<子币 symbol>@<父币 symbol>` 的复合技术标识（如 `TestLOVE20@TestWETH`），不是显示名。显示需求不应反向改合约命名。 |
| 「LOVE20协议」 vs 「LOVE20」 | 「LOVE20协议」是没有选中/未知社区时的协议回退标签，命名的是协议本身；「LOVE20」是 LOVE20 代币社区自己的 `symbol()`，是社区名。两者不互为别名。 |
